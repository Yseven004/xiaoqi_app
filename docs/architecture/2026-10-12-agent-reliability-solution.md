# Agent 通用提示词与调用链路修复方案

日期：2026-10-12，北京时间。状态：**调查和方案完成，尚未实施、部署或真机验收。**

## 先读这页（约 2 分钟）

**建议保留 Genkit，统一任务契约和执行状态，再替换提示词。** 当前故障已有线上证据，不能归结为“模型不够聪明”或“生图模型不支持复杂需求”。

| 已确认的根因 | 对用户的影响 | 通用修复 |
|---|---|---|
| 正则把“讲解……”及其主题删掉 | 有图片，但内容与需求无关 | 保留原始输入；通过结构化规划和媒体描述编译保留语义 |
| 点击动作被当成完整任务，空输入又被自动补句 | 没说画什么也付费生图 | 区分原始输入、入口元数据与展示文案；必要信息不足先追问 |
| 本地把“第一性原理”等词列入所谓版权黑名单 | 有效需求在调用供应商前就被拒绝 | 删除无依据的业务词黑名单；按真实供应商错误分类 |
| 调用之前就设置“已生成”，混合任务无强制阶段顺序 | 失败后无法纠正，先等图片后看解释 | 用持久化步骤状态代替布尔值；按交付物依赖执行 |
| 有文本或文件就标记整项完成 | 没交付图片也显示完成 | 完成判定逐项对照交付物与验收证据 |

本方案适用于知识问答、图像、视频、文档、代码和混合任务。案例中的人名、学科词和句式仅用于验收，**不进入生产代码的特判分支**。

## 1. 根因证据

### 1.1 第一性原理变成电解水：主题在服务器内被删掉

线上任务 `task-900ebef5e83d189439aa8d9d`：

| 项目 | 实际证据 |
|---|---|
| 本轮输入 | `给我用图片讲解一下马斯克的第一性原理` |
| 入口 | `action/create-image` |
| 09:08:32 日志 | `answer_before_image=false`，原文长度 18，视觉提示长度 3 |
| 最终任务 | `completed`，1 张 JPEG |
| 用户截图 | 返回“电解水实验”，不是所需主题 |

`agent_runtime.dart:448` 删除“讲解”到句末，再在 `:456` 删除“给我”。按当前源代码重建，视觉描述只剩 **“用图片”**，之后追加默认比例。该重建与线上记录的 3 字长度吻合；供应商请求正文没有单独留存，不能把重建冒充原始 HTTP 抓包。

图片偏题发生前，任务主题已丢失。不需要先假设模型版权限制、缓存串图或历史图片误用，便能解释这条链路缺陷。

### 1.2 牛顿第一定律变成阅读场景：同一个通用缺陷

线上任务 `task-a4eb12e890ace7ea8bcc9906`：

| 项目 | 实际证据 |
|---|---|
| 本轮输入 | `生成图片给我讲解一下牛顿的第一定律` |
| 09:25:35 日志 | `answer_before_image=false`，原文长度 17，视觉提示长度 6 |
| 按源码重建 | **“生成图片给我”**，主题和学科均消失 |
| 最终任务 | `completed`，1 张 JPEG；截图为窗边阅读场景 |

`agentImageRequestNeedsTextAnswer()` 同时要求命中“附加图片”类句式和另一组解释词，且后者缺少“讲解”。这类组合正则无法稳定表达“用户要求几个交付物、各自是什么”。不能靠继续增补同义词彻底解决。

### 1.3 视频的生图失败：是本地过滤，并非这次被供应商拒绝

线上任务 `task-91095563828ce75ee1b2394c`，09:09:32 开始：

1. 模型提出 `generate_image` 调用，已构造科技概念插画描述。
2. 本地 `agentImagePrompt()` 命中“第一性原理”过滤，09:09:40.743301 记录 `keyword_filtered`，返回 `ok:false`。该分支在 `images.generate()` 前返回。
3. 模型又尝试两次调整描述，均收到“本任务已经生成过图片”。原因是 `imageToolCalled=true` 在成功前就写入。
4. 任务仍保存为 `completed`，**artifacts=[]**。视频中的回答把本地拒绝描述成了“图像服务判定内容不适合生成”。

因此，这一次不能称为 Seedream 的版权拒绝。即使模型生成了合适的视觉描述，`agent_runtime.dart:1083` 仍会追加全部用户原文，继续触发本地过滤。

### 1.4 空输入自动生图：已找到真实空输入记录

任务 `task-03b5a1bf6d8364bd2f861605` 的会话快照记录：

```json
{
  "current_turn_text": "",
  "message_text": "我选择了“创建图像”，请结合当前对话继续。"
}
```

前端 `_emptyCapabilityIntent()` 为入口生成这句话；`_buildAiMessages()` 将其写入用户消息。后端 `currentTurnText.isNotEmpty ? currentTurnText : _latestUserText(...)` 又把明确的空字符串视为未提供字段，读取了合成文案。空输入保护因此失效。

该任务 09:35:45 的线上日志记录：被当作 21 字请求，提取出 20 字“视觉提示”，进入 `selected_action` 直接生图；最终状态 `completed`，产物数量为 1。这里不只是源码推测，空输入自动生图已有任务记录佐证。

这次有证据的是**合成文案替代原始输入**。旧报告所说“必然是读取上一轮历史”不够准确；当前函数取的是最新用户消息，可能恰好是前端合成的消息。

### 1.5 成功、质量、时序没有形成契约

| 位置 | 已存在的问题 |
|---|---|
| `agent_runtime.dart:690` | 选中创建图像就强制 `answerBeforeImage=false`，入口覆盖了用户交付要求 |
| `agent_runtime.dart:1382` | 提示“必须调用生图、也要回答”，但没有强制先完成文字阶段 |
| `agent_runtime.dart:1074` | 尝试调用与成功交付共用一个布尔值 |
| `image_service.dart:105` 起 | 检查返回项、下载与保存，未核验图像语义是否符合需求 |
| `api.dart:610` 起 | 非中断的正常返回直接标记完成，未核对必要交付物 |

`ImagePromptQualityChecker` 与 `ImageGenerationMonitor` 文件存在，但全仓检索未发现调用方。前者检查的是关键词与长度，不是图片内容；接上它也不能解决语义偏题，而且会进一步误拦正常请求。

## 2. 通用调用链路

```text
客户端原始输入 + 入口元数据 + 本轮附件 + 明确引用
                    ↓
TurnEnvelope 校验 / 身份与权限绑定 / 当前回合归属
                    ↓
结构化任务规划 TaskPlan（无副作用）
        ├─ 缺少必要信息 → awaiting_input → 用户补充 → 更新同一计划
        ├─ 能力不可用   → 如实说明 / 保留可完成部分
        └─ 计划有效     → 持久化交付物和步骤依赖
                              ↓
                    确定性的步骤执行器
        ┌─────────────────────┴──────────────────────┐
        │ 文字 / 检索 / 计算 / 文件步骤                │
        │ 按真实依赖执行、流式回传、逐步持久化          │
        └─────────────────────┬──────────────────────┘
                              ↓
              媒体 Brief → 供应商适配 → 调用与存储
                              ↓
                  技术检查 + 任务语义检查
                              ↓
              逐项汇总：完成 / 部分完成 / 失败 / 未知
```

### 2.1 文字优先是交付顺序，必须由执行器保证

| 请求类型 | 建议行为 |
|---|---|
| 普通知识问答 | 直接流式回答，默认不生成媒体 |
| “讲解主题，附一张图” | 完整文字解释先流出并保存，再开始配图，最后追加图片 |
| “用一张图讲解主题” | 先内部整理知识与构图，再生图；不强塞长篇文字，除非用户要求 |
| “只给我图片” | 输出图片，不额外生成长解释 |
| 图像/视频分析、必须先计算才能回答 | 先完成必要分析或计算，再给真实答案，不能为“文字优先”编造结论 |

纯入口无任务时只追问：“你想生成什么内容的图片？”不要求用户先掌握专业提示词。缺少主题要问；没写光照、镜头、配色通常可以使用合理默认值。

只选入口时不主动复用历史主题；“把上面那段做成图”等明确引用可以解析历史，并绑定具体消息 ID。附件有明确意图时可以使用；仅有附件但不知道要做什么时追问。

### 2.2 固定的是边界，灵活的是任务内容

| 模型负责 | 程序负责 |
|---|---|
| 识别目标、解释上下文引用 | 区分字段缺失与明确空值，校验当前回合归属 |
| 提出交付物和依赖关系 | 校验 DAG 无环、工具存在、权限合法、额度与超时 |
| 编写答案和媒体 Brief | 强制阶段顺序、绑定输入版本、持久化输出 |
| 建议可纠正的描述调整 | 决定是否可重试、是否可能重复扣费 |
| 对实际产物作语义评估 | 按交付物记录判定最终状态，不接受模型自称完成 |

普通问答无需每次额外调用一个规划模型。可以在原有首轮里输出经 schema 校验的交付计划；复杂混合任务再启用显式多阶段流程。若计划损坏或引用不明，不降级成“拿原文直接调用付费工具”。

## 3. 状态、重试与恢复

### 3.1 分开记录任务与步骤

任务状态建议：`awaiting_input / running / completed / partially_completed / failed / cancelled`。步骤状态建议：`pending / running / succeeded / failed / unknown / cancelled / blocked`。

`blocked` 表示依赖或配置阻塞；`unknown` 表示供应商可能已受理但本地未取得结果。工具不可用不能伪装成等待用户描述。

`completed` 必须满足：所有用户要求的交付物都已存储、可读取，并达到声明的验收标准。文字成功而配图失败，状态为 `partially_completed`，明确显示缺少图片，允许只重试配图。图像接口返回成功与主题符合需求是两种证据。

“顺便配图”也仍是用户要求的交付物：它失败不应删除已完成文字，但也不能把整个任务称为完成。

### 3.2 重试按错误类别决定

| 错误 | 处理 |
|---|---|
| 缺少输入、规划或工具参数错误，且尚未发起外部调用 | 追问或最多一次无副作用的参数修正，不占用“生图成功”状态 |
| 供应商明确拒绝、鉴权失败、模型不可用 | 按真实错误码结束该步骤；不自动绕过审核，不原样循环重试 |
| 429 或供应商明确说明可安全重试的临时故障 | 依供应商语义、Retry-After、幂等支持与预算有限重试 |
| 超时、连接中断或 5xx，受理结果不确定 | 标记 `unknown`；优先按供应商任务 ID 查询，不盲目重新付费生成 |
| 图片已生成但下载/入库失败 | 重试下载/保存；复用已有产物地址，不能重跑生图 |

5xx 不天然等于“没有执行”。当前 `ImageService` 不重试不确定超时的方向是正确的，应保留。

幂等键由服务端建立，至少绑定 tenant、task、step、输入版本、尝试编号；一次逻辑请求的重复投递复用原结果。用户明确要求重新生成时创建新尝试编号。使用数据库唯一约束、CAS 或事务领取步骤，不能仅靠进程内布尔值。

若供应商没有幂等键或可查询任务 ID，本地系统无法保证外部“恰好执行一次”：未知结果必须显式保留，由用户选择是否承担重新生成的可能费用。

### 3.3 取消、断线与服务重启

客户端断线不等于用户取消。持久化已流出的文字和步骤进度；重连通过任务 ID、最后事件序号恢复。取消时立即阻止尚未开始的后续步骤；正在执行的调用若支持取消则取消，不支持时记录晚到结果，不宣称供应商已停止或不会计费。

持久化任务/步骤账本，利用现有 SQLite 存储；为重启后仍处于运行中的步骤设置租约和恢复检查。首版无需引入 Redis、另一套 Agent 框架或多个独立规划 Agent。

恢复历史任务时缺失新字段应视为 legacy/unknown，不把未知历史状态写成成功；租户隔离、快照分支、附件归属和数据兼容必须保持。

## 4. 通用提示词体系

模板正文见配套文件，分成五个可独立版本化的模块：

| 模块 | 输入 | 输出 |
|---|---|---|
| 任务规划 | 原始输入、附件、显式引用、能力目录 | `TaskPlan` / 最小必要追问 |
| 文字交付 | 已校验的文字交付物、资料和事实依据 | 可流式展示的正文 |
| 媒体 Brief 编译 | 指定交付物、主题、已确认内容、真实模型能力 | `MediaBrief`，保持主题和必要事实 |
| 产物验证 | 用户要求、Brief、实际文件或帧/音轨 | `pass / fail / uncertain` 与证据 |
| 结果汇总 | 持久化步骤结果、产物与错误 | 如实交付已有内容、说明未完成项 |

公共约束通过共享片段复用。使用 `.prompt` 与命名 schema 管理；代码中的超长系统字符串不再承担工作流。每次任务固定 `prompt_version / schema_version / policy_version / model_config_version`，便于复盘和回滚。

供应商差异保留在适配器：真实模型 ID、尺寸、数量、参考图、时长、异步查询、审核错误、超时与配额。能力目录应由服务端配置并经实际验证，不从关键词或模型自述推断。

对知识图片，Brief 必须带“要表达的命题、关系、必要标签、不得误导的事实”。删除人名或概念词不是通用优化方法。需要大量精确文字/公式时，根据能力选择受控排版或征询替代交付形式，不能偷偷把知识图改成氛围插画。

视频复用同一交付物/状态契约，增加镜头、时长、旁白、音画一致性及供应商任务轮询。**当前调查没有证明项目已有可用视频供应商；本方案不把视频支持称为已实现。**

## 5. 验收标准

### 5.1 输入、语义与交付

| 类别 | 必须满足的断言 |
|---|---|
| 所有入口的空输入、空白、仅标签 | 无付费工具调用，出现功能相关追问；当前空值不被历史/合成文案覆盖 |
| 图像概念讲解、任意学科、人名、同义句、语序变化 | 原始主题、核心命题和交付物保留；不依赖特定关键词 |
| 文字+图片/视频/文档 | 文字先持久化并展示，再执行没有前置分析依赖的附加交付步骤 |
| 仅图片、仅文字、禁止配图、明确复用上文 | 尊重输出范围；引用必须绑定正确版本，不能串用旧主题 |
| 技术成功但主题错误、数量不符、公式错误 | 不标记整体完成；保留验证证据和可执行的下一步 |

### 5.2 稳定性与真实性

| 类别 | 必须满足的断言 |
|---|---|
| 本地拒绝/供应商拒绝 | 错误来源准确；本地拒绝不得包装为供应商审核失败 |
| 超时、429、下载失败、未知结果 | 遵循各自恢复策略；不能重复生图扣费 |
| 重复点击、重复消息、进程重启、断线重连 | 同一逻辑步骤不会因重复投递重新执行，已完成内容可恢复 |
| 取消、局部失败、能力未配置 | 停止后续步骤；展示真实局部状态；不永久锁住输入或用页面转圈过渡 |
| 租户、历史数据、提示注入、预算 | 任务/产物权限不越界；外部内容不能修改工具权限或预算 |

测试集应由输入类型 × 交付组合 × 故障类型构成；加入未出现在模板中的主题和改写作为留出集。当前案例只是其中三个样本。先用 fake provider 验证确定性状态机，再用真实模型小样本验收语义和供应商限制。

语义检查可以使用具备视觉能力的模型，但它也会判断错；输出 `uncertain`，不能让生成模型仅凭自己的文本声称图片正确。对严格事实图采用核对表、文字识别/结构检查和实际图像评估。质量失败是否允许再次付费生成，应受明确预算约束。

## 6. 实施顺序与上线边界

| 顺序 | 工作包 | 完成标志 |
|---|---|---|
| 1 | 确认交互规格：追问、文字先行、局部完成、重试、取消 | 使用 Product Design 对照现有界面确定状态；用户确认范围 |
| 2 | 输入契约、公共规划模板、schema、语义保留 | 空输入/引用/交付组合矩阵通过，移除破坏性正则及无依据黑名单 |
| 3 | 分阶段执行、步骤账本、错误分类、产物验证 | 幂等/取消/恢复/局部失败通过；模板与适配器版本固定 |
| 4 | 端到端与目标设备验收、小流量发布 | 真实模型产物相关，事件顺序和 UI 状态正确，既有数据兼容 |
| 5 | 阿里云备份、发布、健康与数据核对、回滚演练 | 记录部署版本、镜像、数据核对结果；失败恢复原发布 |

改动主要落点：`home_page.dart` 的原始输入和事件呈现、`agent_runtime.dart` 的规划及步骤编排、`image_service.dart` 的适配和结果分类、`api.dart` 的任务状态、`store.dart` 的步骤账本。公共模板建议放入服务端 `prompts/`，本次只提供设计稿，不写入运行中的提示词目录。

预计完整实施需 **3–5 个工作日**，假设现有供应商账号可用且首版只接现有能力；新增视频供应商另估。该估算不是已完成承诺。首版明确后置：多 Agent 团队、框架迁移、Redis、新视频服务、新设计风格。
