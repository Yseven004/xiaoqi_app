# 单次联网执行授权（API 24）

状态：代码与本地回归完成，待对应提交 CI、发布及客户端验收。完整权限修复目标仍按 P01–P14 台账执行。

## 范围与现有交互

沿用已确认的搜索开关、联网确认卡片、允许/保持断网按钮及任务事件。普通离线工作区执行不增加确认。未知效果的联网代码、Shell 和已安装脚本使用同一授权判断，不再因搜索开启自动取得外部操作权限，也不因借用技能临时联网绕过确认。可信搜索/读取工具的规则保持独立；不根据模型自称只读或远端注解授予权限。

确认卡片复用现有 MCP 参数展示：显示用途、精确域名、代码或技能脚本参数及文件名称；长内容可滚动，不截断实际待确认代码。不展示工作区路径、内部指纹、平台凭据或内部执行标识。没有新增页面、按钮、视觉资产或路由加载动画。

## 服务端绑定

`NetworkCallAuthorization` 将批准绑定当前任务范围、实际工具入口、完整参数、实际输入/产物字节指纹、技能版本/组件与不可变制品、精确域名、联网模式及当前 release/API contract。运行前复查取消、范围、模式、技能状态、授权及文件绑定。改变代码、参数、文件、版本或任务范围不能沿用旧批准。

所有这类执行默认效果为 unknown，不能由模型参数覆盖可信效果。保持断网会阻止当前任务范围内代码/脚本换入口重复申请，离线处理仍可继续；用户更新任务后重新判断。MCP 拒绝保留原有按工具与动作的授权语义，不由本次代码联网拒绝改写。

批准不写入 `authorized_network_domains`。同一已批准且成功的调用复用其结果，不再启动桥接或重复扣执行预算。代码预算由执行服务累计，动作记录标明由代码预算承担，避免重复计数。确定尚未提交的失败可以保留原批准后重试；已提交但结果未知的动作不自动重放。恢复后的已知执行结果与外层动作记录关联仍属于 P13 后续工作，不能据此称全部恢复问题完成。

## 流式 Agent

服务端工具返回既有 `network_permission` interrupt，新增并校验 `approval_hash`，同时附带用途、域名、可见 `details`。客户端批准与拒绝均用原工具请求的 `restart`，回传 `approved`、`domains` 和 `approval_hash`；拒绝不再通过 `respond` 跳过服务端记录。参数更改必须重新确认。

Genkit 1.0 的 `ToolRequestPart.restart` 和恢复检查以本地锁定 SDK 源码及人机确认参考核对；SDK 本身也拒绝篡改 restart 中原始工具输入。服务端绑定仍独立检查，不能仅依赖客户端历史。

## 轮询任务接口

`POST /v1/agent/tasks/<task>/authorize-network` 必须发送：

```json
{"domains":["example.com"],"approval_hash":"本次事件返回的64位十六进制标识"}
```

只允许当前 awaiting_network_permission 的精确动作和完整域名集合。缺少/无效标识返回 400；动作或状态已变、已拒绝返回 409；任务确认数量超限返回 429。成功仍返回 queued。旧格式不保留兼容，两端共享 contract 24；不匹配时沿用现有版本提示并停止正常 API 流程。

旧轮询入口保存本任务原始 SDK 消息与工具请求，恢复该请求后继续，避免重新生成另一段代码。快照最多 8 MiB，存于当前账号/任务专用对象命名空间，任务文档保存指针和规范化请求摘要；不作为用户产物导出。其他账号、任务、更改后的请求或不匹配的服务版本不能借用。完成后不再自动重启该快照；保留最后检查点为任务数据，替换时删除前一检查点，沿用任务数据保留/清理策略。

轮询界面的拒绝仍使用既有取消任务行为。非联网的其他工具 interrupt 不得被旧入口当成完成；旧轮询入口对 MCP 等确认的完整恢复仍列入 P01/P13 待办，未以失败提示代替闭环修复。
