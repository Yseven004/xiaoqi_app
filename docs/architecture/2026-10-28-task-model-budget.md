# Task-wide model request accounting

The existing `maxTurns=64` belongs to an individual Genkit generation. Resuming an interrupt, steering a task, intent classification, attachment notes, format repair and final-answer generation could therefore consume additional requests without a task-wide record.

The per-generation 64-step limit stays in place. `ExecutionLimits.modelRequests` adds a server-owned default of 128 provider POST attempts per task, independent of the model's delivery plan. A task-scoped HTTP client is injected into all eight existing OpenAI/DeepSeek plugin construction paths. Its asynchronous task context covers intent routing, optional connector selection, attachment/vision work, preparation, repair and final answer. The client is owned and closed by the runtime; the SDK already supports a caller-owned HTTP client. No dependency is added and tool authorization is unchanged.

Before each SDK provider POST, SQLite compare-and-swap reserves one `model_request_runs` attempt under the authenticated tenant/task key. Failure still consumes that attempt. New runtime/client instances and changed user scopes retain the count; another task has its own budget. Metadata GETs do not consume model attempts. Missing/stopped/cancelled tasks cannot submit a provider POST. Cancellation is checked before reservation. Counter corruption or revision failure does not become an unmetered request. A recorded reservation refusal is rethrown by the owning runtime even if an SDK/intent fallback catches it, preventing a false successful completion. Retrieved files and results are not removed when the budget is exhausted.

The real API already ensures the task record before invoking the runtime. The attachment-only test fixture previously bypassed that setup; it now supplies the same precondition. Production does not create a second task or change task lifecycle as a workaround.

This is request accounting, not provider billing: it does not infer tokens, money, or packet-level retries below the HTTP client. Existing tasks with no counter begin metering at their first request after rollout; prior unrecorded usage cannot be reconstructed and is not claimed as measured. Provider calls outside the agent-task runtime and image-generation accounting remain separate. P12 resource/cost verification is not closed by this change.

Reference: [genkit_openai 1.0.0](https://pub.dev/packages/genkit_openai/versions/1.0.0), maintained by [genkit-ai/genkit-dart](https://github.com/genkit-ai/genkit-dart), checked 2026-10-28. The installed 1.0.0 source exposes `httpClient` for both OpenAI and DeepSeek and skips closing caller-owned clients. Its package declares Apache-2.0. This implementation uses that public injection point; no upstream implementation is copied or modified.

Tests cover failed attempts, durable counts across service/store reconstruction and steering, cancellation, tenant/task ownership, metadata reads, context lifetime and swallowed refusal. The actual Genkit runtime fixtures now compare the persisted count against every provider request received, including intent, repair and resume, across all existing capability/MCP scenarios. Complete checks and deployment are recorded separately when terminal. The public API contract remains 24; rollback restores the earlier server image while preserving the added counter field and existing task data.

Final local checks: analyzer reports no issues and complete Dart regression passes 291 tests. The first integration run exposed three attachment fixtures without the real API task initialization; after correcting that fixture precondition, the complete suite passed with all provider-count comparisons active. The assertions were retained. No paid model or image requests were made by these tests. CI and production success are not inferred from local checks.
