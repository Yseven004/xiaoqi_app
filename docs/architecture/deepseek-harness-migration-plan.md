# 小七 Agent 运行时迁移方案

日期：2026-10-04  
状态：API 与 Harness Worker 已部署；杭州 `personal` 白名单已启用；DeepSeek→Harness→MCP→E2B→OSS Python→CSV smoke 通过，完整迁移验收继续进行。2026-10-05 增加的个人邮箱登录代码已完成本地检查，尚未部署到 API 函数。  
推荐方向：直接复用 DeepSeek Harness 官方运行时，通过插件接入小七能力，逐步替换自研 Agent 循环。

## 1. 本次要解决什么

小七需要让用户从应用内发起任务，由 Agent 实际调用工具，并拿到可用结果。当前运行时同时维护模型请求、工具调度、任务状态、会话历史和产物处理，持续增加维护成本。

本次目标是减少自研通用运行时，同时保持小七已有业务能力和可验证的任务结果。框架正常结束不等于业务成功；用户要求生成的文件必须真实存在并可通过授权接口下载。

已确认方向：用户希望复用 DeepSeek Harness，避免重复建设通用 Agent 架构，并已要求下载源码分析及编写本方案。

以下产品范围已由用户确认：

| 项目 | 首版建议 |
| --- | --- |
| 目标用户 | 唯一获准的个人账号；服务端按邮箱白名单授权 |
| 触发场景 | 登录后从现有首页发起任务，不要求先保存技能 |
| 核心操作 | 邮箱验证码登录、提交任务、查看执行反馈、取消、恢复、取回结果、失败后重新发起 |
| 成功标准 | 首页统一进入 Agent 任务接口；真实工具执行可追溯，CSV 内容正确且可下载，失败和取消不误报成功 |
| 用户体验 | 沿用现有首页、聊天记录、附件准备和授权逻辑；仅新增独立登录页，首页布局不改 |

## 2. 首版范围与后置项

完整迁移范围为现有任务闭环和所有既有工具：`read_task_material`、`read_skill_resource`、`draft_workspace`、`execute_python`，同时保留联网授权与恢复、会话历史、任务取消、产物保存、用户隔离和旧任务兼容。Python→CSV 是第一条可验收链路，不是最终范围。新开发的独立产品能力不在本次迁移范围。

本次不重做 Flutter 产品、不迁移书籍和笔记数据、不引入 Supabase/Firebase 等新身份服务、不开发一个同时兼容多套框架的通用平台。个人邮箱自动授权属于本次范围；新安装和本地无会话设备不再要求配对码。

## 3. 先冻结用户闭环

| 场景 | 建议行为与验收要求 |
| --- | --- |
| 入口与提交 | 沿用现有入口；缺少输入时给出明确提示；重复点击不能重复创建同一任务 |
| 排队与运行 | 展示可理解的任务状态；工具执行信息必须来自真实事件，不能依据模型口述 |
| 完成与下载 | 验证文件内容、存储提交和授权下载后才显示业务成功 |
| 失败 | 区分模型调用失败、工具失败、文件交付失败；允许用户重新发起，保留错误记录 |
| 取消 | 用户发起取消后先显示正在取消；实际停止并完成清理后才进入已取消 |
| 超时 | 终止运行时活动及沙箱工作，记录明确原因，不能无限等待 |
| 退出与恢复 | 离开页面不自动取消；再次进入从服务端读取任务状态。此交互建议需用户确认 |
| 应用断网 | 重连后查询同一任务，不能自动重复执行；下载失败可重试下载 |
| 服务中断 | 重启后能说明任务最终状态；未知外部执行结果不得自动重试有副作用的工具 |
| 权限与空状态 | 无权限不能读取其他用户任务或文件；尚无结果时显示静态占位 |

页面进入和路由切换禁止转圈加载。任务按钮内的小圈反馈可按现有规范保留。状态不能只靠颜色表达，错误文本和取消按钮须具备清楚的可访问标签。

首页沿用现有页面和状态语义，不改现有布局；新增独立登录页，流程为邮箱、获取验证码、输入验证码、登录。登录后尝试同步技能和草稿；同步失败保留本地内容且不阻止 Agent 任务。已有有效邮箱会话可离线查看本地内容，云端功能等网络恢复。

## 5. 推荐接入结构

```text
Flutter 现有任务页面
        ↓
小七 capability API：身份、权限、任务与文件下载接口
        ↓
小七 worker：任务归属、运行时调用、状态和产物交付
        ↓ 官方 ACP Python SDK / Harness ACP profile
DeepSeek Harness：模型调用、Agent 循环、工具调度、会话事件
        ↓ 本机 Streamable HTTP MCP
现有 Python 沙箱 → 产物校验 → OSS / OTS → 授权下载
```

保留现有 Python API 和 worker 外壳，通过官方 ACP Python SDK 驱动 DeepSeek Harness。普通 Python SDK 缺少跨进程会话恢复及单会话取消；实测 Harness ACP profile 提供这两项能力，因此接入方案改为 ACP。小栖工具以本机 Streamable HTTP MCP 提供，绑定 `127.0.0.1`，不对公网开放。FC 上的进程、运行时包和目录支持仍需验证。

首轮优先评估每个运行中任务独立运行时进程及独立工作目录，降低不同任务取消和状态互相影响的风险。进程启动成本、并发容量及会话复用方式由验证结果决定，暂不建设共享进程池。不能把独立目录当作完整安全隔离。

选用官方 SDK profile 后显式限制可用工具，只暴露首版需要的能力。官方默认工具清单不自动成为小七的权限清单。优先采用小七外部插件及配置扩展，避免 fork 核心循环。

## 6. 职责与接口边界

| 层 | 迁移后负责什么 |
| --- | --- |
| Harness | 模型请求、循环、工具注册与调用、会话事件；通过官方扩展点接入策略 |
| 小七 API | 登录和任务鉴权、幂等任务创建、权限范围、状态查询、文件下载 |
| 小七 worker | 任务领取和租约、运行时生命周期、事件映射、超时与取消协调、产物验收 |
| 小七 Python 工具 | 调用已有沙箱、执行限定任务、返回结构化执行结果和产物引用 |
| 存储 | 小七业务状态和文件继续使用现有存储；Harness 会话存储单独验证持久化与恢复方式 |

现有 worker 中模型请求和循环是主要替换对象。`_persist_artifacts`、任务归属校验、文件下载鉴权等业务逻辑须逐项保留或迁接，不能整体删除 worker。

插件调用已有 Python 能力的具体通信方式，在验证官方扩展机制后确定。优先复用受控内部能力接口；如需新增内部工具入口，必须绑定服务端确定的用户、任务和执行轮次，避免模型提供的 tenant 或 task_id 直接成为授权依据。不要新增第二套 Agent 调度服务。

## 7. 状态、数据与恢复

对外继续沿用现有 API 的兼容表示。下列是语义要求，不是直接新增数据库枚举：待执行、运行中、取消中、成功、失败、已取消；超时作为终止原因保留。

- Harness `completed` 只表示运行时结束，业务成功还要求 Python 工具成功、预期产物通过校验、文件持久化完成。
- 工具调用开始、工具结果与产物就绪分别记录；事件应带任务与执行轮次标识，并能够去重。
- 取消和成功提交竞争时，通过现有存储支持的原子条件更新裁决；终止后的晚到事件不能覆盖最终状态或再次提交文件。
- 对外幂等键沿用已有规则；运行时重连、客户端重试和 worker 重启均不能重复触发一次未知结果的工具操作。
- Harness 会话标识与业务 task_id 保持映射，避免混用用户身份和会话身份。

拟新增最少元数据：运行时类型、固定运行时版本、Harness 会话标识、执行轮次、必要的事件定位信息。最终字段需与现有 schema 核对后确定；采用增量兼容，不回写或批量转换历史任务。

历史任务及文件仍按旧方式读取。首版优先从新任务验证新运行时；历史会话续接是否需要迁移，作为待确认范围，不默认直接导入旧消息历史。

离线时只保留现有客户端行为；本次不新增离线 Agent 执行或缓存体系。

## 8. 取消、超时与部署难点

ACP 客户端暴露单会话 `cancel`，Harness ACP profile 同时声明 `session.resume`。Windows 本机模拟验证已通过服务重启后恢复同一会话及工具上下文；单会话取消调用和外部沙箱停止仍需端到端实测。运行中的任务须先复用小栖取消标记，再取消 Harness 请求并停止对应 E2B 沙箱，最后确认清理结果。

分别设置启动、任务和工具执行的有限超时；具体值经现有配置和真实运行测量确定。达到期限后必须释放资源并写入终止原因。官方 SDK 普通任务默认可能无界等待，不能直接沿用默认值上线。

现有 FC 无法满足运行时要求时，先报告验证证据和成本，再决定是否使用同云环境的容器部署；不静默更换基础设施或降低取消、隔离与持久化标准。

## 9. 权限与可观测性

沿用服务端用户鉴权、内部 worker 鉴权和产物下载鉴权。凭证只来自受控服务端配置，不进入模型上下文、插件源码、报告或普通事件日志。插件及模型可调用的工具使用显式允许清单，未授权能力默认不可用。

每次执行记录 task_id、attempt、运行时版本、工具调用标识、状态变化及耗时；用户内容和工具输出按现有隐私规则处理，日志避免记录密钥及完整敏感材料。

灰度至少观察：成功率、错误分类、首次响应与完整任务耗时、取消耗时、重复调用、孤立沙箱、文件交付失败。与相同模型、输入和沙箱条件下的旧路径比较；具体性能容忍阈值在基线测量后记录并冻结，未冻结前不宣称性能验收通过。

## 11. 发布与回退

使用任务创建时确定的运行时路由标记，指定测试用户进入新路径。运行中的任务固定使用创建时的路径，不因开关变化被另一套运行时接管。

出现隔离问题、取消失效、重复执行、虚假成功或明显交付失败时停止扩大灰度。回退开关只将后续新任务送回旧路径；在途任务按所属运行时完成或显式取消，不双跑、不自动重放。

保留旧路径的代码、配置和依赖直至新路径验收稳定。新会话数据独立保留，不能假设旧运行时可读取；使用兼容的增量业务元数据，避免回退依赖破坏性数据库回滚。
