# Link recovered code results to their authorized operation

Runner execution recovery already preserved an execution ID, result and files. Its outer authorized-code operation could still remain unknown, however, and the request-wide unknown-network flag could block unrelated progress even after the result was known.

The network grant now exposes the same server-derived operation identity used by `ToolExecution`. Generated code and installed-script calls pass it to the executor. Immediately before submission, one task-document update validates the running external/code-budget parent and current user scope, binds its random execution ID, and records the parent's arguments hash with the child. An unrelated or changed scope cannot submit code. Offline calls retain their existing path.

After the original runner result and files are persisted, the executor reconciles only the matching parent ID, child execution ID and arguments hash. Successful results become cached success; known failures become cached failures rather than permission to retry. The same text formatter and saved original artifact names serve both normal and recovered results. A late transport failure cannot downgrade this confirmed parent result. No script, tool or HTTP mutation is repeated to obtain a result.

If the original caller is still waiting, it receives the confirmed result instead of a late transport error. This return path rechecks the captured task scope; confirmation never revives a cancelled or superseded operation. Known failure remains a failure, with the original output available and no script replay.

Unknown-network scopes retain a set of associated operation IDs. Reconciliation removes only the confirmed member; other pending operations and older unlinked uncertainty remain. Failure callbacks address the captured original user scope, so late failures cannot mark a newer user instruction as uncertain. Existing exact approvals, denials, scope checks, code budgets and file-ownership boundaries still apply.

Tests use the native worker bridge to lose the original result stream, close/reopen the task store, retrieve the same execution result and recover its original bytes. They cover success, known failure, preserved legacy uncertainty, zero replay, no additional code budget and original output filenames. Separate tests cover late failure after confirmation, multiple unknown identities, old/new user scopes and rejection of an unrelated parent before runner submission. Full regression and rollout are recorded separately when terminal.

This does not invent associations for old unlinked executions. It does not make changed code, credentials, files or task scopes share an approval.
