# 小七生图失败：服务器调查与解决方案

调查日期：2026-10-09（北京时间）。范围：现有客户端代码、目标 ECS 正在运行的配置、两张截图对应任务、插件安装源码、真实沙箱行为、模型服务只读鉴权。没有修改线上配置、部署新版本或调用收费生图接口。

## 结论

**主要问题在后端能力装配，不是客户端重新编译能解决的问题。另有一个确定的工具说明错误，导致替代脚本也失败。**

| 用户怀疑项 | 调查结果 | 应对 |
|---|---|---|
| ACP / Adapter 连接或编译 | ACP 能正常完成会话和 MCP 工具调用；插件也已发布到 ACP 配置。但 `dsh-image-gen 0.8.6` 强制依赖 `webServer`，该 ACP 配置没有提供它，插件无法在这一依赖条件下激活 | 修复插件的无 Web 运行兼容性；不能把包已安装、配置可编译当成工具可用 |
| API Key 无法识别 | `ARK_API_KEY` 已保存在 DSH 凭据的 `refs` 中，非空；任务启动代码会复制该凭据文件。用服务器保存的 Key 请求模型列表返回 HTTP 200，包含配置的模型 | 保留现有凭据机制，不把 Key 写进提示词、客户端或技能脚本；真实生图权限、余额和响应仍须另验 |
| 提示词错误 | 原生插件缺依赖不是提示词能修的；但小七的技能执行工具说明确实写错输出路径 | 修正工具契约，已保存的错误技能也需要修正 |
| 沙箱未安装或完全不可写 | 沙箱可以运行；真实实验中相对路径 `output/audit.txt` 写入并回收成功 | 保持隔离，不开放根文件系统；使用沙箱真正的输出目录 |
| 为什么不能重试 | 后端硬编码每个任务执行技能脚本最多一次，开始执行前就扣除次数，失败也占用 | 当前新任务可获得新配额；若改重试策略，需要限制次数并避免重复收费操作 |

**优先修原生 DSH 插件通路。不要继续让模型另造一个公共生图服务脚本来替代已经配置好的 Seedream。**

## 1. 第一张截图：插件安装了，但生图工具没有正常进入会话

定位到原任务 `task-6c015b4c2cbf166edad87433`，创建时间为北京时间 21:20:43，服务端保存的回复与截图一致。记录的工具调用是 `draft_workspace`，没有 `generate_image` 调用；没有证据显示此次请求到达生图 API。

服务器实际状态：

- DSH 运行时：`0.2.0-rc.2`；生图插件：`dsh-image-gen 0.8.6`。
- 原任务锁定配置：`cfg-20261009094659-4c49c1b6`，修订号 7。
- Web 和该 ACP 配置的 bundles 都包含 `dsh-image-gen`，排除“只安装 Web、没发布到 ACP”的猜测。
- 两端生图配置都是 `provider: seedream`，接口 `https://ark.cn-beijing.volces.com/api/v3`，模型 `doubao-seedream-5-0-flash-260915`。
- 服务器已安装插件的 `lib/index.js:28273` 声明必需依赖 `tools`、`attachments`、`credentials`、`webServer`；`apply` 中注册 Web 路由，`generate_image` 的注册在约 28517 行。实际 ACP 合成配置具有前三项服务对应组件，但没有提供 `webServer` 的组件。

用生产配置的临时副本执行 `dsh --profile xiaoqi-acp --dump-config` 返回 0，但只证明配置能合成，不能证明插件依赖已满足。这个检查遗漏正是当前发布验证的不足。现场同时出现 `ui-settings-general not found` 警告，说明 Web 配置直接转 ACP 还有 Web 设置项残留；不能仅凭这个警告断言它是主因。

证据边界：尚未在修复后的插件上做真实激活/生图对照；上述根因来自已安装代码的必需依赖、实际合成配置缺少对应服务，以及失败任务记录相互印证，而非模型自述。

### 密钥已核实，不需要盲目更换

文件：`/opt/xiaoqi-dsh/web-home/.credentials.yaml`。该文件的 `refs` 使用行内 YAML，`ARK_API_KEY` 是其中非空字符串。调查最初只按行识别字段漏掉了它，后来已用 YAML 解析器纠正。三个容器没有同名环境变量不是故障，因为插件调用的是 DSH `credentials.resolve`，并不只读环境变量。

小七 `harness_worker.py:390` 的 `_copy_dsh_credentials` 从上述位置复制到每次任务的 DSH_HOME；在约 709 行启动流程中调用。运行环境白名单不传入 `ARK_API_KEY`，但通过凭据文件解析不受这个限制。

服务器只读请求 `GET /api/v3/models`：HTTP 200、135 个模型、包含当前配置的模型。**这证明此 Key 对模型列表接口有效、网络可达；不等于已验证生图额度、模型调用授权或成功产图。** 全程未回显 Key。

## 2. 第二张截图：后端告诉模型一个不存在的输出位置

任务 `task-48f76ac4702e7f8bf6a04517` 的事件确认：

1. 第一次 `execute_skill_script` 返回 `Read-only file system: '/workspace'`。
2. 第二次返回“本次任务的技能脚本执行次数已用完”。

错误契约在本地和已部署代码中一致：`xiaoqi_harness/capabilities/harness_mcp_server.py:262` 告诉模型“交付文件写到 `/workspace/output`”。

实际实现 `skill_script_sandbox.py:334` 创建 `/tmp/xiaoqi-skill-随机值/`，其下有 `skill/`、`materials/`、`output/`、`home/`、`tmp/`；约 287 行将工作目录切换到这一任务目录。文件收集器仅回收其中的 `output/`。没有把它映射为 `/workspace`。

在目标服务器用现有沙箱执行两个无网络、无业务数据的最小诊断：

| 写入位置 | 退出码 | 实际结果 |
|---|---:|---|
| `/workspace/output/audit.txt` | 1 | 复现 `EROFS: '/workspace'`，无产物 |
| `output/audit.txt` | 0 | 回收 `audit.txt`，2 字节，内容 `ok` |

因此，不应该按截图里的建议任意回退到系统临时目录或当前目录：这些位置即使能写，也不一定进入产物收集器。应直接使用正确的 `output/`。

次数限制位于 `worker.py:630–636`：检查 `skill_script_runs >= 1`，执行前增加计数。这个报错是预设策略，不是沙箱坏了。再次写同一个错误的绝对目录也不会修复第一次错误。

另一个边界：技能沙箱有意不提供服务器密钥。客户端后来生成的脚本调用的是 Pollinations，和现有 Seedream 插件、ARK Key 是两套通路。即使路径修好，这个替代脚本的外部接口是否仍可免密钥使用也未验证，不能声称它随后必然出图。

## 3. 具体实施方案

### A. 首选：修复现有生图插件的 ACP 兼容性

以当前 `dsh-image-gen 0.8.6` 建立固定版本的兼容补丁，保持现有生成、凭据解析和附件输出逻辑，避免另造生图 API 系统。

1. 将 `webServer` 从整个插件的必需依赖移出。`tools`、`attachments`、`credentials` 仍是必需项。
2. 将 Web 专用逻辑放入 `ctx.inject(['webServer'], ...)` 的生命周期作用域，使用回调提供的 context 注册和释放路由。包括订阅路由及 `apply` 内的 10 个路由，当前构建产物共 12 处 `ctx.webServer.register`；不能只删依赖声明，否则会在访问空服务时出错。
3. `generate_image`、`generate_images`、`edit_image` 等核心工具注册保持在无 Web 也能执行的路径。画布/订阅功能按真实依赖单独启用，不向 ACP 暴露无法完成的 Web 交互。
4. 锁定补丁包的版本或 commit，通过现有发布机制生成新的不可变 ACP 配置；不要直接修改服务器共享 `node_modules`，否则下次安装或配置发布会覆盖修复。
5. 发布验证从 `--dump-config` 升级为“实际启动 + 检查核心工具已注册 + 凭据解析状态”。检查输出只包含存在性和错误类别，不能输出密钥。

不推荐为了让插件启动而把完整 Web 应用装进每次 ACP 任务：它会引入 HTTP 监听、端口冲突和额外生命周期问题。若选择补齐官方 Web 服务的兼容方案，必须先验证只监听回环地址、动态端口、鉴权、并发任务隔离和退出释放；当前调查没有验证这条替代方案。

### B. 同时修复小七技能输出契约

最小完整改动范围：

- `harness_mcp_server.py:262`：工具说明改成“当前工作目录为任务工作区；交付文件写入相对路径 `output/`；仅该目录文件会回传；一次执行限制仍然适用”。
- `worker.py` 的单机系统说明与技能创作模板：统一同一个输出约定，不混用旧远程 Python 沙箱的 `/home/user/workspace/output`。
- 已保存的 `text-to-image` 技能：将 `DEFAULT_OUTPUT_DIR` 改为 `Path.cwd() / 'output'`，修正 SKILL.md。若保留 `--output`，校验最终路径仍在输出目录内。更推荐恢复原生插件后不再用这份替代脚本承担 Seedream 生图。
- 增加有意义的后端回归检查：模型拿到的工具说明与沙箱输出位置一致；合法输出被回收、越界仍被拒绝。无需改 Flutter 页面或放宽文件系统权限。

### C. 重试策略单独处理

短期保持现有上限，修正技能后在新任务中试用。不要把失败后同任务不能重试误判为连接故障。

若需要自动恢复，建议明确区分“执行前校验失败”“已启动但未发请求”“外部请求结果未知”；只给安全的本地前置失败补救机会，并设有限次数。生图 API 可能计费，超时或结果未知不得盲目自动重试。这个策略改变用户流程和计费风险，需要先确定范围，不能顺手去掉所有配额。
