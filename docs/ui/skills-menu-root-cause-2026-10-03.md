# 技能菜单与功能胶囊：根因和修复方案

实施顺序：保持阅读任务胶囊不变，调整技能 / MCP 胶囊匹配其现有视觉规格 → 将技能面板改为锚定浮层 → 补齐 SVG 图标与菜单排版 → 将能力选择接入输入标签和消息数据。

**用户已确认的视觉目标（2026-10-03）：**以用户提供的左图为视觉基准，覆盖三个功能胶囊与技能 / 插件菜单的尺寸比例、图标、字体、颜色、间距、圆角和阴影。后续反馈要求收窄技能 / 插件及阅读任务菜单卡片，并移除技能菜单底部小尖角。补充的空数据规则见第 4 节：无技能、无插件时，只显示四个功能入口和管理能力栏，卡片自适应降低高度。

依据：用户确认的一比一原型目标、输入栏标签截图及当前工作区源码。技术参考与实施取舍已记入 [交互规格](../design/skills-plugins-v1-state-spec.md)。

## 1. 胶囊不统一：两套组件、两套尺寸、两套材质

阅读胶囊在 `lib/widgets/reading_task_switcher.dart:488`；技能与 MCP 在 `lib/features/capabilities/presentation/skills_plugins_composer_controls.dart:254`。

| 参数 | 阅读胶囊 | 技能 / MCP 胶囊 |
| --- | --- | --- |
| 可见背景高度 | 默认字号下内容 18 + 上下内边距 16，约 34；另有边框影响 | 最小高度 48 |
| 背景内边距 | 横向 11、纵向 8 | 横向 14、纵向 10 |
| 圆角 | 13 | 15 |
| 主图标 | 18 | 20 |
| 字号 | 13，w500 | 14，未显式指定字重 |
| 箭头 | Phosphor 14 | Material 18 |
| 背景 | `_GlassPanel`，模糊、边框与阴影 | 独立白色容器与另一套阴影 |
| 外层间距 | 纵向 7，额外底部 8 | 无对应外层间距 |

`home_page.dart:4915` 将完整的 `ReadingTaskSwitcher` 作为 `leadingControl` 插入另外两个胶囊所在的 Row，连原本独立布局需要的外层留白也一起带入。因此可见背景的高度和垂直位置都不同。技能和 MCP 本身复用同一个 `_pill`，二者已有相同尺寸规则；核心不一致发生在它们与阅读胶囊之间。

**用户范围修正：**阅读任务胶囊保持原样，不改它的组件、布局、图标或交互。技能 / MCP 使用独立外观组件，沿用阅读胶囊当前的可见高度、圆角、字号、字重、图标尺寸、箭头、内边距、玻璃材质与阴影；触控区域仍保持 48 dp。宽度按文字内容适配，不要求等宽。

**对齐修复：**阅读胶囊的 48 dp 触控区外还有 8 dp 透明底部留白；技能 / MCP 胶囊补上同样的外层留白，保持内部 48 dp 触控区不变。三者在 Row 中占据相同的 56 dp 布局高度后，玻璃背景的垂直起点一致；浮层锚点也与视觉胶囊对齐。技能与 MCP 胶囊显式复用阅读胶囊的涟漪半径、颜色和透明高亮设置，阴影沿用其相同的颜色、模糊与偏移。

原型与实拍虽同为竖屏，但图片像素尺寸、设备逻辑尺寸和字体缩放未经确认；不能将原型像素直接当作 Flutter dp。实现前以原型相对比例整理尺寸表，统一定标。

## 2. 菜单不符合原型：实现的是整行面板

`skills_plugins_composer_controls.dart:807` 的 Column 使用 `crossAxisAlignment: stretch`，并在第 812 行直接插入 `_panel()`。它参与输入区布局并占满父级可用宽度，没有胶囊锚点、独立菜单宽度或指向胶囊的尖角。

`_panel()` 第 453 行起还明确添加了原型没有的标题栏、问号、右上关闭、引导说明、数字序号、行尾箭头和“关闭 / 跳过”。这是结构性偏差，单独改宽度或圆角不能解决。

**修复：**主菜单改为胶囊上方的锚定浮层，使用统一测量后的目标宽度及屏幕边缘约束；高度随内容增长，到可用高度上限后内部滚动。菜单不再作为输入区 Column 的普通子项。定位方式可参考项目现有阅读菜单，但不照搬其尺寸。

有技能和插件时，主菜单结构恢复为：四个图标功能行 → 分隔线 → 技能分组 → 插件分组 → 分隔线 → 管理我的能力。分组按实际可展示内容条件渲染，空数据结构遵循第 4 节。移除主菜单的额外标题、说明、编号、尾部箭头和“关闭 / 跳过”。根据用户后续确认，点击“创建技能 / 插件”直接向输入栏插入功能标签，不再进入创建类型选择面板，也不弹出任何新窗口（详见第 5 节）。管理和草稿审核保留各自所需操作。

收起规则建议为再次点击胶囊、点击外部或系统返回；确认后纳入交互规格。打开另一菜单时关闭当前菜单，处理键盘、安全区和边缘位置。

另有确定的行为错误：第 643–652 行显示“关闭”的按钮实际执行 `_manage = !_manage`，会进入管理态，而非关闭菜单。应移除该主菜单按钮，或明确改为 `_open = false`。

## 3. 图标缺失：资产存在，但菜单没有使用

前四行调用 `_numberedRow()`（第 308 行），内部固定画 30×30 的编号框和数字；并没有请求加载对应功能图标。因此不是 SVG 加载失败。

| 原型图标 | 仓库可核对的现有 SVG | 修复要求 |
| --- | --- | --- |
| 创建技能 / 插件：拼图 | `assets/icons/capabilities/skill_plugin_capsule.svg` | 与技能 / 插件功能胶囊共用同一图标 |
| 创建图像：图片 | `assets/icons/capabilities/image.svg` | 已重绘相框、圆点和山形轮廓 |
| 联网搜索：地球与搜索 | `assets/icons/capabilities/web_search.svg` | 已重绘经纬线与放大镜组合 |
| 绘图：铅笔 | `assets/icons/capabilities/brush.svg` | 已重绘原型中的斜置铅笔轮廓 |
| 管理我的能力：齿轮 | `assets/icons/capabilities/settings.svg` | 已重绘空心圆心的齿轮轮廓 |

技能 / 插件胶囊和首个菜单功能行共用 `assets/icons/capabilities/skill_plugin_capsule.svg`。本次再次收窄主菜单为视口 40%、210–240 dp，并将功能内容组距卡片两侧各设为 16 dp；菜单水平中心跟随技能 / 插件胶囊，卡片底边固定在按钮上方 8 dp。管理面板保留 48%、220–320 dp。五个菜单图标已生成 80×80 独立预览，并与用户提供的图标裁图逐项核对；本次页面实际菜单仍待同 viewport 视觉验收。

保存能力行另有两处差异：第 371 行按类型统一选择 `auto_stories` 或 `extension`，没有按具体能力映射彩色书本 / Documents 标识；第 246 行 `_icon()` 强制黑色 `colorFilter`，即使传入彩色 SVG 也会被染为单色。

**修复：**区分单色功能图标与保留原色的能力标识；已知能力建立明确的图标映射，未知能力使用通用回退。先检查现有能力标识字段，若需要扩展持久化模型，单独确认，不为视觉修复直接迁移数据。原始 SVG 优先；不能忠实复用的固定图形应独立重建 SVG，预览确认后登记来源、路径、viewBox、显示尺寸、状态和消费组件，再接入。禁止截图裁片或业务页面内随意绘制替代。

阅读胶囊原型是四宫格，目前使用书本图标。用户随后明确要求保持阅读任务胶囊不动，因此本轮不更改它；只处理技能与 MCP 胶囊及技能菜单中的图标。

## 4. 内容与状态差异应分开处理

`_recordRow()` 第 387 行使用 Column，把名称与简介上下排；原型中的已保存技能、插件是名称与简介同行。改为宽度允许时同行，长名称与小屏按确认规则省略或换行。功能入口仍保留两行标题与说明，不混用这两类行布局。

原型有“书本变童话”和 Documents，实拍显示无保存能力。不能为了像原型而把示例写进真实用户数据。视觉验收使用隔离的固定样例。

**已确认的空数据规则：**没有创建或添加任何技能和插件时，主菜单只显示“创建技能 / 插件、创建图像、联网搜索、绘图”四个功能入口，以及底部“管理我的能力”栏。删除“技能”和“插件”分组标题、列表区域及其占位间距；不显示“还没有保存的技能或插件”等空状态提示。四个功能与管理栏之间仅保留一条分隔线，不遗留双分隔线或空白段。

卡片由实际内容撑高，不固定为有数据时的高度，也不设置保留空分组空间的最小高度。卡片保持与胶囊的锚定间距但不显示底部尖角；内容减少时上边缘向下收缩，四个功能行、管理栏自身的尺寸和间距保持原型规格，不通过压缩行高降低卡片高度。

仅有技能时显示技能分组，仅有插件时显示插件分组；空分组不渲染。新增或删除条目后按实际可展示内容重新计算高度；现有“在胶囊中显示”设置继续生效，可展示列表均为空时使用同一紧凑结构。此规则只针对主菜单，不删除管理页所需的空状态或隐藏条目。

当前代码明确提示图像、联网搜索、绘图尚未开放。补齐图标不等于实现这些功能；原型文案若会让用户误认为可用，应在确认规格中保留清楚的未开放反馈。

## 5. 已确认：输入栏轻量标签 UI 与编辑、发送交互

用户于 2026-10-03 确认以下规则。视觉依据为用户补充的 Codex 输入栏截图（`codex-clipboard-b048a3a1-6ebf-41c9-9336-91ff904619a9.png`），仅参考其中图标与文本的轻量标签表现；不引入截图中其他工具栏或界面。原菜单和胶囊继续以最初左图为一比一还原目标。

1. **直接插入：**点击“创建技能 / 插件”，直接把对应功能标签添加进输入栏，不弹窗、不显示二级创建类型选择。点击已有技能或插件，同样添加对应能力标签。原有文字不应因添加标签丢失。
2. **标签外观：**输入栏标签由轻量图标和名称文本组成，文字与 16sp 正文同字号并保留中粗强调；图标与文字包在白色轻阴影容器中，不显示关闭按钮。已发送消息仍沿用正文尺寸，不增加容器。标签位于输入栏可编辑文本流中，不是输入栏上方独立的选中状态卡片。功能图标使用确认后的 SVG，能力标识按其资产规则保留原色。
3. **参与编辑：**标签属于输入内容，支持光标在标签前后移动、键盘退格 / Delete 删除以及触屏选区删除。每个标签是一个不可拆分的语义单元，删除时整体移除，不留下半个名称或孤立图标；跨文字与标签的选区删除应同时正确更新两者。移除标签也必须移除对应待发送的能力引用。
4. **随消息发送：**有文字时，标签和文字作为同一条消息发送，保留标签的能力身份与功能含义；不能只发送名称字符串，或只在输入栏显示而请求中遗漏能力。发送后的消息也须保留标签及文字的对应关系，不能发送后丢失标签。
5. **允许纯标签：**输入栏只有有效标签、没有文字时，发送按钮仍可用，允许发送纯标签消息，不强制补充正文。文字与标签都为空时继续使用空消息限制；发送入口与实际提交校验必须一致。

6. **不自动弹键盘：**选择功能或能力插入标签后，输入框保持未聚焦并收起键盘；用户点击输入区域后再开始编辑。

**实现边界：**这部分包含输入编辑与消息数据行为变化，不能仅靠把现有选择状态换成无背景 Row 完成。后续实现需先核对现有输入控制器、选区和输入法组合文本处理、能力选择结构、消息提交与历史存储，再确定标签表示、序列化及兼容方案；当前文档不预设新增依赖或数据库迁移。发送失败或重试时应保留同一组文字与标签，避免标签丢失或重复提交。此交互不代表尚未开放的插件执行能力已经实现。

**V1 数据边界：**当前消息模型只有一个能力元数据字段，因此每条消息保留一个能力标签；菜单再次选择时替换草稿中的标签。多标签协议、重复标签和创建标签与已有能力并存不纳入本次实现，后续扩展时再单独确认。

## 6. 修复范围与验收

1. 保持阅读任务胶囊原样；技能和 MCP 胶囊匹配其现有尺寸、字体、图标、箭头和玻璃外观。
2. 修改展示与输入交互：技能锚定浮层、原型图标功能行与保存能力行；创建入口改为直接插入轻量标签，取消创建类型选择面板，接入标签编辑和消息发送链路。保留管理及草稿所需业务能力。
3. 补齐状态：关闭、展开、空数据、有数据、长文本、未开放能力、键盘弹出和屏幕边缘。避免多个浮层相互遮挡。
4. 同尺寸同状态验收：分别比较胶囊高度和对齐、浮层锚点及宽度、图标轮廓和颜色、分组与间距；分别记录无技能无插件、仅技能、仅插件、两者都有四种数据状态。空数据必须只有四个功能入口、一条分隔线和管理栏，无分组标题、提示文案或占位空白；增删条目后卡片高度自适应，底部锚点保持稳定。再验证选择、关闭、返回及管理入口。
5. 标签闭环验收：点击创建入口无弹窗且直接插入；已有技能、插件采用同一轻量样式；光标前后移动、退格、Delete、触屏选择和混合选区删除正确；中文输入法组合文本不损坏标签。验证标签加文字、纯标签两种发送，以及全部删除后的空消息限制；核对请求、发送后消息和历史恢复保留能力身份，失败重试不丢失标签。

当前实现中：阅读任务胶囊无差异；技能 / MCP 胶囊已按阅读胶囊现有尺寸和材质独立匹配；技能锚定菜单、四项原型图标与逐字说明、彩色技能 / 插件图标、紧凑空数据状态、输入标签及单能力消息历史 / 发送链路已接入。V1 保持现有单能力消息模型。未运行静态分析、测试、构建或真机操作；同 viewport 实际渲染对比待后续验证。
