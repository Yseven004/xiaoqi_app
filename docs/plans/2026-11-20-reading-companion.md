## 交付顺序

1. 更新两个导入入口，共用四行操作。继续复用 ISBN 与本机导入链路，网上找书链接到公开目录，微信图书导入沿用定稿中的预留状态。
2. 在阅读空间从已选书籍进入伴读。复用正式书源及派生文档，EPUB 按章排版。PDF 保持原页，存在文字层时提供选段操作。书源缺失时提供真实入口。
3. 将选段问答接入现有会话与正式 Agent 请求。安装中心「已安装」显示可开关的内置伴读入口。记录代码、自动检查和同状态视觉验收的实际结果。
4. 同步关联书籍正文。书籍进入任务后，发送首问时将可读正文完整转为 Markdown，登记成同一任务可按需读取的资料。后续问答或分支可继续引用适用的资料。

## 本轮实现与边界

- 两处导入卡共用入口文案、顺序与导入链路。网上找书打开 Project Gutenberg 目录。该目录的 OPDS 搜索端点在本轮核查时返回 HTTP 503，应用内自动获取仍待接入。微信图书导入保留预留状态，伴读中的微信附件可以选择已保存的文件。
- 伴读菜单、排版、选段、注释、选段问答和插件市场开关已接入。脑形按钮使用与定稿同义的独立 SVG，内部线条与定稿位图略有差异。用 SVG 资产预览核对轮廓，整屏同状态比较待真机。
- 首轮交付实现了书目和选段导入。用户随后确认关联书籍的整份可读正文也作为 Markdown 任务资料，按上述第 4 步补齐；扫描 PDF 保持原页阅读。会话执行、流、快照和服务器接口继续沿用当前实现。
- 正文同步在发送阅读任务问题时触发。长 Markdown 按现有附件上限分卷，整份资料就绪后才加入任务。资料更新后会重新转换。暂停续跑使用原快照保存的资料引用，避免替换本次执行已绑定的文件。无文字页和未同步资料会有明确状态。
- 本地验证涵盖 EPUB 正文、PDFium 文字层与原页码、Markdown 分卷和重试、账号切换，以及服务端 Agent 读取第 36 章的合成资料、暂停后复用原资料绑定。测试使用本地样本和模拟账号。
- 相关 Dart 文件完成静态分析，结果无错误或警告，存量文件仍有 info 级提示。书库、安装市场、MCP 与会话回归共 20 项通过，包括选段经过历史恢复与问题分支后仍能读取。
- 同状态视觉比较、真实账号 Agent 闭环及 Android 真机均待验收。上述首轮正文同步使用原服务端附件接口。

## MarkItDown 替换

2026-11-20 用户要求采用微软 MarkItDown 转换 Agent 所用资料，并确认可以将任务关联的原始 PDF／EPUB 上传到小栖服务端。伴读页面继续读取本机原书和排版数据。转换输出作为当前任务资料。

| 需要 | 官方能力与版本 | 本项目接入 | 状态归属 |
| --- | --- | --- | --- |
| 本机展示原书 | 项目锁定的 pdfrx 与 EPUB 结构化阅读器 | 沿用原页、选文、注释和阅读进度 | Flutter 本地书库 |
| PDF／EPUB 转 Markdown | [Microsoft MarkItDown v0.1.9](https://github.com/microsoft/markitdown/releases/tag/v0.1.9)（MIT），Python 文档转换 API | 书籍附件使用独立的转换配置。调用固定的本地转换脚本，保留 EPUB 阅读顺序。PDF 逐原页调用转换器并标记页码，跳过无文字页 | 小栖服务端现有附件缓存、租户隔离和资料就绪状态 |
| Agent 按需阅读 | 双端锁定 Genkit Dart 1.0.2，已有 Remote Agent `Message`、Session／Snapshot 与 `read_task_material` | Flutter 只把已就绪的书籍资料 ID 加到任务。服务端按问题取正文，暂停恢复继续用快照原绑定 | 附件服务保管输出。Genkit 会话持有执行和分支 |

使用按版本区分的附件转换配置，避免普通附件与书籍转换结果共用缓存键。转换过程在小栖服务端离线运行，输出不足或失败时在当前任务报告可读取范围。以合成 PDF／EPUB 验证后段查询、页码、空白页、失败重试、跨租户拒绝和原快照恢复。客户端和服务端共同升级接口版本，使用现有发布管线建立回滚点。

实现约束与证据：

- 继续接受 256 MiB 以内的 PDF／EPUB 原文件。转换后的 Markdown 文字上限为 50 MiB，单份 PDF 最多处理 2,000 个物理页。原件和派生正文沿用附件服务 24 小时缓存。工具读取和脚本附件使用转换后的 Markdown。
- EPUB 包读取只负责定位书内阅读顺序和章节，正文调用 MarkItDown 的官方 HTML 转换器。PDF 按页调用官方 PDF 转换器，扫描页保持无文字状态。
- 本地合成资料经过 MarkItDown 转换和附件存储后，Agent 资料工具读到了尾章。停止恢复测试核对原快照仍使用同一资料引用。书籍转换作为接口版本 37 的候选构建完成。

## 普通聊天附件

用户补充要求普通文档上传也由 MarkItDown 生成 Agent 资料。聊天的 PDF、EPUB、DOCX、PPTX、XLSX、TXT 和 Markdown 文件使用与书籍共享的服务端转换组件。服务端同一配置也接受 HTML 文件。普通 PDF 的文字层由 MarkItDown 转换，无文字页沿用现有按需 OCR。图片继续通过原有多模态附件入口交给模型。普通文档和阅读任务书籍使用各自的附件配置，服务器根据配置隔离转换缓存。

普通附件沿用 50 MiB 原件、10 MiB 正文和 PDF 500 个物理页的上限。Office 压缩容器另外受条目数与解压大小限制。转换后的 Markdown 交给现有 `read_task_material`，与书籍共用 Genkit Dart 1.0.2 的任务上下文和会话管理。转换失败沿用附件状态、取消和重试流程。服务重启后，源文件仍有效且中断的整份转换自动重新排队。保留旧资料的快照引用和读取方式。客户端和服务端配对发布在接口版本 38。

本地用合成 EPUB 和普通 HTML 从上传验证到 Agent 资料查询。转换器验证 Office 格式、中文文本及原页定位。附件服务验证混合 PDF 的按页 OCR、权限、取消及重启恢复。Flutter 验证原件上传、正确识别转换配置、PDF 进度和图片上传。
