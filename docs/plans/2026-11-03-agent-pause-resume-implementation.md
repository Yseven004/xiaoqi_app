# 暂停与恢复修复：实现与验收

## 已确认范围

用户要求直接修复暂停、继续、快照恢复和防重复执行，测试后完成服务端部署；真机验收由用户执行。沿用现有按钮和页面，不增加页面加载动画。

## 实现

- 客户端发起远程任务前持久化任务引用。暂停与失败保存半截回复时保留原任务；继续使用原任务检查点，以同一答案替换恢复结果。历史会话缺失本地任务引用时，从当前租户的消息绑定查询原任务；无快照时明确报错，不新建任务重放。
- 服务端把远程 Agent 接入取消控制器。暂停期间状态为 `pausing`，执行器结束后为 `cancelled`；重复恢复不能并发进入同一任务。进程重启后，失去执行者的远程运行记录收敛为 failed，保留恢复检查点和未知工具记录。
- 每次执行前持久化包含原输入的 Genkit 检查点。文字加配图在文字完成后额外保存正文、消息和固定图片参数；恢复优先读取该检查点，跳过已完成的正文生成。
- 复用 ToolExecution 的原任务执行记录：成功工具返回原结果；未确认的外部副作用保持阻断。完成任务的空消息重试返回原结果，避免再次进入运行时。
- 消息绑定冲突使用明确的 failedPrecondition 状态；新建失败任务不再遗留 running，原任务的状态不会被冲突请求改坏。
- 发布标识统一为 `2026-11-03-agent-resume`，Flutter 与服务器 API 契约均为 `26`。旧客户端需要重新构建，按单版本策略不保留旧契约兼容分支。

## 恢复边界与取舍

暂停是协作式取消，不冻结第三方请求。无法确认是否已经提交的外部操作不能自动重跑。输入回合中断时，从安全检查点重新驱动模型，已确认工具结果通过原操作记录复用；不承诺在任意 token 位置继续。文字加配图拥有独立文字完成检查点，可只执行剩余图片步骤。

服务端保持现有单实例部署，在当前进程内拦截同任务并发；进程重启以持久化检查点和工具记录恢复。没有引入新队列或新的 Agent 框架。

参考和定位证据见 [诊断与方案](2026-11-03-agent-pause-resume-diagnosis.md)。实现复用已固定的 Genkit 1.0.0 与现有存储，不复制第三方实现。

## 验收记录

- 新增 HTTP 用例：运行中暂停、同任务并发恢复被拒绝、快照恢复保持原消息与任务、已完成外部工具结果只执行一次、完成后重试不再执行运行时。
- 新增运行时用例：文字完成检查点跳过模型生成，仅执行剩余图片操作；重复恢复不重复生图。
- Windows 本地全套服务端测试 552 项通过；随后针对最终变更的恢复/运行时/执行记录测试 39 项通过。测试使用 XIAOQI_TEST_PYTHON 指向本机实际 Python；首轮应用商店占位入口失败不计为通过。
- 服务端 dart analyze 无问题。客户端针对变更文件检查没有 error/warning，存在 16 项已有 info 级风格提示；以 --no-fatal-infos 执行。
- APK 构建与部署结果以最终交付证据为准；执行中不标记为通过。
- 真机/Android 交互：未执行验证，待用户真机验证。

## 部署与回滚

检查通过后提交并推送同一 main 版本；使用 deploy_current.ps1 等待该提交的 CI 预构建产物，再执行 ECS 激活、健康与数据检查及清理。部署失败由脚本恢复当前健康版本，不清空恢复记录或持久数据。最多保留一个非运行应急恢复点。
