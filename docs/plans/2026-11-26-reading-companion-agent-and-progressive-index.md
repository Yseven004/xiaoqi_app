## 实现与验证记录

1. EPUB 冷开先显示目标章。目录可继续使用，新的跳转可以调整正在运行的解析任务。后台补齐正文和分页时保留阅读锚点。导入预热和阅读器共用同一版本的解析任务。在桌面用 96 章、每章 160 段的合成中文 EPUB 测了三次。目标第 82 章解析耗时 8–9 ms，旧路径全量解析耗时 422–438 ms。计时含读取文件和正文解析，不含实际设备冷磁盘、分页和绘制。
2. 服务端按批处理 EPUB/PDF。当前批次完成后优先最新的阅读目标，再从书序继续。每批提交 SQLite 事务后立即可检索。资料页显示云端准备范围和失败重试。覆盖了稀疏就绪范围、中文短词、原始页号、重启和资料撤权。PDF 无可靠目录时先排当前页，再排前后一页。具有可验证书目身份的书使用稳定的书籍键，其他资料使用本机作用域。设备各自确认授权。相同账号与资料版本复用已有索引，服务端在撤回最后一份授权后清除数据。跨设备真机验收尚待完成。
3. 云朵与独立伴读问答已接入。快捷解释由 Agent 判断是否补查一次。正式讨论使用独立会话，主 Agent 委派沿用 Genkit 子回合及父取消令牌。正式讨论摘要依据读者当前选择的已提交快照，由业务层保存选择，沿官方快照父链获取内容。临时解释、已切走的兄弟分支和已失权资料不进入共享摘要。
4. 有检索依据的答案可点「查看原文」。服务端提供资料版本与稳定位置。EPUB 引文唯一匹配时定位段落，存在歧义时定位章节。PDF 使用原文件页。自动化已覆盖同书不同 EPUB 版本的切换和段落回链。真实模型用合成书完成快捷解释和正式讨论，均找回了中文原句及章节位置。真实 PDF 点回、同状态视觉和真机端到端仍待验证。
5. 契约 45 已部署，运行提交为 `93c2976`。Linux CI、线上健康、生产数据与恢复点均通过发布脚本核验。68 项 Flutter 定向测试通过，Android ARM64 APK 已生成并通过签名校验。真实模型另验证了主 Agent 委派，官方快照中保留了工具调用和查证结果。多本代表性中文资料的命中率和设备上的首屏性能仍按第 9 节测量。

## 1. 读者最终得到什么

读者在手机或平板导入一本中文书，从目录跳到第七章，可以先看到该章正文，选一句话就地获得简短解释。需要讨论时，一步进入本书的伴读问答，再一步回到刚才的阅读位置。对于允许云端处理的资料，第七章一旦可查，伴读就能引用该章已完成的原文，其余章节继续准备。

| 已确认的产品决定 | 第一版边界 |
| --- | --- |
| 内置伴读插件有独立的读书 Agent | 阅读器直接调用。主 Agent 可委派复杂查书任务，两者可使用同账号、同书的相关压缩上下文。阅读器控件仍由插件管理。 |
| 快捷解释以原文为中心 | 选段和前后一两句通常够用。指代不清时，Agent 可自行决定补查一次本书已就绪正文。查不到就指出具体疑点。 |
| 临时解释和正式讨论有不同寿命 | 云朵可重新生成、切回上一条。进入深聊承接当前可见版本，第一次主动发送自定义问题时才进入本书历史。 |
| 手机和平板都保留阅读空间 | 云朵按上方、侧边、下方兜底摆放。自定义提问使用独立问答页，并保留返回原位置的入口。 |
| 新导入资料可以马上准备 | 导入确认说明整份资料的云端用途，默认开启，可对该资料选择仅本机。原件本地导入、手机显示正文、服务端索引就绪分别报告。 |
| 当前阅读位置优先 | 正在处理的一批先结束，然后处理最后停留的章节或页段，再从书序中最早未完成的单元继续。退出阅读器后，已上传且获准处理的资料继续完成。 |
| 以原文证据决定问答是否可靠 | EPUB 与有文字层的 PDF 为首发范围，扫描页保留原页阅读并标注缺少可检索文字。解析复用 MarkItDown、pypdf，检索复用 SQLite FTS5。整书 OCR、向量检索、EmbeddingGemma 2 和 DuckDB 均后置。 |

## 3. 阅读器交互与视觉验收基准

沿用现有选区菜单的「复制」「注释」「AI」。AI 入口建议显示「解释这段」与「自定义提问」两个动作，前者立即解读，后者直接打开问答页。深聊底栏沿用稿中的附件、语音和发送入口，既有模型设置可从次级入口使用。

| 入口或状态 | 行为、退出和异常处理 |
| --- | --- |
| 选段 →「解释这段」 | 获取原文、可可靠取得的前后一两句和源位置，立即启动一个临时回合。云内直接呈现简短解释，默认没有标题、编辑框或键盘。引用原文属于资料数据。 |
| 首次等待和出字 | 小云以指向选段的尾尖为锚点，按摆位方向展开，轮廓稳定后呈现已到达的回答。系统减少动态效果时直接显示完整轮廓。 |
| 摆放 | 用可见选区的逐行矩形、显示区域、安全区及工具栏边界计算空间。依次尝试上方、遮字较少的一侧、下方。尾巴朝选段，侧边可压少量未选文字。高亮、手柄、关键操作保持可用。极端大字或选区占满视口时，收为可点开的紧凑提示，完整解释可进问答页阅读。此降级作为工程建议验收。 |
| 重新生成 | 使用同一份选段与位置。云朵内部用两条灰色占位线表达等待。成功后可看新解释或切回「上一条」。切换已生成的版本直接显示。失败后恢复前一版及出处。 |
| 关闭、换选、翻页 | 关闭云结束本次短问并释放临时内容。新选区和新资料有新请求身份。锚点离屏收起云，迟到结果不能出现在另一段上。取消、断网和重试均保持正文位置，错误就地显示。 |
| 「继续聊」或自定义提问 | 两端都打开独立「伴读问答」。顶栏「原文」一步返回，标题下是书名，引文只占一行，点开轻量引用弹层即可查看全文，关闭回到当前讨论。继续聊承接当前可见解释及其引文。直接自定义提问承接所选引文。既有无选段问答使用当前书籍范围。打开页面、查看或返回均不产生正式历史。 |
| 发送与返回 | 第一次主动发送才创建或绑定正式会话并保存当前引文、所选解释与问题。重复点发送或断线重试只生成一条提问。返回时恢复原资料、格式和锚点，正式讨论可再进入。输入器沿用文字、语音、模型等现有能力和既有权限反馈。 |

视觉基准为[问答页及操作原稿](../design/reading-companion/confirmed/cloud-and-discussion-2026-11-26.png)和用户确认的[三栏云朵 GIF](../design/reading-companion/confirmed/cloud-placement-2026-11-26.gif)。三栏 GIF 覆盖摆位、首次展开和重生占位。静态原稿中的下方云和标题已由后续摆位与无标题规则修订。单云漂移稿保留为探索记录。

伴读问答发送前只查当前账号和资料版本已授权的逐章索引，有已就绪的正文就随现有资料参数提交。尚无可用索引时，按已提供的选段和书籍信息开始回答。客户端跳过旧的整本附件转换队列；会话及流式响应仍由已锁定的 Genkit Dart 1.0.2 `remoteAgent` 和现有服务端会话处理。

实现时从确认的云形制作独立 SVG，分别登记来源、viewBox、显示尺寸、尾巴方向和消费组件，先核对至少 64 × 64 的独立预览及实际尺寸。文字、按钮、语义与动效由 Flutter 渲染。复用系统返回、焦点管理、深色配色与屏幕阅读器语义。快捷解释不抢焦点。空输入收键盘同时失焦，有文字时保留草稿，点外部按钮当次生效。页面进入使用静态占位。[全局设计规则](../../DESIGN.md)

## 4. 一个读书角色，三种调用

| 调用方式 | 输入与工具范围 | 结果与状态所有者 |
| --- | --- | --- |
| 阅读器直达 · 快捷解释 | 锁定本次选段、邻句、账号、书籍资料版本、位置，只开放一次该版本的只读补查。自行选择是否查、查什么。 | 正常情况下一个模型回合即可回答。Flutter 持有可见解释版本，服务端使用短生命周期的隔离执行状态。结束后释放，排除出历史、长期摘要和正文索引。 |
| 阅读器直达 · 深聊 | 当前书籍、用户选定的引文和话题，允许按需查询本书。附件、技能及 MCP 仅限用户本场启用、已安装且有权限的能力。沿用工具审批及版本绑定。 | 独立伴读会话与分支。持久对话、流式、暂停及恢复由现有 Genkit 传输、SessionStore 和任务层承接。 |
| 主 Agent 委派 · 复杂书籍问题 | 主 Agent 按需选择委派，传任务与少量相关摘要。服务端从父回合已授权绑定建立读书范围，子调用只读查证。 | 回给主 Agent 结论、原文出处、证据缺口。委派有独立调用身份，避免改写读者正在进行的深聊。主 Agent 负责最终答复。 |

快捷解释只需以下一条提示规则。

> 结合选段和前后文直接解释。指代不清时，可查一次本书已就绪的正文。仍不确定，就说明哪里不确定。

一次补查的额度属于一次解释生成。工具在调用边界原子占用，以同一请求和工具引用实现幂等重放，并拒绝并发或后续的第二次实际检索。重新生成是读者主动发起的新回合。资料范围、次数上限、取消和权限由运行时保证。保持标准模型与工具循环。

**上下文共享。** 主界面与伴读可自动取同账号、同书、与问题相关的少量已保存讨论摘要。正式发送后再按已提交的会话分支异步更新摘要，记录来源会话、消息和资料版本，可重建、可删除。讨论主题、读者观点、未解问题与书中引用分字段保存。回答“作者怎么说”时回到书中原文，回答“我之前怎么理解”时标明来自讨论。切账号、撤权、删会话和更换资料后重验可见性，重新生成只引用读者选中的分支。摘要失败时照常阅读和问答。跨会话分享范围由业务层控制，单会话长度压缩沿用[现有官方压缩接入](../../xiaoqi_harness/genkit_server/lib/src/official_context_compression.dart)。

## 5. 原书导入、首屏和后台调度

**导入与隐私。** 三个导入入口共用同一书源登记。成功保存本地原件和来源关联后即可打开。云端开关属于具体资料，导入确认展示会上传供 AI 查书。仅本机时不上传原件或后台建云索引。用户主动使用在线 AI 时，按界面告知的范围仅发送本次选段与必要邻文。未登录、离线或上传失败时保留本地阅读，云端准备显示实际状态。恢复网络并校验原账号与授权后可重试。登出期间冻结待传作业。旧资料尊重既有授权，不因升级批量上传。

**手机首屏。** EPUB 先读取包结构、spine、目录和当前位置，解析目标正文单元，交付首帧所需块和样式。继续使用章节 ID、href、已有片段/分页缓存，以资料及解析版本校验缓存。跳转位置未加载时只等目标所需内容，处理中的旧页面不能覆盖新位置。目录总页数尚未计算时可先显示真实章名或页内位置。原始 PDF 继续走现有原页渲染。手机 PDF 电子书重排沿用其独立准备与缓存，云端索引进度不能当作设备重排进度。[PDF 重排基线](2026-11-24-companion-pdf-reflow-repair.md) · [阅读器定位类型](../../lib/models/reader_pagination.dart)

**服务端每批如何运行。**

1. 上传完整性校验通过后，按认证账号、书籍、资料版本登记绑定。解析器打开原件，枚举稳定单元、估算范围。EPUB 以 spine 项为物理单元，目录项可指同一项不同片段，也可能跨项。PDF 使用从 1 开始的原始页号。
2. 沿用 MarkItDown 及 pypdf 转换路径。一个工作进程保持原件打开，Dart 协调器在批次边界下发下一组单元。Python 逐单元输出稳定 ID、原始位置、可读段落以及明确的完成、无文本或错误标志。仅将原单向输出改成逐行读取仍无法改变解析顺序。保留归档路径/解压安全检查、字节数、耗时及内存上限。
3. 首份可读内容尽早提交。每批只在写入 SQLite 时持有短事务。解析、上传与模型调用都在事务外。完成集合可稀疏，例如第一章及第七章同时已就绪。优先章很长时边处理边使已完成单元可查。一项包含多个目录章节时复用这项结果。
4. 导航只更新当前目标。客户端按账号、资料版本和阅读实例暂存最后一次跳转。即使读者在上传或登记完成前就跳到第七章，登记或重连成功且阅读器仍活跃时也立即补发最后目标。关闭后丢弃尚未发送的目标。每个实例上报单调递增序号。多设备竞争时以最近有效的交互目标为先，崩溃遗留目标到期释放。进行中的批次先结束，再读最新目标。对可靠目录，按章节所属单元优先。PDF 无可靠范围时先当前原页，再邻页。已完成单元直接跳过。优先范围完成后回最早未完成处继续。连跳第三、七、十二章只留下十二章这个待处理目标。
5. 退出阅读器清除交互优先级，已上传、仍授权的任务继续按书序。应用被杀时未上传完的资料在下次可运行时按原账号和授权恢复。云端已受理的任务独立运行。进程重启后重新认领未完成单元，已提交的内容立刻可查。重复导入、双击重试、两个 worker 交替认领均须幂等。

PDF 书签须能映射当前原件、有序且有可信页边界才可作为章范围。只有标题时走原页策略。无文字页记录原页及处理结果，整本无可读文字时返回原因，仍可查看原 PDF。某单元损坏保留其他已提交结果，并公布未完成范围。整份超限或无效归档按现有政策终止并停止提供不应保留的数据。并发以现有资源预算优先保证读操作和首批可查，在基线后调批量大小、邻页窗口与公平性。[解析器限制](../../xiaoqi_harness/genkit_server/bin/book_markitdown.py) · [部署资源配置](../../xiaoqi_harness/deploy/compose.yaml)

## 6. SQLite 数据归属、检索与原文定位

手机数据库管理本地原件、阅读位置和资料选择。服务端使用现有 `xiaoqi.sqlite3`，已启用 WAL。长期书源与普通临时附件使用各自的生命周期。下表为建议的逻辑模型，可整合既有表和键。[书源模型](../../lib/models/book_source.dart) · [服务端数据库](../../xiaoqi_harness/genkit_server/lib/src/store.dart)

| 数据 | 主键、关联及写入约束 |
| --- | --- |
| 授权书源与解析版本 | 绑定账号、稳定书籍标识、资料标识、原件内容哈希、解析规则版本、授权状态。历史资料版本 ID 缺失时用经核验的原件哈希补齐。账号与资料绑定是访问入口。同账号相同原件及规则可以复用解析结果。 |
| 工单及完成单元 | 持久化待办、有效任务代次、当前目标、已提交单元或页范围、可重试原因。单元键为解析版本和 spine 项或原始页。唯一约束防止重复。任务认领到期可恢复，提交时再次校验代次和授权。 |
| 段落与全文索引 | 每段保存单元内序号、可核查原文、用于查找的规范化文本、前后段关系和源锚点。FTS5 索引关联段落 ID。章节或页批次的正文、FTS、完成标记和覆盖进度在同一事务提交。中断只能看到前一完整批次。 |
| 正式讨论摘要 | 引用会话、选定快照、消息和资料版本，并绑定账号及书。正文索引与讨论摘要分别查询。正文结果要能还原到书里，摘要结果要能追到讨论来源。 |

**一次查书。** 现有工具收到授权资料 ID、阅读锚点及 Agent 自选的少量有辨识度的词或短语。先从已就绪的当前单元和相邻原文尝试消解指代，必要时在同一调用内查该版本其余就绪段落。按确切引文、多个有效词共同命中、正文与目录的区别以及阅读位置排序。返回少量片段、可信位置和覆盖状态，点击可回原处。整章分析和附件概览仍走原有对应模式。快问的零命中不触发概览抽样、排队或等待整书。

**中文搜索。** FTS5 使用 trigram 处理三字及以上的连续短语，多个短语分别绑定、转义后查询，避免将整句问话视为一个词。对“女王”等一两字词在授权范围内做有界精确包含匹配，先当前章及邻段。若扫描上限耗尽，明确返回尚未搜完的范围。对“他”“这两所”等缺少区分度的指代，以选段位置找有证据的上下文。保留原文和原坐标，另建检索字段处理全半角、可确定的软换行与空白。不得把双栏、换段或跨页文本直接拼成一句引文。[SQLite FTS5 分词行为](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)

**点回原文。** EPUB 使用与 Flutter 相同的 spine item ID、href、原文 fragment 或可复核的上下文短引。能唯一匹配时再高亮选段，表格等无法逐字标记的对象按块提示。重复句难以区分时定位到章节并说明粒度。PDF 用原文件页号定位，在 PDF 阅读时可按可靠坐标定位页内，在电子书阅读时把原文件页和选段映射到重排段落，保留当前格式。内部片段号、界面重排页号、Markdown 标题和规范化字符偏移均不能直接充当原书位置。旧版本出处始终绑定旧原件，无法访问时显示原出处及不可用状态。

**撤权与再导入。** 删除云端资料或收回许可时先使绑定不可读，再停止旧代次任务，清理相应原件、派生正文、FTS 和摘要引用。共享的同账号结果仅在最后一个有效绑定移除后回收。新文件附到同书时创建独立版本，原书源及旧笔记依原有生命周期保留。旧任务、旧快照和恢复中的请求沿用当时绑定，并重新校验当前权限。普通附件仍沿用当前缓存期限。

## 7. 客户端与服务端契约

下列是实施所需的最小业务交互。优先扩展现有上传、资料读取和 Agent 协议。仅批次导航优先级、长期书源状态等缺口增加业务端点。优先级更新由阅读器发出，不注册成模型工具。

| 操作 | 请求和结果 | 幂等及失败语义 |
| --- | --- | --- |
| 登记或上传书源 | 上传原件时附书籍、资料版本、安装绑定和当前授权代次。返回服务端资料 ID、处理代次和准备状态。已有合法结果时只登记新增绑定。 | 认证身份由服务端取得。撤权轮换该安装的授权代次，拒绝迟到的旧上传。文件校验失败保留客户端原件。 |
| 读取准备状态 | 返回上传/排队/解析/完成/失败、已提交范围、无文本范围及可重试状态。书级覆盖与单元可读分别表达。 | 部分覆盖可以同时带局部错误。查询状态只读，重复查询不启动新转换。 |
| 更新/释放当前目标 | 提交经验证的书源、阅读实例、导航序号、章或原页。合并连续跳转。登记完成或重连时补发仍活跃的最后目标。 | 忽略过期或重复事件。释放目标与删除书源分别处理。 |
| 书籍查询 | 沿用 `read_task_material`，结果含 `matches[]`、每段 `quote/locator/sourceVersion`、`coverage` 及搜索是否穷尽。 | 区分目标未就绪、在已查范围无匹配、扫描预算耗尽、无可读文字、失权及服务故障。工具一次返回即可供 Agent 说明证据边界。 |
| 伴读回合与晋升 | 沿用官方流式消息、取消和快照语义。入口区别临时解释、持续讨论、主界面委派。首次主动发送带当前可见解释和客户端消息 ID。 | Flutter 持有临时解释和出典。服务端独立核验当前账号、讨论所属书籍和所查资料版本，生成可信出典。关闭临时云不会删除已有正式讨论或取消解析工单。 |

基线双端 API 契约为 `44`。实施时以当时 main 的值同步提升双端契约及统一发布标识。不匹配时走已有升级提示。历史资料兼容由数据迁移解决。普通聊天、普通附件上传、书源选择、注释笔记和 PDF 原页阅读分别做回归。[客户端版本](../../lib/config/release.dart) · [服务端版本](../../xiaoqi_harness/genkit_server/lib/src/release.dart)

服务端为持久会话绑定执行角色、账号、书籍及资料范围。读取、恢复、委派续接和分支均核对该绑定及当前授权，覆盖同账号跨书和误传主聊天快照的情况。旧版主 Agent 快照按原执行身份恢复。用户要在新版伴读继续旧话题时，可承接可见摘要另开正式讨论。

## 9. 验收与度量

用许可覆盖测试和记录的真实中文 EPUB、文字 PDF 建立样本，再补合成边界样本。至少区分普通长书、单个超长 spine、有效/缺失 PDF 书签、双栏断行、重复句、混合扫描和全扫描。固定原件哈希、资料版本、章节与正确引文、目标设备、网络条件及服务器资源。冷测使用无任何本地解析缓存、云端索引的新书绑定，热测重复打开已完成版本。记录每个样本的试次与分布。

新旧版本以相同顺序导入、立即跳章，并在固定时点提同一个需要原文的问句。旧版首次提问才启动备书，计时应保留这一段等待。用只读观测获取就绪时间，避免为了测量而提前触发解析。增设上传尚未登记时连跳、登记前退出两个场景，分别验证补发最后目标与按书序继续。

| 验收面 | 操作与判定 |
| --- | --- |
| 速度 | 同一本新书，导入后立即跳第七章。从同一次跳转分别记录到**目标章正文首帧**和**伴读检索能返回指定原句**的时间。另记导入开始到首个可查单元、整书完成、上传/排队/解析/索引分项、峰值资源、查询耗时及首字时间。小样本保留逐次结果，试次充分后报中位数与 P95。用旧版和候选版同条件数据定秒数、PDF 邻页窗口和批量参数，冻结后跑回归。 |
| 中文准确度 | 分别统计目标原文进入前三条的题数/有答案题数、点回正确页或章节及唯一段落的比例、无依据题中如实指出疑点的比例。必须覆盖两字人名、同名学校、目录同词、换行、跨段指代和答案尚未就绪。对“这两所大学”能给名字只说明实体命中。不得凭此推出作者未说明的动机。 |
| 快捷解释 | 分别输入上下文充分或指代模糊的选段，再覆盖无匹配、尚无就绪章节和网络中断。核对快问直接到达伴读 Agent，书籍检索调用次数为零或一，每处引用对应授权原文。重试、双击和并发工具请求遵守单次预算。 |
| 双端 UI | 同状态覆盖手机/平板、横竖屏、深浅色、大字号、减少动态。上方有空间必须在上方。侧放最多遮少量未选正文，三种摆位均检验高亮和尾巴。验证首生成、重生、上一条、断网、关闭、返回原位、引文展开、输入焦点及屏幕阅读器。留存相同 viewport 的目标与实际截图，动效另外留录屏。 |
| 会话与权限 | 快捷关闭、只打开深聊后返回、首次发送重复提交、同账号跨书/主聊天快照被拒、两个账号同名书、摘要删除、主 Agent 委派、暂停恢复及重新生成分支。父取消时，用 Trace 与可观测慢模型/工具验证子执行确实收到停止、后续读取停止、迟到结果不进入父会话，独立的书籍解析工单仍可完成。 |
| 调度及数据 | 重复导入，单元事务前/后断电，进程重启，两次认领，跨版本回链，处理时撤权、离线重连、登录切换、关阅读器和整书无文字。稀疏就绪集合准确，查不到时不拿概览当证据，撤权立即阻断旧 job 和读请求。 |

扩展既有[资料准备测试](../../test/reading_task_materials_test.dart)、[导入锚点测试](../../test/book_source_import_anchor_test.dart)、[阅读器导航测试](../../test/reading_companion_navigation_test.dart)、[PDF 测试](../../test/reading_companion_pdf_test.dart)、[转换器测试](../../xiaoqi_harness/genkit_server/test/test_book_markitdown.py)及[服务端附件测试](../../xiaoqi_harness/genkit_server/test/attachment_service_test.dart)。新增用例围绕稀疏提交、优先级和零命中等现有覆盖缺口。

Agent 验收用项目的[本地 Genkit DevTools Flow](../../xiaoqi_harness/genkit_server/tool/genkit_devtools_agent.dart)，用隔离账号和授权书源逐 span 看模型输入、工具引用、原文证据、结束原因、父子取消及快照关系。性能与 UI 在实际目标设备另验。服务端合成账号跑通与真实账号安装权限分开记录。生产日志仅记必要的脱敏标识、耗时、范围和错误类型。

## 10. 迁移、降级与发布

- **存量。** 使用可重复执行的增量迁移建立书籍绑定、单元及全文索引。保留既有书籍、多资料关联、注释、阅读位置和正式聊天。旧全量缓存仅在账号、原件哈希、解析版本和映射能完整核验时才可导入，否则按本资料授权重新构建。历史已完成会话保留其原身份，后续新伴读回合走专用身份。
- **性能降级。** 云端繁忙或暂不可达仍可本地打开。在线模型可用时，用手头选段给出有依据的解释。索引正在修复时可读取已验证的少量近邻，显式返回有限覆盖。PDF 扫描页回原页，旧本地缓存过期则回原件重新解析。对总大小、页数、输出体积、磁盘压力及超长单元执行有界处理和可恢复错误反馈。
- **发布。** 双端改动随同一 release 上线。校验运行镜像 FTS 能力及契约，暂停接收新写入并等当前批次提交或撤销，使用项目现有备份和单一恢复点。把新增授权绑定、已完成单元/段落数量、原文抽检、索引一致性及可恢复工单纳入部署数据验证。恢复演练须能实际查回固定原句，并证明撤权资料仍不可读。[发布规则](../architecture/release-flow-validation-2026-11-05.md) · [部署说明](../../xiaoqi_harness/deploy/README.docker.md) · [数据核对脚本](../../xiaoqi_harness/deploy/verify_store.py)
- **回滚。** 先在隔离副本验证上一版本应用可读取原有业务数据，以及新增派生索引可重建。生产切换失败保持写入闸门并使用脚本回滚，复核健康、契约、书籍/笔记/会话与恢复点的一致性，再恢复服务。已产生用户写入时按既有恢复流程核对并保全新增数据。上线后用授权测试书实测首屏、查回指定原句、云朵返回和正式保存，分别记录上线与验证有效。
