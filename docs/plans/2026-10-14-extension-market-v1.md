# 小七扩展市场 V1 实施计划（视觉冻结版）

日期：2026-10-14

状态：市场页与扩展详情页已确认；正式实现前须先完成测量规格与外部 SVG 素材清单。
本计划覆盖并替代旧计划中“插件市场、第三方插件与 MCP 后置”的相关范围；既有技能创建和聊天调用能力继续保留并迁移到统一扩展模型。

## 1. 目标、范围与成功标准

V1 建立统一的技能、Agent 插件和 MCP 市场，支持小七精选目录、公开 GitHub URL 导入、用户创建技能、安装、更新、卸载、会话选择和真实运行。插件指 Agent 插件，不是 Flutter/Android 插件。

成功标准：用户可完成“发现或导入 → 查看详情与作者 → 安装 → 在聊天中选择 → 成功调用 → 手动更新或卸载”的闭环；危险、不兼容或无法安全安装的扩展由平台直接阻止，用户不承担技术审查。

V1 不包含私有 GitHub 仓库、社区投稿、评分评论、自动更新、用户创建插件/MCP、插件 hooks、Flutter 插件和付费能力。Agent Plugins 1.0、常见 Codex/Claude 旧清单需归一化支持；hook 字段只记录不执行，纯 hook 插件判定不兼容。

### 市场页

- 顶部为返回、标题、搜索和“创建/导入”；该入口提供“创建技能”和“从公开 GitHub 导入”，不暗示 V1 可创建插件/MCP。
- 一级页签为“技能 / 插件 / MCP”，二级筛选为“精选 / 已安装 / 我创建的”，切换后保持各自滚动与筛选状态。
- “精选合集”固定 5 个合集：横向拖动并每 5 秒自动前进一项；用户触摸/拖动时暂停，停止交互 8 秒后恢复；开启减少动态效果时禁用自动轮播。只显示 5 个圆点，不显示左右箭头。
- 首页内容按分类分区。每个分类标题整行可点击进入完整分类页；平板预览严格为两列四行共 8 个条目，列宽 1:1、列间距 16dp、卡片等高，手机折叠为一列并保持阅读顺序。
- 条目包含作者随扩展提交的产品图标、名称、作者小头像与作者名、一行简介，以及独立的“＋/✓”安装控件。点击卡片主体进入详情；点击“＋”只安装；“✓”表示已安装。条目使用暖白表面、1px 低对比边界和极轻柔阴影，不能退化为无层次平面列表或厚重商城卡片。
- 作者头像缺失时使用名称首字默认头像。技能、插件、MCP 三个页签复用完全相同的条目结构。

### 详情页与作者页

- 标题区包含扩展图标、名称、可点击作者头像＋作者名、类型标签、平台检查状态、版本、可点击来源仓库、简介、适用内容和紧凑安装按钮。
- GitHub 来源使用 GitHub 官方 SVG 标志和外链图标；点击打开对应网页。作者入口打开作者资料与作品页，展示头像、名称、简介、主页以及其发布的技能/插件/MCP，作品列表复用市场页的等宽条目组件。
- 详情页主体由作者编辑并发布，包含简介、适用内容、“你可以用它做什么”的功能说明与配图，以及“如何使用”的提示词示例；平台只提供固定标题区、内容编辑器、区块模板、预览、校验和安全审核，不替作者统一生成正文或插图，也不将示例文案写死在页面代码中。
- “你可以用它做什么”默认支持定稿的一大两小图文区块，作者可在编辑器中填写标题、说明并上传配图；V1 只允许平台规定的安全区块、数量和顺序范围，确保作者可编辑但公开详情页仍能忠实保持定稿布局。
- “如何使用”按“例如：＋编号列表”呈现纯文本提示词，不做按钮、卡片或跳转。支持可变数量、长文本换行和作者更新。
- 不显示“更多信息”；许可证、扫描报告、完整依赖和内部兼容数据仅在平台后台保存，不占据普通详情页。
- 作者页尚无独立定稿图，必须先按上述结构生成视觉稿并由用户确认后才能编码；不得由实现者自行发挥。

### 作者内容与视觉资产规则

- 每个技能、插件和 MCP 的产品图标由该扩展作者创建或提供，并随发布内容一并提交；平台不为各扩展重新设计或自动生成图标。作者可以使用自制素材、官方资源或许可兼容的成熟图标库素材，但必须声明来源与使用权。
- 详情页主体中的功能配图同样由作者上传和维护。平台校验文件格式、尺寸、透明边界、安全性、可访问性替代文本和授权信息；不擅自替换作者素材。作者未提供产品图标时，直接按“技能 / 插件 / MCP”类型使用对应的小七官方默认图标，不阻止创建或发布；作者主动上传自定义图标时才校验该素材与授权。官方默认图标作为正式产品资产统一设计、冻结并以独立 SVG 接入，不临时手绘近似图标。
- 平台自身的通用界面图标仍按“项目现有 SVG → 官方平台/品牌资源 → 成熟开源图标库原始 SVG”的顺序选择；GitHub 等品牌标志必须使用品牌方允许的官方资源。平台固定图形不默认自行绘制。
- 合集封面等平台运营素材先寻找许可兼容的现成矢量资源；确无合适素材时先制作候选预览并取得确认，再整理为页面外独立 SVG。禁止在业务页面内用 `CustomPainter`、Path、emoji、截图裁片或位图嵌入 SVG 近似替代。
- 建立两类资产清单：平台资产记录来源 URL、作者/项目、许可证、原始文件、最终 SVG、viewBox、显示尺寸、状态映射和消费组件；作者资产记录提交者、来源/原创声明、许可证或授权、文件哈希、审核状态和所属扩展。平台固定 SVG 接入前至少以 64×64 或实际显示尺寸预览核对。

## 3. 统一模型、目录与接口

核心类型：

- `ExtensionKind`: `skill | plugin | mcp`
- `ExtensionOrigin`: `curated | github | created`
- `ManifestFormat`: `agentSkill | agentPluginV1 | codexLegacy | claudeLegacy | mcpServerJson`
- `InstallState`: `notInstalled | checking | installing | installed | updateAvailable | blocked | error`
- `ScanStatus`: `pending | passed | blocked | revoked`
- `ExtensionAuthor`: `id, name, avatarUrl, bio, homepageUrl, verified`
- `ExtensionManifestV2`: 身份、作者、版本、来源提交、内容哈希、类型、组件、作者提交的产品图标、结构化详情区块、使用示例、素材来源/授权声明、兼容性、域名与凭据需求、hook 状态。
- `ExtensionDetailContent`: 作者可编辑的简介、适用内容、功能区块（标题、说明、配图、替代文本）和编号提示词示例；服务端按版本保存、校验并生成安全的只读发布快照，客户端只按固定模板渲染，不执行作者提交的 HTML 或脚本。

精选目录采用 Git 管理的 `registry/{skills,plugins,mcps}/{slug}/entry.json`，构建时生成确定性 catalog；运行时不依赖 GitHub 或 MCP Registry 实时可用。集合固定 5 个且可配置顺序；分类分别维护预览顺序与完整列表。

API 保持 `/v1` 路径，但整体契约升级并由客户端与服务端共享 `api_contract_version`：

- `GET /health`：状态、`release_id`、契约版本。
- `GET /v1/extensions/catalog`、`/catalog/{id}`：搜索、页签、筛选、分类与详情。
- `GET /v1/extensions/collections`、`/categories/{id}`：5 个合集和分类完整列表。
- `GET /v1/extensions/authors/{id}`、`/authors/{id}/works`：作者资料与作品。
- `POST /v1/extensions/inspections`、`GET /inspections/{id}`：GitHub 导入检查。
- `POST/GET/PATCH/DELETE /v1/extensions/installations`：安装、列表、启停、展示和卸载。
- `GET/POST /v1/extensions/installations/{id}/update`：检查与手动更新。
- `GET /v1/extensions/artifacts/{versionId}`：鉴权下载和哈希校验。

客户端正常请求前校验服务端契约；不匹配时停止受影响流程并同时显示客户端/服务端版本。消息中的能力引用统一携带 `extension_id`、`version_id`、可选 `component_id` 和 `kind`，旧 capability 写入格式在同一发布中迁移后停止使用。

## 4. 存储、导入、安全与运行

- 元数据迁入 SQLite；不可变包文件存入应用支持目录，安装采用临时目录检查、哈希验证、原子切换。现有技能、插件和草稿迁移为统一扩展记录，迁移校验成功前保留原数据备份。
- GitHub 导入仅接受公开仓库或子目录 URL，解析并固定到精确 commit；同仓库多扩展时让用户选择。检查 URL 与重定向、路径穿越、符号链接、设备文件、文件数、解压体积、压缩炸弹、嵌入密钥、清单和许可证元数据。
- npm 安装禁用生命周期脚本；PyPI 只接受可验证的固定版本安全制品。必须执行任意安装脚本才能工作的包在 V1 判定不兼容。通过扫描才允许安装，严重撤销项进入 `revoked` 并禁止执行，不提供用户绕过。
- 技能复用现有 skills middleware 与任务级 Docker 沙箱；Python、JavaScript、TypeScript 均只能在沙箱运行。远程 MCP 只允许 HTTPS，使用 `genkit_mcp` 按任务创建客户端并在结束/取消时关闭。本地 npm/PyPI/GitHub MCP 只在受限容器中启动，通过内部桥接连接，禁止在 Genkit 主进程执行第三方命令。
- 沙箱默认断网，只开放清单声明且通过审核的域名；保留 CPU、内存、进程数、超时、输出和取消限制。OAuth/API Key 仅在首次实际连接时通过安全界面获取，按租户加密保存，不进入模型上下文、日志或包文件。
- 更新只提示，不自动切换；新版本重新扫描，失败时继续使用当前版本。服务端提供技能、插件、远程 MCP、本地 MCP 的独立运行开关，以便事故隔离。

## 5. 实施阶段与验收

1. **视觉冻结**：从两张定稿生成 Layout Spec、平台界面图标候选表、作者内容区块规范和两类资产清单；补齐并确认作者页视觉稿。此阶段未通过不得开始页面正式编码。
2. **契约与迁移**：建立统一模型、作者/集合/分类数据、SQLite 与服务端迁移、发布 ID/契约握手；移除旧写入分支。
3. **目录与安装**：实现精选目录、搜索、分类、5 合集、GitHub 检查、原子安装、手动更新、撤销和作者作品查询。
4. **运行接入**：打通技能、插件组合组件、远程 MCP、本地沙箱 MCP、凭据连接、取消和运行开关。
5. **严格 UI 复刻**：按 Layout Spec 实现市场、详情和作者页；固定形状全部接入审核后的 SVG。不得在此阶段重新探索视觉方向。
6. **验证与部署**：完成自动化、视觉、服务健康和数据检查；涉及服务端/API 的改动通过检查后自动运行 `xiaoqi_harness/deploy/deploy_current.ps1`，失败自动回滚，只保留当前发布和一个非运行应急恢复点。

必须覆盖：

- 5 合集、5 圆点、无箭头、自动轮播暂停/恢复/减少动态效果。
- 三个类型页签、分类标题跳转、平板两列四行、手机一列、等宽卡片、作者头像、卡片与“＋”分离点击。
- 详情安装、作者跳转、GitHub 外链、作者可变说明与编号示例、长文本/缺头像/空作品；缺产品图标时应正确回退到对应类型的小七官方默认 SVG。作者主动提交的自定义素材缺少授权声明、格式不合格或安全扫描失败时必须阻止该素材发布并给出明确修复提示。
- 三类清单与旧清单归一化、hook 禁用、恶意压缩包、SSRF、密钥泄露、跨租户访问、撤销与更新失败回退。
- 三种技能脚本、远程 MCP、本地 MCP、超时、取消、网络限制和凭据脱敏。
- Widget 测试断言页面路由与加载区域不存在 `CircularProgressIndicator`；按钮任务进行中的小型进度反馈除外。

视觉验收必须使用冻结数据和同一 viewport：先在 1048×1501 画布或等比例标准化画布生成实际截图，再与定稿并排、50% 透明叠加和像素差异检查。逐项记录几何、文字、颜色、图标、阴影和状态偏差，最多两轮集中修正。没有同状态对比证据只能称“已按规格接入”，不能称“视觉复刻完成”。ARTEMIS 当前不可用时，设备级验证明确记录为“未执行验证，待用户真机验证”。

## 6. 外部参考与取舍

- 目录结构参考 [Cline Marketplace](https://github.com/cline/marketplace)，只借鉴 Git 管理目录与构建 catalog 的方式，不复制其内容。
- 包兼容基线采用 [Agent Plugins Specification 1.0](https://github.com/agentplugins/agent-plugins-spec/blob/main/spec/1.0.0.md)。
- MCP Registry 只作为发布时选源，服务运行不实时依赖其可用性；Claude/Codex 旧格式仅通过适配器归一化。
- Codex 插件市场录屏只作为“两列分类预览与标题查看更多”的交互参考；最终品牌、颜色、素材与组件必须严格还原小七定稿图。
