# 小七开发方案：让主要聊天统一使用 DSH

2026-10-06｜方案草案｜使用 Ponytail full 的精简原则

## 先看这一页

**目标：保留小七的阅读和笔记体验，把主要聊天交给 DSH，删除被替代的旧 AI 代码，减少维护负担。**

| 谁 | 做什么 |
|---|---|
| Flutter | 显示页面、发送问题、展示进度和结果 |
| 阿里云用户与数据服务 | 管理登录，保存需要上云的资料、任务和文件；现有本地书籍与笔记继续使用原存储 |
| 阿里云云函数中的 DSH | 在云端完成任务，手机锁屏后继续运行 |
| DeepSeek API | 提供模型回答和推理能力 |

你要得到的体验：**发起分析 → 可以锁屏 → 回来看到进度或结果 → 文件能保存 → 出错能重试 → 点击停止确实停止。**

### 开发分五步

1. **确定现在真正跑的是哪一版。**核对 App、云端服务和 DSH 版本，记录一个可恢复的旧版本。现在有一次云端 CSV 成功记录，但不能代替完整 App 验收。
2. **让主要聊天只走一条路。**发送、重新生成、继续回答都进入同一个云端任务入口；先接好，再移除这些入口原来直接请求模型的代码。
3. **把后台任务做完整。**接好资料读取、工具执行、文件保存、停止和重新打开恢复。锁屏或暂时断网不会自动重发同一任务。
4. **用真实操作验收。**分析资料、生成文件、锁屏回来、停止任务、断网重连都按同一套入口检查。失败项修好后再进入下一步。
5. **删除旧系统并交付。**删除旧 Agent 循环，以及已无人使用的聊天转发、分流和配置。交付时明确列出删了什么、少维护了什么。

**完成标准：主聊天只有一条执行路径；只维护 DSH 一套 Agent 循环；原有阅读和笔记可用；任务在云端完成并能取回结果。**

## 本次范围

本版先服务当前获准的个人账号，从现有首页进入。沿用已有首页、模型选择、附件、回复和文件保存界面，复用邮箱登录页。

需要覆盖的操作：发送消息、带资料提问、重新生成、继续回答、停止、重新进入、失败后再次发起、下载文件。DSH 接管现有四项任务工具：读资料、读技能资源、处理草稿、执行 Python。

**本版后置：**学习空间新功能、插件市场、手机内嵌 DSH、用户规模扩张，以及笔记分析/改写、会话标题等独立 AI 功能的全面迁移。这些独立功能暂时保留原实现；“只用一套 Agent”不等于这一版消灭所有直接模型请求。

不新增向量数据库，不更换云厂商，不重做阅读器，不迁移或删除历史书籍和笔记。模型列表不擅自缩水；现有模型/图片场景需要确认 DSH 能承接，否则属于阻塞项，不能偷偷删掉。

## 实现前要确定的用户行为

| 场景 | 本版拟定行为 |
|---|---|
| 没登录或登录过期 | 复用现有邮箱登录页；保留已输入文字和附件，登录回来由用户发送。取消登录返回原页面，不暗中切到旧聊天路线 |
| 等待、执行、完成 | 沿用现有反馈；进度与文件来自真实任务记录，不把模型说“完成”当成交付成功 |
| 锁屏、切换应用、断网 | 已提交任务在云端继续；回来查询原任务，不自动创建新任务 |
| 停止与重试 | 停止期间显示正在停止；确认执行和沙箱清理后结束。结果未知时先恢复查询，明确失败后才允许用户重新发起 |
| 文件与异常 | 文件可保存并再次取回；缺文件、权限不足、网络失败都有明确提示。页面进入使用静态占位，重要状态有文字和可访问标签 |

开发前按已有页面核对这些状态。若登录返回、继续回答或停止反馈需要改变，用 Product Design 展示受影响的交互并确认；已有布局不重新设计。本文不是对尚未展示的新交互的批准。

## 开发实现：尽量复用现有代码

**先保留现有两个云函数：一个接收请求，一个执行后台任务。**它们已有分工；本轮不为了少一个名字而改成新的常驻服务器。

- 云函数使用真正的异步任务执行 DSH，提交后返回任务编号。不能在普通请求中启动后台线程、提前返回就当作任务可靠运行。
- 沿用当前 DSH 官方运行时、连接方式和四项工具桥，不另建一个通用 Agent 框架。小七能力优先通过已有工具、配置和官方插件扩展；不改 Harness 核心。
- 沿用阿里云任务状态和文件存储。函数临时目录不承担长期保存；会话恢复所需数据和最终文件必须保存到持久存储。
- 模型凭证保留在服务端；任务、资料、工具和文件按账号校验权限。目标不接入 E2B 云服务；Python 如纳入本版，改用阿里云 FC 云沙箱。
- 全程沿用一个任务编号串联进度和结果。手机断连不终止云任务；停止必须同时处理 DSH 和阿里云沙箱，重复请求不能重复执行未知结果的操作。

平台已有的任务排队、执行状态和停止能力优先复用。小七仍需记录文件是否交付、账号归属和业务结果：云函数成功退出不代表用户已经拿到文件。平台状态不能直接替代全部产品记录。

### 代码修改与删除顺序

| 位置 | 处理方式 |
|---|---|
| `lib/pages/home_page.dart` | 汇合发送、重新生成、继续回答的任务入口，复用已有恢复与文件展示代码 |
| `lib/features/capabilities/data/capability_cloud_sync.dart` | 复用任务提交、查询、停止和下载；只补已确认缺口 |
| `xiaoqi_harness/capabilities/worker.py` 与 `harness_worker.py` | 先保住共用工具、任务和文件逻辑，完成接管后删除旧模型循环；不得直接删除整个 Worker 文件 |
| `xiaoqi_harness/capabilities/api.py` | 保留登录、任务和权限；全部所需场景接管后删除新旧运行时分流 |
| `lib/services/ai_service.dart` 与 `xiaoqi_harness/fc_proxy_function.py` | 逐个核对调用方；只删除已替代且无人调用的部分，保留笔记分析、改写和标题等本版后置能力需要的实现 |

不增加只有一种实现的通用适配层。共用代码只在删除旧循环确实需要时最小整理；不顺手重构整套目录。

## 怎么验收、怎么发布

验收重点共五组：

1. **主要对话：**发送、重新生成、继续回答均进入 DSH；现有模型及图片输入按支持范围逐项确认。
2. **资料和文件：**长资料按需分段读取；四项既有工具可用；生成文件真实存在、内容正确、能保存；只有代码文本时不能报文件交付成功。
3. **后台和恢复：**锁屏、切应用、断网、重开后找到原任务；服务进程中断后显示可信状态，不冒险重复执行结果未知的操作。
4. **停止和权限：**模型阶段、Python 阶段均能停止；沙箱释放失败可恢复处理；未授权账号不能取得任务和文件，日志不泄漏凭证。
5. **既有功能：**阅读、笔记、旧会话、历史文件仍可打开；状态提示可读、关键控件可操作；记录首字等待、任务耗时和运行成本，与修改前比较。

自动化检查优先使用项目已有测试和静态检查，只为真实风险补必要用例。需要编写移动端测试时，先按项目规范通过 ARTEMIS 探索真实交互；多设备时由用户选目标设备。用户自行验收的项目明确写“未执行验证，待用户真机验证”。

发布先限当前个人账号，确认 App、API、Worker 和运行时的发布版本一致。新任务固定执行版本；旧在途任务完成或明确取消后再移除旧循环。

回退使用上一套已记录的发布包和配置，不在同一个任务中切换执行引擎。保留原数据结构，必要字段只做兼容增加；不靠删数据恢复旧版本。旧代码从主分支退役后，恢复依靠版本记录和旧发布包，避免永久保留双套实现。

交付分别记录：代码完成、自动化/静态检查、受影响界面验收、真机验证、部署完成、云端实际有效。任何一项都不能代替另一项。

## 已知风险和处理

| 风险 | 处理 |
|---|---|
| 新版 DSH 或依赖不兼容 | 第一轮沿用锁定版本，不同时升级框架；新增插件必须匹配该版本 |
| 阿里云云沙箱账号或地域不可用，或现有 E2B 客户端无法直接连接 | 上线前先核实开通资格和 SDK 接法；若无法接通，本版暂缓 Python 执行工具，不引入 E2B 云服务作为替代 |
| 云函数启动慢、超时或包过大 | 先记录目标区域实测结果；超限时调整现有打包/运行参数。需要改部署方式时单独说明依据和成本 |
| 部分模型、图片仍依赖旧路径 | 先补接管并验收；无法承接时明确阻塞，不伪装迁移完成 |
| 取消或文件交付失败 | 保留真实状态和资源标识，可恢复清理与下载；不误报成功 |
| 删除共用代码伤及笔记功能 | 逐个核对调用方，先迁接再删除；保留历史数据并支持发布回退 |

### 已确认的登录交互

用户确认无登录态仍进入首页并可使用本地阅读/笔记；发送、重试或续写时打开现有邮箱登录页。登录成功返回未提交的原输入，由用户再次触发操作；取消返回原页并保留输入。主要聊天不得静默回退到直接模型请求。

现状核对已记录；下方进展记录覆盖“尚未改业务代码”的原计划状态。线上旧在途任务已核实清空，Worker 旧循环已删除。第 4 步仍待目标设备上的真实交互验收。

### 第 2 步：统一聊天

- 首页无需邮箱登录也能打开；登录页改为从首页压入的现有页面。发送、编辑后重发、重新生成、续写都先确认邮箱登录，用户取消时保留当前输入/编辑状态，登录成功返回后由用户再次触发。
- 发送、编辑后重发、重新生成、续写共用 `_runAgentTaskReply` 和现有 `/agent/tasks`、`watchTask` 流程；主聊天不再调用 `AiService.startChatReply`，不会静默回退到直连模型。
- 从 `AiService` 删除了已无调用方的流式直连聊天和首页附件摘要路径；标题、笔记分析与改写仍保留。

### 第 3 步：补齐后台任务

- 新任务只允许白名单账号并固定进入 `deepseek-harness`；不支持的模型会返回错误，不再按账号或图片类型静默分流到旧循环。
