## 已确认范围

面向小七用户，通过现有聊天与技能菜单创建、保存、使用技能，也能从公开 GitHub 仓库导入。支持纯指令以及带 Python、JavaScript、TypeScript 脚本的技能，不再以纯文本作为本版上限。用户不需要先选择编程语言，由技能需求决定实现方式。

私有仓库导入、用户创建 DSH 插件、插件市场后置。DSH 必要运行组件由产品统一配置，不作为用户安装流程。现有“本地保存原件、任务上传必要资料”的原则继续有效；跨设备云同步不因本次扩展自动加入。

成功标准：同一技能可创建或导入、真实试用、保存、重开后再次调用；支持三种脚本运行并交付真实文件；失败可解释、停止有效、不同账号不能读取或执行对方技能。导入成功与运行兼容是不同状态。

## 概念与兼容性

- 技能包以 SKILL.md 为入口，可含 scripts、references、assets。纯文本仍是有效技能；Python、JavaScript、TypeScript 是可选脚本语言，不是三套技能格式。
- Python 需要解释器与依赖环境；JavaScript 需要 Node.js；TypeScript 需要经过验证的执行或编译方案，不能仅凭 Node 已安装宣称全面兼容 TypeScript。
- DSH 的技能服务、文件系统技能来源和 skill 工具负责发现、加载；执行工具与隔离环境负责运行脚本。这些属于引擎组合配置。导入一个技能包不等于安装一个拥有宿主权限的 DSH 插件。
- 三种语言可运行，不代表所有 GitHub 技能兼容。依赖 Claude 专用工具、浏览器、系统软件、外部凭证或额外服务的技能需显示具体缺项。不能静默删除脚本或冒充纯文本运行成功。

## 实现前已核实的差距

1. `harness_worker.py` 的 `_DISABLED_TOOLS` 包含 tool-skill、tool-bash、tool-pwsh、tool-fs 等。不能直接全量解除禁用；先确定 Docker 加额外沙箱的执行路径与受控工具映射，不以多用户容器建设为前置。
2. 当前 Dockerfile 已包含 Node 和 Python，用于服务自身。共享应用容器不能直接充当第三方技能脚本的执行环境。
3. SkillCreatorAdapter 仍按旧方案只生成 Python；草稿资源、运行状态和保存入口也需核对三语言及完整技能包支持，不能仅修改提示词。
4. 本地技能存储、后台目录发现和云同步逻辑需按新范围核查账号归属、版本及本地原件；旧云同步行为不能未经确认带回本版。
5. 多用户容器隔离及其完整验收后置；Docker 加额外沙箱的脚本执行边界必须验证后才能开放脚本运行，两者分别记录。

## 技术研究结论与待落实方案

优先使用锁定 DSH 的官方技能组件及现有任务桥，不修改引擎核心。具体 Profile 组合以部署版本的配置检查为准；不为每种语言单独寻找所谓“语言插件”。只有现有接口不能承载受控执行时，才评估最小自定义工具适配。

拟议执行环境：开发阶段采用 Docker 加额外沙箱，按任务建立工作目录，只提供当前技能版本及授权输入；Python 与 Node/TypeScript 运行环境和依赖锁定。具体额外沙箱实现尚未选定或验证，不把 DSH 文件策略自动等同该要求。依赖安装在沙箱准备阶段进行，安装失败不得改动现有可用版本；安装脚本也属于代码执行，不能在导入下载阶段运行。依赖缓存、网络允许范围、版本组合与资源阈值需按现有 ECS 容量确定并验证。

公开 GitHub 导入由受控下载流程完成，固定 commit 与文件清单，记录来源、许可证和哈希；检查路径越界、符号链接、文件数、大小与压缩膨胀。不执行仓库的安装钩子，不把仓库里的 DSH Profile、MCP 配置或插件清单自动变成系统配置。网络下载需限制目标与重定向，不能允许任意内部地址。

本地保存完整技能包及不可变版本；单一 SKILL.md 旧记录需兼容读取。执行时上传对应版本和授权输入，账号由可信登录会话决定。任务结束的临时清理不能删除手机上的技能原件或已保存结果。正式数据结构、迁移、容量、API 和回滚设计在交互确认后确定。

DSH 文件沙箱不统一限制网络与进程可见性；本版实现脚本沙箱所需的网络边界、密钥分离、运行资源限制和取消清理。多用户独立容器、每用户配额和用户间故障隔离后置。不可把 DSH 内置文件沙箱或仅安装 Docker 等同额外沙箱已完成。

回退原则：可单独关闭脚本执行，保留技能原件与历史结果；受影响技能明确显示暂不可运行，不改写为已成功。保留上一可用运行镜像与技能版本，升级不改变在途任务版本。新功能未通过验收前不对外开放。
