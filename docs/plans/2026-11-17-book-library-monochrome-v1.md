## 1. 目标、范围和成功标准

目标用户：现有 Android 手机／平板用户。痛点：书库及相关弹窗的绿色、米色和装饰与全局黑白简约风格不一致，入口和操作层级不够统一。

核心闭环：进入书库 → 搜索／筛选或新建 → 扫描／输入 ISBN 或导入 PDF／EPUB → 确认资料并保存 → 查看详情 → 编辑资料／分类／封面或写笔记 → 返回原书库位置。两个新建入口保留各自后续的书籍与任务关联行为。

成功标准：

- 范围内界面统一为白底、黑灰文字与线性图标；原始书封、照片保留原色，删除保留错误红。
- 用户已确认的入口、菜单、空态、扫码暂停与键盘行为全部可用，原有功能和真实计数保留。
- 详情退出恢复书库搜索、筛选、排序、展示方式和滚动位置；不丢分类、封面、资料、笔记和任务关联。
- 两个共用入口实际消费同一组件；固定图形交付独立 SVG，经预览登记后接入。
- 同状态视觉比较和用户真机验收分别留证据；概念图或编译通过不能代替实际效果验收。

本版本包含：书库首页及网格／列表、搜索分类排序、多选管理、共用添加与导入面板、ISBN 扫描与输入、资料确认、书籍详情、编辑分类、封面弹窗、相关管理／确认／失败浮层，以及底部“笔记”图标复用。

明确不做：阅读器、独立“笔记”页面与编辑器外观、聊天主界面重设计、OCR／识别服务重写、Agent 执行链、云同步、微信读书真实授权／关联／同步、封面模板／AI 封面／裁剪功能、数据库结构和服务端 API 改版。不得借本轮新增类似工具或依赖。

冻结交互：

- 详情“…”只含“编辑／关联微信读书／删除”，在按钮下方轻量下拉；不做底部菜单，不出现深色整页遮罩。点外部只关闭菜单、不穿透操作背景；系统返回先关菜单。
- 分类并入编辑，最多 3 个，随资料统一保存。取消关闭不提交草稿。书库的独立分类管理能力继续保留。
- 进入详情隐藏导航及占位，返回后恢复。分享、本书资料、简介全文、真实统计与已有笔记入口保留。
- 封面为居中轻量弹窗：标题与关闭、竖向预览、并排“恢复原书封面／上传封面”。上传后选择相册或拍摄；没有模板、AI、重复照片入口或“应用此封面”。
- 恢复／选图成功即返回调用方；详情调用由详情保存，编辑／新建调用仅更新表单草稿，随父表单保存。取消系统选图／拍摄不修改封面。没有可恢复原封面时禁用恢复并解释原因。
- 手动输入时扫描真实停止；只有关闭输入面板后才恢复扫描，不能因单独收键盘就恢复。提交查询继续暂停；重复扫码和重复提交受互斥保护。
- 详情笔记空态保留现有文字提示和原点击行为；本轮不改空态视觉、引导或笔记创建流程。
- 全局输入焦点规则与无转圈路由规则适用；状态提示复用 `AppToast`，有撤销动作的提示保留足够操作时间。

## 7. 风险、降级、回滚与后置项

- 主题共享泄漏：先盘点消费者，只更新授权范围；不得为了全局换色影响阅读器／独立笔记页面。

- Android 选图过程中 Activity 回收：按锁定插件支持核对 lost-data 处理与书籍归属，恢复结果不能误写另一书籍；未验证不声称可恢复。
- 分类与资料分开写入：在现有本地服务补最小事务入口，保留旧模型和表；失败不允许部分保存。
- 历史模板与图片：仅停止新模板供给，保留历史引用和必要渲染；没有迁移需求，不批量重写现有书籍。
- 返回书库重建状态：不要只保留滚动位置而丢搜索／筛选；明确由现有页面 state 或现有偏好承接，避免引入第二份冲突状态。
- 回滚以本次独立代码 diff 恢复，不回滚用户数据库、图片和笔记；不存在数据库迁移。不得使用整个工作区 reset 覆盖其他任务。
- 后置：微信读书真实关联、封面 AI／模板、阅读器、独立笔记页改版、识别服务优化均不阻塞本版本，也不在实施时悄悄加入。

## 10. 列表模式工具行对齐修复（2026-11-18）

| 问题 | 根因与修复 |
| --- | --- |
| 列表态工具行收缩居中 | 工具行是 `Wrap(alignment: spaceBetween)`；`RenderWrap` 只在拿到紧宽度时才铺满并分配剩余空间。列表模式外层 `Column` 默认 `crossAxisAlignment.center`，给子项的是松约束，Wrap 收缩到内容宽度后又被居中。修复：列表与空态两个 `Column` 改为 `CrossAxisAlignment.stretch`。网格模式由 Sliver 给紧约束，原本不受影响，两种展示方式现在一致。 |
| 同一操作组图标不成系列 | 筛选图标用 `inkSecondary`，排序与多选是 `ink`；大小 22／24／24 不一致。统一为 `ink` 与 22dp，保留 48dp 触控盒和筛选激活圆点。 |
