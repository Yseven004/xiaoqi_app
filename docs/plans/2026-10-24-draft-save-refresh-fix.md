## 实施结果（2026-10-25）

- 草稿先写本机，再异步同步；同一草稿的上传串行化，旧响应不能降低已知 revision 或覆盖更新内容。冲突、远端删除和网络问题分别保存为本机状态，坏草稿不会中断已安装技能列表刷新或其他草稿同步。
- 技能列表改为先显示本机数据，再独立读取云端；技能、插件目录、连接和发布列表各自合并请求并短时缓存。刷新失效会丢弃旧请求的缓存归属，安装／删除操作使用服务端已返回的变更记录，不额外等待一次全表刷新。
- 创建弹窗与两步创建页使用选定的底部状态带。保存成功不再叠加短暂 toast；冲突收敛为一个“处理同步”入口，发布在冲突期间禁用。关闭时会检查两步中尚未保存的修改。
- 只复用现有 API 和 revision 规则；没有服务端、部署文件或 API 契约变更，无数据库迁移。
