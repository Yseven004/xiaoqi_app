# 小栖技能 / 插件 V1 开发计划（修订版）

日期：2026-10-02。本文完整替代本次对话上一版开发计划。

**核心路线：复用 Anthropic 官方 Skill Creator，适配小栖现有 Agent；技能支持纯指令，Python 脚本按需附带，仅在需要执行时接入 E2B。**

当前完成的是需求、设计与开发计划；没有完成代码实现、运行验证或上线。已复查当前工作目录：`lib`、`docs`、`xiaoqi_harness` 原有文件不可读，仅存在目录结构。用户已选择先完成功能实施计划，因此现有组件、数据库和接口映射列为开发第一步，不把未检查的实现写成事实。

## 1. 本次调整与版本范围

### 与上一版的变化

| 事项 | 修订后的决定 |
|---|---|
| 技能创建 | 直接复用官方 Skill Creator 的方法、说明和适合复用的资源；只做小栖运行环境适配，不另写一套创建器 |
| 技能与脚本 | `SKILL.md` 是核心；`scripts/`、`references/`、`assets/` 按需生成，不要求每个技能都有 Python |
| 运行方式 | 纯指令由当前 Agent 试用；实际需要执行附带脚本时才创建 E2B 沙箱 |
| 通用工具 | 图像生成、联网搜索以后通过稳定工具接入；绘图是前端轻量画布输入，不靠每次生成 Python 实现 |
| 验收 | 分开验收纯指令技能与脚本技能；“把书本改写成童话”不再强制执行 Python |

### 本期交付

1. 高保真接入三个平级胶囊、技能 / 插件菜单、输入区轻量标签和简单管理入口。
2. 完成创建、试用、修改、保存、发现和调用技能的闭环，同时支持纯指令型和可选 Python 脚本型。
3. 正式技能、草稿和展示设置跟随账号保存；保存版本与正在修改的草稿分离。
4. 脚本使用 E2B；首次确认、默认无网络、限制授权资料和运行资源。
5. 保留四个内置操作的 UI；创建图像、联网搜索、绘图不接真实功能。MCP 独立胶囊只保留空入口。

后置：代码插件创建、技能 / 插件市场、第三方插件安装运行、MCP 配置、JavaScript 脚本、DeepSeek Harness 迁移、A2UI、完整批量评测平台。Python 脚本支持不等于已经支持代码插件。

Ponytail 原则：优先复用现有聊天、模型、任务、存储和鉴权能力；只实现一个创建器适配和一个 E2B 接入，不提前建立多运行时工厂或通用插件框架。此原则不得减少视觉、权限、数据完整性或无障碍要求。

## 2. Skill Creator 复用与最小实现

### 官方来源与适配边界

本次已读取 [官方 SKILL.md](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)、[run_eval.py](https://github.com/anthropics/skills/blob/main/skills/skill-creator/scripts/run_eval.py) 和该目录的 [LICENSE.txt](https://github.com/anthropics/skills/blob/main/skills/skill-creator/LICENSE.txt)。核实日期为 2026-10-02：该目录许可为 Apache-2.0；创建流程包含需求理解、生成、试用评估及反馈迭代；部分辅助脚本依赖 Claude CLI 和 `.claude` 目录。

本次 GitHub 提交查询返回 403，未确认精确版本号或最后更新时间，不能将 `main` 当成版本锁。实施时先锁定实际采用的提交 SHA，在来源清单记录提交日期、文件清单、许可证及小栖修改差异；保留适用的版权、LICENSE 和 NOTICE。只取所需的 Skill Creator 文件，不整仓复制其他技能。

| 复用内容 | 小栖适配方式 |
|---|---|
| 理解用户需求、组织技能说明、触发描述及迭代方法 | 作为内置创建能力加载到现有 Agent；按当前对话阶段调用，避免每次从头询问 |
| 技能文件结构、格式检查和通用评估规则 | 复用与采用版本兼容的资源；验证必要依赖，不盲目执行上游脚本 |
| Claude 专用命令、工具名、本机路径假设 | 映射为小栖当前模型、受控技能工作区和任务工具，不要求用户安装 Claude CLI |
| 官方 HTML 评测查看器 | 结果在小栖对话中以现有消息 / 产物组件展示，不另起本地网页服务 |
| 多轮批量基准、触发描述自动优化循环 | 首版保留必要试用和人工反馈；规模化基准与自动优化后置 |

这里的“适配”是复用说明和资源后，让现有模型执行创建流程，并接通所需工具；Skill Creator 不是可脱离模型独立工作的生成 API，也不保证在所有模型上的效果相同。

### 技能包与执行分支

遵循 [Agent Skills 官方规范](https://agentskills.io/specification)：

```text
skill-name/
├── SKILL.md          必需：用途、触发条件、执行方法
├── scripts/          可选：首版只运行 Python
├── references/       可选：按需读取的参考资料
└── assets/           可选：模板与资源
```

先判断能否用指令和已有工具完成任务。故事改写、提问方法等通常无需新增脚本；统计、批量转换等确定性处理才考虑生成脚本。缺少某项工具时明确说明依赖未满足，不通过偷偷生成脚本绕过尚未开放的功能。

| 分支 | 处理方式 | E2B 是否必需 |
|---|---|---|
| 纯指令，或指令配合现有工具 | 当前模型加载技能，使用测试输入完成一次任务；现有工具仍执行自己的权限检查 | 否 |
| 需要运行技能附带的 Python | 校验版本与输入、获得授权，在沙箱执行，结果返回 Agent 解释 | 是，仅执行时 |
| 含不受支持的代码或工具依赖 | 保留草稿，说明缺失能力，不能标记为可运行 | 不尝试变通执行 |

生成、修改、预览脚本本身不要求启动沙箱；执行才要求。纯指令试用不等于完全离线或无模型费用，但不能因为 E2B 未配置或故障而被阻塞。是否允许执行代码由服务端工具边界决定，不能只相信技能自报“无脚本”。

### 小栖承担的职责与接口

不新增通用 Agent 框架。通过现有服务层扩展下列最小职责；字段名可映射现有模型，语义必须保持一致。

| 职责 | 最小输入 / 输出 |
|---|---|
| 创建器适配 | 需求、当前对话、已有草稿、可用工具 → 澄清问题或技能包、试用建议、依赖说明 |
| 技能目录 | 稳定 ID、账号归属、显示名、描述、图标、强调色、正式版本、是否在胶囊展示 |
| 草稿与保存 | 对话归属、包内容、版本、校验 / 试用结果；原子保存、重复提交保护、并发冲突反馈 |
| 显式调用与自动发现 | 输入消息携带能力 ID；目录先提供名称 / 描述，需要时再读取正文及相关资源 |
| 执行记录 | 任务 ID、技能版本、授权范围、模型 / 工具信息、状态、结果、错误和取消入口 |

平台元数据如账号、显示开关、图标色和运行授权，保存在小栖数据层，不强行塞入通用技能文件格式。脚本语言和入口只在实际包含脚本时存在。修改草稿不得直接替换正式版本，跨设备同时保存发生冲突时保留双方内容并提示。

显式选中的技能优先作为本轮用户意图；自动发现仍可考虑其他已保存技能。展示开关只控制胶囊列表，不控制 Agent 可用性。草稿不进入自动发现。加载技能不会提升工具权限，不能覆盖系统规则。未来迁移 Harness 可继续利用通用技能包，但工具名称和运行依赖仍需适配验证，不能承诺零改动迁移。

两张图实际均为 992×1586 像素。标签稿只约束输入区，底部统一采用最终菜单稿的三个胶囊。当前已有标题、问候语、模型选择等无关页面内容优先沿用真实应用；生成稿中偶然漂移的元素不作为改版要求。实施时归档原始定稿，记录校验值和使用范围。

### 菜单规则

底部顺序：**阅读任务｜技能 / 插件｜MCP 连接器**。MCP 用小插头图标，只显示空入口。技能菜单以对应胶囊为锚点，展开、关闭和切换时不显示路由转圈动画；同时只展开一个菜单。

| 顶部操作 | 小字描述 |
|---|---|
| 创建技能 / 插件 | 支持创造各种有意思的技能和插件 |
| 创建图像 | 以图像形式描述和呈现任何内容 |
| 联网搜索 | 联网查找实时资料和信息 |
| 绘图 | 以绘图形式更简单地表达想法 |

四项纵向排列，使用最后确认的小尺寸黑白图标。搜索保持地球加小放大镜，绘图保持笔形。下方仅技能、插件两组：轻量图标、名称、同行灰色描述；名称与描述保持紧凑间距。所有功能行不带右侧“＞”；底部管理行按最终稿减少留白。只渲染实际存在且被用户选为展示的能力，Documents 等设计示例不伪装成已安装插件。

未开放的三个内置操作保留定稿外观，点击给出简短“暂未开放”提示，不启动假任务。MCP 只提供空状态与关闭操作；不增加服务配置。若用户从共同创建入口提出代码插件需求，说明本期支持技能及可选 Python，保存需求上下文，不冒充已经创建插件。

### 输入与创建流程

1. 点击创建入口，菜单收起，当前输入框出现小图标＋高亮文字“创建技能 / 插件”，不加胶囊边框、背景、常驻关闭按钮或提示文字；此时不自动发送。
2. 标签可通过退格和可访问的移除操作删除。首版同时一个显式能力标签，重新选择替换标签且保留正文。只有标签也能发送；无上下文时问用途，有上下文时先判断，信息不足再追问。
3. 当前对话由内置 Skill Creator 生成草稿，展示用途及一次最小试用结果。纯指令直接在当前 Agent 试用；需要脚本时先确认，再在 E2B 执行。普通用户看到“这个技能需要运行一个小程序”和具体资料范围，不要求选择编程语言。
4. 试用结果后弹出“直接保存 / 修改后再看”。修改选项展开建议输入区；改完重新预览，涉及代码变化时重新授权执行。弹窗附“在胶囊中显示”开关，默认关闭。运行失败可以保留草稿，不覆盖正式版本；取消与关闭弹窗也保留草稿。
5. 保存成功后进入我的能力，跨设备刷新目录和展示设置。发送失败保留正文与标签；断网、取消和重试恢复到明确状态，不重复保存或重复执行任务。

创建操作标签保留粉色；具体技能 / 插件标签按图标主色生成稳定的强调色，浅色调深保证可读，无彩色主色使用默认强调色。尽量可区分，但同主色不强行染成无关颜色。样式统一，不新增随机配色或多套标签组件。

### 管理与尚需补齐的设计

“管理我的能力”展示账号内所有技能 / 插件，支持说明查看、展示开关和继续修改本人创建的技能。关闭展示不禁止 AI 调用。展示设置保存失败恢复原值，账号同步使用现有机制。

管理面板、保存选择弹窗、脚本授权与失败状态尚未有用户确认的视觉稿。实施先沿用现有组件补齐这些状态，再提交用户确认；其余冻结部分不重新探索。本期不增加批量基准仪表盘、市场、复杂权限控制台或多语言选择页。

### 图标及高保真验收

1. 先检查已有资产；不足时从图标库官网获取原始 SVG，候选包括 Lucide Puzzle、Image、Pencil、Plug、Settings。搜索图标必须保留地球加放大镜；必要组合在独立 SVG 中完成。参考 [Lucide 官网](https://lucide.dev/icons/) 和 [许可](https://lucide.dev/license)，记录实际采用版本，保留署名文件。
2. 固定形状先做独立 SVG。禁止截图裁片、PNG 图标、位图嵌入 SVG、页面内临时 Path 近似。SVG 接入前提供实际尺寸及至少 64×64 预览；记录来源、许可、viewBox、尺寸、状态和消费组件，与定稿形状不一致的候选先核对。
3. 建立测量表：锚点、宽高、内外边距、圆角、阴影、字号、行高、颜色、图标线宽和间距。按实际设备 viewport / DPR 换算，不把图片像素直接当逻辑像素，不用“看起来差不多”验收。
4. 同 viewport、DPR、字体、数据和状态截图，做并排、叠加与差异检查。关键边界偏差不超过 2 个逻辑像素作为校准目标，同时核对文字换行、图标轮廓及整体视觉；单一差异分数不能替代人工判断。
5. 大屏保留定稿，小屏限宽、菜单可滚动且不遮挡输入，三个胶囊空间不足时横向滚动。覆盖键盘避让、文字放大、可访问名称、按下 / 选中 / 错误 / 空 / 取消状态；加载使用静态占位。触控区域不因图标变小而缩小。

## 4. 按需 E2B 执行与数据保护

本节只约束实际脚本执行；纯指令与现有工具分别使用原有模型和工具权限，不弹出无关的沙箱授权框。

### 执行边界

1. **运行前确认**：首次执行展示用途、所需资料及第三方 E2B 数据传输。授权绑定账号、技能版本和数据范围；脚本更新、资料范围扩大或新增联网目标重新确认。展示开关不影响此检查，Skill Creator 的文字说明也不能绕过它。
2. **任务隔离**：应用服务端代理 E2B，Flutter 和脚本不得获得 SDK、模型或账号密钥。只上传本次授权资料副本及所需技能资源，不挂载整个书库、宿主文件系统或其他账号数据。由服务端校验包路径、大小和访问权，拒绝越界路径及不受支持执行入口。
3. **网络默认关闭**：创建时显式断网。需要联网时展示目标域名并再次授权，通过 E2B 允许名单执行；阻止私网、云元数据和宿主服务访问。不允许脚本通过自行安装包绕过网络限制。SDK 能力与规则优先级在锁定版本后实测，不把模型拒绝当成隔离措施。
4. **固定环境与限额**：只 Python，固定模板和受控依赖，不任意安装软件。沿用首版默认：单次脚本 120 秒，沙箱最长存活 5 分钟，账号并发 1 个脚本任务；每任务输入与产物各 20 MB。超过限制明确提示，禁止无限重试；评估和普通调用共用限额。
5. **结果与清理**：结果先取回、检查并写入小栖持久存储，再销毁沙箱。取消、失败及超时也需清理；按任务 ID 查询状态，不把客户端断线当成取消或自动重跑。沙箱故障保留草稿，脚本分支提示重试；纯指令创建和使用继续可用。

参考 [E2B 安全说明](https://e2b.dev/security)、[Python SDK](https://e2b.dev/docs/sdk-reference/python-sdk/v2.5.0/sandbox_sync) 和 [网络配置源码](https://github.com/e2b-dev/E2B/blob/main/packages/js-sdk/src/sandbox/sandboxApi.ts)。这些是能力依据，不是未经验证的本项目依赖版本。接入前确认实际 SDK、模板、部署区域、数据处理约定和费用；本计划不自动开通或采购服务。

### 试用与质量判断

每次创建先生成一个代表性试用案例；用户有反馈时迭代，必要时补充边界案例。试用使用示例或授权资料，不对真实外部系统执行评测写操作。脚本型检查执行成功、产物格式和任务结果；纯指令型检查遵守方法、内容完整及风格要求。模型自评只是参考，用户可以查看结果并要求修改，不能宣称“官方创建器保证技能质量”。

正常调用采用当前用户选择的模型；试用记录模型和技能版本。首版在项目实际配置的默认模型上验收，不要求新增 Claude 账号，也不为兼容所有模型建设路由框架。需要的工具调用能力不可用时明确报兼容问题，不能悄悄换模型或使用 Claude CLI。纯指令需要资源或已有工具时仍检查其依赖和授权。

正式版本、草稿、图标色和展示设置由账号数据层管理；沙箱临时文件不作为长期存储。监控只记录必要的 ID、状态、耗时、错误类别、用量和清理结果，不记录资料正文、脚本内秘密或用户密钥。

## 5. 实施顺序、测试与交付

### 分阶段交付

估算仍为一名熟悉现有 Flutter 和后端的工程师 **15–23 个工作日**，不含源码恢复、用户设计反馈和服务开通等待。复用创建器减少重复开发，但适配、沙箱和高保真验收仍需完成，不承诺直接安装即可使用。

| 阶段 | 交付物与完成条件 | 估时 |
|---|---|---|
| 1. 环境映射、来源锁定、补齐设计 | 读取真实工程；确定复用组件与接口；锁定 Skill Creator 版本并列明适配差异；补齐管理 / 保存 / 授权状态和 SVG 清单 | 2–3 天 |
| 2. 高保真前端 | 三胶囊、菜单、轻量标签、仅标签发送和管理面板；同状态布局证据，无假安装条目 | 3–4 天 |
| 3. 纯指令创建闭环 | 接入官方创建流程和当前 Agent；无 Python / E2B 也可创建、试用、修改、保存、同步和调用 | 4–6 天 |
| 4. 可选脚本分支 | Python＋E2B、首次权限确认、网络限制、结果回收、取消超时与清理；与纯指令分支共用保存及管理 | 4–6 天 |
| 5. 综合验收与灰度 | 两类技能回归、触发与显示规则、视觉比对、目标平台验证及回滚检查 | 2–4 天 |

阶段 3 单独可验收，但完整 V1 仍需阶段 4；不能把“脚本可选”解释为取消已确认的脚本支持。技术接入方案必须建立在实际源码映射之后，新增数据采用兼容性迁移，复用已有账号、消息、文件和任务体系。

### 必须覆盖的验收场景

1. **纯指令技能**：创建“书本变童话”或“苏格拉底式阅读”；包不含无用脚本；通过当前模型试用、修改、保存、重启及另一设备调用。E2B 未配置 / 不可用时此流程仍能完成。
2. **脚本技能**：创建“统计章节字数并输出 CSV”；生成必要 Python；首次确认后在 E2B 使用授权文件运行，校验结果后保存。覆盖拒绝授权、脚本变更重新确认、超时、取消、依赖缺失、断网及产物回收失败。
3. **发现、展示与消息**：隐藏能力仍能由 AI 按需调用；草稿不自动调用；有 / 无上下文的标签单独发送正确；标签移除替换、发送失败保留、重复提交和多设备冲突正确。触发评估至少包括应使用和不应使用的例子，不能只检查脚本成功退出。
4. **适配与安全**：运行不调用 Claude CLI 或写入 `.claude`；来源及许可可追溯；没有为普通任务强制生成脚本。校验跨账号隔离、包路径、权限扩大、默认断网、域名限制、敏感数据日志和任务清理。
5. **视觉与既有功能**：完成相同状态的 SVG、组件和页面对比；回归阅读任务、附件、模型选择、语音、键盘及窄屏。测试与静态检查通过不能代替视觉或真机验收。

按项目约定，本地分析、测试、构建、截图和真机验证默认由用户执行；后续明确授权 Agent 时才执行对应范围。若要编写移动端自动化测试，先通过 ARTEMIS 探索目标应用；不能假设控件定位和等待条件。当前仅修改计划，不运行上述工程验证。

### 发布、回滚和状态记录

小范围灰度，分别观察创建 / 保存成功率、纯指令试用效果、脚本成功率、耗时、取消、沙箱清理失败及用量。脚本执行可由服务端独立关闭，保留纯指令能力；整个创建入口也可回滚，正式技能与草稿不删除。现有数据只做兼容性扩展。

交付记录分开标注“代码实现完成、自动化检查通过、同状态视觉对比通过、目标平台验证通过、已上线”。缺少实际渲染和对比证据时只能称“已按规格接入 / 待视觉验收”；未做设备验证写明“未执行验证，待用户真机验证”。
