# 主界面与伴读注释改版最终方案

2026-11-25。产品与交互以 [设计定稿及确认图](../design/annotation-refresh-2026-11-25.md) 为验收依据。代码基线为 `594fbbe`，本文件给出实施顺序、复用边界和发布门槛。

## 版本范围

- 主界面面向下一轮 AI 提问。每条文字注释可附至多三张解释图，可以只附图。有图时缩略图排在同一输入框内的文字下方。箭头收进待发队列并显示编号，点编号编辑，聊天主输入框发出整批。成功后从聊天记录回看，附件失败保留待发批次。
- 伴读面向私密阅读记录。文字、现场录音和图片任选其一即可保存。同一选区再次编辑原注释，不同选区各自存储。正文用淡叶绿细虚线，点击先查看，铅笔进入编辑，右上角「取消」。详情随内容收高，文字和录音同区混排，图片在下方。详情和编辑都可打开无尖角的可见范围菜单，本版启用「私密」，社区三项显示暂未开放。
- 两处编辑框贴键盘，遵循全局焦点规则。**引文在编辑和回看面板中固定一行，超出部分隐藏**。点引文可单独读完整摘录，原文跳转另外判断。笔记库副本也保存完整引文。「本书注释」位于目录面板，同一份资料的 PDF、电子书及译文共用注释。
- 伴读先存本机，联网后同步同账号设备。两端均编辑时按最后编辑的一版。书内注释从新版创建起形成原位记录。主动「加入笔记库」才创建本书笔记的独立副本，保留当时完整引文和媒体。
- 聊天当前输入区总计九个附件，解释图计入总数。单条伴读注释可在「本书注释」列表长按删除，二次确认后生效。删书时整本的书内注释随书删除，手动加入笔记库的副本继续保留。书架现有软删除、恢复方法及导入限制见下文。

## 主界面实现

1. 复用 [聊天注释定位和编号](../../lib/widgets/chat_annotation_controls.dart)、[聊天发送与草稿入口](../../lib/pages/home_page.dart) 和 [附件准备器](../../lib/services/home_chat_attachment_preparer.dart)。文字注释进入同一轻量编辑器，选择图片时把文件移入现有聊天附件持久目录。原模型中的 `attachmentId` 继续指被注释的图片目标。文字注释新增有序解释图 ID 集，索引到同一套聊天附件记录。按 ID 绑定和移除，文件名只用于展示。现有图片点位走原编辑流程。
2. 在同一账号和会话内持久保存待发注释、批次编号、主输入文字与附件关系。提交前冻结发送内容和消息、任务、尝试标识。已发送历史可读且原任务确认该批已接收并可继续时，才清除对应待发编号。已验证读图并进入澄清、等待用户或主动暂停的回合从原任务继续。明确的配图失败恢复整个批次，包括原编号，之后新增的草稿另行保留。回执丢失先对账原任务、快照及外部操作回执。历史写入与草稿清理需可中断后重放，客户端重启、切会话或重复点击都只呈现一条已发送消息。
3. 修正 [草稿恢复与附件删除](../../lib/pages/home_page.dart) 中按评论非空过滤和直接删文件的路径。解释图或有效评论任一存在即可保存、恢复和发送。旧格式缺解释图字段时按空列表读取。编辑取消只释放本次新增且再无引用的文件，替换、移除或清空待发条目时保护其他草稿和历史的原图。用户换图或更改图片所属注释后，属于新内容。把稳定注释 ID、顺序、图片归属及内容标识纳入[原有消息尝试指纹](../../xiaoqi_harness/genkit_server/lib/src/api.dart)，沿现有编辑、分支与幂等机制提交。
4. 每条至多三图，本轮输入附件合计至多九个，模型输入还受服务端 5 MiB 图片字节预算约束。普通 JPEG/PNG 当前按原文件上传，现有准备器主要对 HEIC/HEIF 转码。原图留给本机历史，另为本轮准备发送图，按实际字节总量预检。用带细字的截图验证缩图后的信息仍可读。合理缩图后仍超限时提示调整配图并保留整批。服务端对实际投递的媒体执行相同的字节限制。
5. 将本轮视觉内容与当前工作可查的历史资料清单分开。每张解释图按稳定 ID 紧跟所属注释的引文和评论投递，普通附件保留原用途。已分组图片不再从材料末尾重复追加。历史查阅仍受原授权范围限制，旧图过期不应阻塞无关的新一批注释。客户端判断是否新开工作、服务端判断图片用途时，使用用户主输入、手写评论及显式能力选择。引文和图中文字作为参考材料。遇到结构化准备或供应商视觉错误时，已知具体图片就指出编号，只有批级错误时说明整批。模型正常询问图片用途时由用户在本轮回答。
6. 现有聊天附件读取 `AttachmentService.imagePart(tenant,id)` 按租户索引，邮箱会话使用共享的 `personal` 键。本轮解释图上传、解析、取图和重试一律验证当前身份对该附件及本轮消息的授权，客户端提供的材料清单只能描述关系。新图需要可验证的所有者或授权关联，所有能读到它的入口执行同一检查。旧本机草稿以原图重新准备新授权。用隔离账号夹具验证错误账号无法通过已知 ID、其他消息或普通附件读取路径访问该图。

## 伴读实现

### 本机保存与来源定位

1. 替换 [伴读选区保存入口](../../lib/widgets/reading_companion.dart) 的自动入笔记逻辑。新增伴读记录持有稳定注释 ID、书籍关联、资料版本、选区、完整引文、内容和修订标识。文字与按录制顺序排列的现场录音在同一内容区，图片按选择顺序显示在下方。按账号、书籍关联、资料版本和规范化选区约束一条活跃注释。两端离线为相同选区新建时合并到一个稳定 ID，待上传操作和媒体关系跟随归并结果。旧 `companion_note_sources` 仍服务既有笔记，升级不回填虚线或同步旧记录。现有 [数据库](../../lib/services/database_service.dart) 采用增量迁移，本机注释与待同步操作同事务提交。
2. 原资料版本内以稳定来源坐标为主，保存起点、终点、精确引文和上下文。导航用的 `ReaderAnchor` 仍负责跳转，注释持有半开选区。PDF 原页保存 `pdfrx` 字符范围与分页面跨度，从按序端点处理正向、反向和跨页选择。原生 EPUB 复用章节、文段 ID 和 UTF-16 位置，利用 `ReaderBlockSlice` 把位置投影到重分页后的文字。
3. [PDF 重排](../../lib/services/companion_pdf_reflow.dart) 已能在合并块和原块间转换位置，需要把提取阶段的原页字符跨度、OCR 行来源保留到切片和合并结果。PDF 选区以阅读器已有的有序端点 `textSelectionPointRange` 为起点，反向跨页应和正向得到相同范围。[现有翻译调用](../../lib/services/ai_service.dart) 按输入顺序返回等长的字符串数组，可给原文单元保存稳定 ID、源区间和对应译文区间，随译文缓存版本核验。整句映射只证明整句，局部选区需另有可验证边界。保存在创建视图的精确位置与引文。存在歧义时，其他视图从「本书注释」回看，重新生成译文或 OCR 后也要先核验再画线。验收既要有能双向命中的真实样例，也要有明确回退的反例。
4. 显示层仅查询当前资料和可见页或文段，随字号、方向和分页重算虚线。PDF 复用字形位置、页面绘制回调，电子书复用当前文段渲染。检测注释点击时保留选文、链接、涂鸦和翻页的既有交互。不同选区即使重叠也保留各自 ID。点到重叠位置时显示命中的注释供查看，再打开对应详情。无文字层和暂缺译文时沿用现有可选文状态及列表入口。
5. 复用 [录音服务](../../lib/services/speech_recognition_service.dart) 的本机文件录制能力和 [笔记播放器](../../lib/pages/note_editor_page.dart) 的本机回放。只在点麦克风时请求权限。权限被拒、录音中断或用户取消选图时，只清理失败片段，保留本次已输入的文字、已选图片和已录好的音频。明确取消整个编辑才放弃本次更改。图片和录音先验证并写入私有目录，再提交引用，存储失败时保留其余草稿以便重试。
6. 点虚线和点「本书注释」条目打开同一只读详情，点铅笔才起键盘。取消编辑回到原详情，保存成功回到新详情。列表长按条目后可选择「删除注释」，二次确认通过后，本机一次提交删除和待同步操作。取消不产生改动。删除只作用于该 ID，重算重叠区的其余虚线，笔记库副本可继续打开。在列表语义操作中提供等价的删除入口。小屏、横屏或大字号下，超出可用高度的内容可滚动，短注释操作栏紧跟内容。

### 账号隔离与跨设备同步

- 服务器以验证过的账号身份派生稳定作用域，设备会话刷新后仍绑定同一账号。现有邮箱会话的通用 `personal` 租户键不足以区分私密注释。复用现有认证入口、SQLite 和持久对象底层。同步请求和媒体下载均重新校验账号，服务端只接纳私密可见性，日志限于状态、大小、耗时和脱敏 ID。当前邮箱登录仅允许配置的所有者邮箱，跨账号负例用隔离环境中两个独立认证身份及未授权会话跑实际接口。登出、切号或迟到下载均按原账号落盘，本机访客内容留在访客域。
- 本机书和资料整数 ID 映射到稳定的账号级书籍关联和资料版本。首次绑定持久化账号下的书籍标识及本机关联，第二设备须解析到同一标识。自动匹配要求原始 SHA-256 一致，书籍身份在本地和账号内都能唯一对应。书名、可变元数据或文件哈希单独均不能决定归属。同书无文件时保留可读的注释和待绑定来源。书籍归属也无法确定时保留未绑定记录，重新导入或获得唯一关联后再匹配。验收覆盖两台设备独立导入同书同文件、同一文件分属两本书、重命名和完全相同的引文位于不同段落。
- 用 SQLite 内的待同步操作记录和稳定操作 ID 执行重试。客户端联网后按增量游标拉取，上传媒体并校验类型、大小与摘要后提交相应注释版本。现有 `CloudStore.put` 每次只提交一份文档，本次需在同一 SQLite 连接内为注释、操作回执和递增序号补一个事务。分页读取有固定上界。客户端一次事务落下变更及游标。游标失效走全量校对，保留本机尚未确认的操作。
- 保存时记录编辑所基于的版本，并生成固定的编辑排序值。每次本地保存都排在所见版本之后。两端独立离线编辑同一条时按校准后的编辑时间排序，同值以持久逻辑计数和稳定设备标识定序。时钟回拨时沿用最近可信基准及单调顺序，首次离线且没有校时样本时采用保存时的本机时间并标记不确定。完全离线且设备时间错误时无法还原绝对先后。所有设备按同一规则选择整条版本及其媒体，上传或重试不会刷新编辑时间。
- 单条删除携带该条记录的删除标记，书籍删除另带书籍生命周期代次。旧设备迟到的修改不能复活被删条目。用户在同一选区主动重新新建时用新 ID，延迟操作仍指向旧 ID。恢复原书只恢复因本次删书隐藏的条目，之前单独删除的不恢复。服务端校验操作的原代次，媒体待无任何有效引用后再清理。
- 伴读媒体使用私有、持久、可鉴权下载的对象服务。现有 Agent 任务附件会到期且媒体种类不同，复用其底层流式校验和对象写入思路。只发送用户主动选给聊天或伴读问答的材料。新设备可能先收到注释，再下载图片或录音。断网时可读文字、可回放已缓存录音，其余附件显示待下载，联网后继续。编辑文字时完整保留尚未下载的媒体引用。待同步操作只由其原认证账号发送。

### 加入笔记库与删除边界

一键保存点击时的注释修订到「本书笔记」。固定该版本的完整引文、文字、图片、录音与排列顺序，用现有笔记写入链路生成可独立整理的笔记。先备齐全部媒体并确认副本能独立读取，再事务提交笔记和本次操作回执。缺媒体、空间不足或中途失败时保留原注释及重试入口。连点或结果未知重试只生成一个副本，成功后才显示「已加入笔记库」，页面停在原详情。后续改书内注释不会覆盖旧副本，用户编辑后再次主动加入可以另存新版本。

副本保留私密来源的账号归属，沿用本机笔记库的保存范围。[现有笔记查询](../../lib/services/database_service.dart) 与按书查询主要按本机记录检索。为这类新副本在列表、搜索、主页最近笔记、按 ID 打开及媒体读取处校验所属账号。副本保留自己的媒体访问权，原注释单条删除、切号或缓存清理都应可验证。已有普通笔记沿用原有规则。

| 用户操作 | 书内注释与已保存副本 |
| --- | --- |
| 从本书移除资料、转移资料，或彻底删除本机文件 | 按受影响的书与本机文件更新原文可达性。按哈希删文件可能同时影响本机多本书，不能据此跨书或跨设备删除注释。书内记录仍归原书，另一设备若有原资料仍可跳转。 |
| 最后一份可读资料也已移除 | [伴读目标解析](../../lib/widgets/reading_companion.dart) 会过滤缺失文件，[主界面入口](../../lib/pages/home_page.dart) 可能在打开阅读器前就返回。当已选书有注释时，从其既有入口直接到可打开「本书注释」的无资料状态，两层都要接通。可以点引文读完整摘录、回听已缓存录音。跳转依据文件和选区的实际可达性，区分本机缺文件、资料已删除及定位不确定。 |
| 在书架删除原书 | 书内注释立即从活跃列表和正文消失，将删书事件同步到同账号。现有[单本](../../lib/pages/book_study_page.dart)与[多本删除](../../lib/pages/book_learning_space_page.dart)提示都应准确说明手动加入笔记库的副本保留。[删书事务](../../lib/services/book_library_service.dart)中为副本保留有效笔记本、媒体和来源快照。用户已移动或整理过的副本保留其当前位置。 |
| 恢复原书或重新导入 | 书架实行软删除，给回收批次写入 30 天期限，服务层有恢复方法。当前界面没有书籍恢复入口，也未查到按期限永久清理书籍的链路。书内注释跟随原书的实际状态。显式恢复同一书记录时，只恢复因该次删书隐藏的注释。仅在确认原书已永久删除后，才清理相应注释和无引用媒体，留下阻止旧设备重新上传的代次记录。禁止仅凭本地时间或暂时找不到资料清除可恢复内容。重新导入时沿用书架对回收中书籍的限制，真正创建新书关联才使用新范围，重复导入活跃书的同一份文件可复用原资料。 |

## 实施与验收顺序

固定控件优先复用项目独立 SVG，包括已有编号图钉。按确认图核对锁、铅笔、麦克风和操作图形，在接入前用独立预览确认轮廓与线宽，登记来源、SVG 路径、viewBox、显示尺寸、状态和消费组件。用相同视口、键盘与内容状态做实机或目标平台渲染对比。读屏可识别铅笔、录音、私密选中状态、暂未开放项及列表操作，用户也可通过列表找到淡色虚线对应的注释。

| 阶段 | 交付与验收 |
| --- | --- |
| 1. 先验证技术边界 | 正例必须命中。分别从同一 PDF 的原页与重排视图创建注释，再从原文与已对齐的完整译句双向创建。另一视图必须在正确范围画线，打开同一 ID，编辑后两边看到更新。另测上下文能唯一定位的重复句、反向跨页，以及确实无法核实的局部译文回退。用项目 Genkit Flow 和 Trace 验证两款模型收到分组图片，以不同图片的独有内容验证理解。验证聊天附件、私密同步、下载和本机副本的账号隔离。 |
| 2. 主界面联通 | 点号编辑、仅图重启、三张与总量分别达限、普通附件混排、两图交换所属编号、同名图、失败整批保留、历史原图。模拟服务端已接收但客户端未收到回执，确保重试只有一条消息。验证已读图待澄清、暂停恢复、重新生成及切分支。引文包含「新任务」或「生成图片」时，按用户实际评论与主输入判断意图，核对工作归属及实际调用。 |
| 3. 伴读联通 | 手机、平板同状态对图。测单行引文与只读全文、键盘及读屏、长短面板、同区文字与录音、仅图或仅录音保存、权限失败。测长按删除与取消、重叠选区剩余虚线、旧记录不回填、同版本跨视图打开同一详情。两设备测离线逆序上传、时间回拨、旧设备迟到写入、单条删除后重新创建、切号及媒体下载中断。分别验收删最后一份资料、删书、显式恢复服务，用夹具验证永久删除后的迟到写入不能复活数据。检查副本完整可读，同一加入操作重试只落一份。 |
| 4. 同版本发布 | 核对当前接口版本，基线两端均为 43。新同步接口和注释媒体关联契约随客户端与服务端同次升级，交付共享发布标识。跑受影响检查，按现有 [发布验证基线](../architecture/release-flow-validation-2026-11-05.md) 和 [部署说明](../../xiaoqi_harness/deploy/README.docker.md) 用 `deploy_current.ps1` 发布、检查健康与数据、验证回滚。 |

本机数据库和云端存储迁移为增量写入，保留已有笔记记录。发布验证失败使用现有部署回滚点，保护已经产生的本机草稿及账号私密数据。同步异常时提示重试，保持离线写入和读取。验收报告分别记录实现、自动检查、同状态视觉、目标设备、部署和业务有效性。

## 实施记录

1. 主界面每条文字注释可以选择至多三张解释图。图片按注释 ID 和编号保存，账号及消息绑定由服务端校验。对应的图文块进入同一个 Genkit Agent 回合。整批待发数据和原尝试标识保存在本机，失败后可重试。
2. 伴读原版 PDF 与重排通过原页字符来源确认选区。完整译文单元与原文范围双向对应。无法验证的 OCR 和局部译文选区仍可从「本书注释」回看。旧 PDF 重排缓存升级后按需重建定位数据。
3. 伴读私密数据支持离线保存及同账号增量同步。云端按账号保存操作回执、编辑时间、资料绑定和删除状态，两台设备的本机数据库可以使用不同的书及资料 ID。
4. 「加入笔记库」在附件齐全时独立保存选中修订。原资料删除后，副本继续显示完整引文和自己的附件。副本归当前账号，可在笔记库查看、整理。

客户端与服务端使用发布标识 `2026-11-25-annotation-refresh` 和契约 `44`。Genkit DevTools 的合成图片验证在两个模型的 Trace 中都看到“注释 1、红图、注释 2、蓝图”的输入顺序。DeepSeek 实际返回了正确颜色，MiMo 的本机请求被供应商鉴权拒绝。仍需目标设备上的同状态对图、键盘和双端真机验收。

复审覆盖整批重试的文件引用和内容比较、解释图在会话后续任务中的账号隔离、普通附件与解释图混用时的澄清工具、跨页和离线来源定位，以及同步遇到删书代次变化和回滚游标时的数据保全。通过标准 Genkit 会话继续或分支，保留快照和任务回执作为原有恢复依据。用合成模型请求核实混合附件仍可以澄清，追问仍可访问授权历史中的解释图。
