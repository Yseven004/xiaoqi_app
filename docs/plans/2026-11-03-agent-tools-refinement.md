# Agent 工具完善与任务依赖按需准备（实施记录）

## 1. 目标、已确认范围与本次新增边界

让 Agent 容易判断何时使用哪个工具、如何填写参数、如何利用返回结果。优先完善现有能力，避免同类工具和提前建设。用户已确认交互与实施范围；本文记录实现及定向验收结果。

已确认的范围：解除通用任务文件工具与插件绑定；统一自有工具说明与返回契约；补齐当前任务文本检索、聊天内结构化提问、当前任务及其后台工作状态查询。

本次补充：Agent 可判断缺少依赖，通过现有执行工具申请任务依赖，由运行层安装、校验并复用。不是插件安装，不新增 install_package、install_python、install_npm 等模型可见工具。

**已确认边界：**支持 PyPI 的兼容 wheel 包、npm 包及其无需安装脚本即可使用的 CLI。暂不支持系统级 apt/sudo、源码编译、npm 安装脚本、任意 URL/Git 仓库安装、私有源凭据及任意二进制下载。缺少系统级命令时应明确报告本版限制，不冒称支持。已有镜像自带的系统工具继续可用，不为假想需求扩大预装镜像。

## 3. 实施顺序与接口

### 3.1 解耦与统一契约

- 将 list_task_files、read_task_text_file、write_task_text_file、edit_task_text_file 从插件存在条件中移出。读操作限定当前任务，写操作仍要求工作区授权；保留版本冲突、任务隔离、取消、预算及子 Agent 权限收缩。
- 保留现有职责明确的名字，不批量改名、不加同义别名。说明固定覆盖使用时机、相邻工具边界、参数来源、默认值、单位、限制及结果用途。账号、任务、权限由宿主注入。
- 自有工具统一 ok/data/error 外层；error 包含 code、message、retryable、可选修正建议。空结果不算失败。分页字段保持语义清楚。第三方 MCP 资源、结构化结果和 App 元数据保留协议语义，不强行包装。
- 用现有 Schemantic 定义输入与结果模型，同步当前调用方、提示词、策略和测试；不保留两套模型可见接口。工具中断继续走 Genkit 的 interrupt/resume。

### 3.2 三项已确认能力

| 工具 | 参数与使用时机 | 行为 |
|---|---|---|
| search_task_text | query 必填；prefix、offset、case_sensitive 可选；找当前任务正文时使用 | 仅 UTF-8 字面检索；默认不区分大小写；每批最多 20 条；返回路径、版本、片段、Unicode 字符定位及续查 offset |
| ask_user | questions 必填，每题有稳定 id、题目、可选选项 | 一次 1–3 题，单选或文字回答；选项也允许文字替代；返回按题目 ID 对应的答案或取消结果 |
| get_task_status | 无必填参数，任务身份由宿主提供 | 查询当前任务、其后台工作和依赖准备状态，返回实际状态、更新时间、等待原因及已完成产物摘要 |

- 路径发现继续用 list_task_files，精确读取用 read_task_text_file，附件按问题读取继续用 read_task_material。不加入跨任务检索、向量库或任务管理页面。
- 检索按文件当前版本扫描，限制 128 个文件、64 MiB 和 20 条结果；`truncated=true` 表示扫描预算用尽，不能据此断言无匹配。片段返回 artifact_id 和 Unicode 字符偏移。
- 提问通过现有 Genkit interrupt/resume 流程显示结构化表单，复用当前对话的选项芯片、文字输入和取消交互；一次 1–3 题，校验唯一问题 ID 和选项。取消会停止当前回复；答案不能代替操作授权。
- 状态从持久化运行记录读取，不虚构百分比、不启动或重跑工作，不自动持续轮询。

### 3.3 在执行工具内准备依赖：新增部分

为 execute_python、execute_shell 增加可选参数：`dependencies: {python: [包规格], npm: [包规格]}`。例如 Python 使用 `{"python":["openpyxl==3.1.5"]}`；npm 使用 `包名@版本` 或仅包名。只接受 PyPI/npm 包名与支持的固定版本格式；服务端解析无版本声明并锁定。每次最多声明 20 项直接依赖；传递依赖计入统一资源预算。新依赖合并到当前任务已准备环境，复用旧锁；版本变化需重新确认，失败不替换旧环境。

1. **Agent 判断与调用。**先检查环境是否已有能力；只有完成当前任务确实需要时才声明依赖。在现有 purpose 中简述用途。调用语义是“确保这些依赖可用后执行代码”，不是让模型自行编写安装器或修改注册表。Python 代码用 execute_python；CLI 和 Node 命令用 execute_shell。
2. **授权与隔离下载。**下载仅访问固定 PyPI/npm 官方源，域名由服务端推导。复用现有确认卡片，展示包名、用途、来源和权限范围；本版默认首次下载需确认。同任务、同一份已批准并锁定的依赖环境可复用；新增包或版本变化需要新的批准。已明确关闭或撤销联网时不偷偷下载，已有依赖可离线使用。依赖批准不授权用户脚本联网。
3. **准备、校验、发布。**在独立构建沙箱准备依赖，不挂载用户附件、产物或业务密钥。Python 仅接收官方源 wheel，记录版本、来源与 SHA256；npm 生成并校验 lock，使用 ci 且不运行生命周期脚本。对包规格、锁文件 URL、归档路径、链接、解包体积和可执行文件权限做验证。准备成功后原子发布，失败不替换原环境。
4. **任务内复用。**依赖包作为内部环境资料存储，不列入用户交付文件。键包含租户、任务、基础镜像身份/架构和依赖锁散列。后续新沙箱自动挂载该版本并配置 PATH、PYTHONPATH、Node 模块解析；任务代码默认仍断网。已有技能依赖位置保持原有隔离，任务依赖不得覆盖冻结的技能包或脚本。
5. **恢复与清理。**复用现有执行日志、执行 ID 和恢复机制。同一准备操作重试查询原结果，不重复执行；未知结果返回明确状态。依赖准备纳入 get_task_status。任务删除或既有过期清理时删除内部环境；并发运行固定各自已绑定环境，不在运行中替换。

安装阶段沿用 600 秒、384 MiB 内存、最终依赖文件总量 40 MiB 上限，另限制下载及构建临时空间为 256 MiB；必须在写入过程中执行配额，不能仅结束后检查。用户代码仍沿用 120 秒限制，安装不挤占该时间，也不绕过整个任务的预算。超时、超量、无兼容 wheel、依赖安装脚本要求或系统库缺失都返回可行动错误；不自行升权、换源或无限重试。

安装成功后运行实际 import/CLI 检查和用户代码，返回准备的包版本、缓存是否复用及阶段失败信息；安装成功不等于任务成功。安装成功而业务代码失败时，保留可复用环境，后续修正代码不再安装。

## 4. 设计确认、验收与发布

1. **交互实现。**复用现有授权对话框展示依赖包、用途、来源和任务范围；新依赖组需单独确认，已准备并锁定的组可直接复用。提问复用当前对话的中断/恢复及表单控件，无新页面、不预选答案、不自动弹键盘；遵守全局焦点规则和无页面转圈规则，并同步 DESIGN.md。
2. **定向回归。**验证无插件文件工具、跨任务拒绝、版本冲突；检索中文/分页/扫描预算；提问提交/取消；任务与依赖准备状态。只运行受影响的静态分析与测试，不重跑整套检查。
3. **依赖专项。**分别验证 Python 包和 npm CLI 的首次安装、第二次新沙箱离线复用；版本变更失败保留旧环境；断线不重复安装；取消和网络撤销；跨账号/任务隔离；非法来源与路径、损坏包、脚本要求、系统安装请求、下载与磁盘限额。测试实际 Node 模块导入和 CLI shim，不以存在目录代替可执行性。
4. **小量实际调用。**使用 Genkit trace 确认 Agent 正确选择工具、声明必要依赖并继续任务；用真实 Docker 沙箱做少量安装与离线复用验收。真机焦点和卡片验证单列，不把静态检查或容器测试写成手机验证通过。保留部署必需 CI 门禁，不额外重复整套检查。
5. **统一发布。**Flutter、服务端、执行请求及结果契约作为一次发布更新共享版本；不升级 Genkit 或引入另一套 Agent 框架。检查通过后由代理按现有 deploy_current.ps1 流程部署，验证健康、数据、版本与合约；失败自动回滚。日志区分实现、自动化、容器、视觉、真机、上线及实际效果。

## 5. 固化规则、参考与当前状态

项目规范固化：工具名、描述和参数应让 Agent 易懂、易选；一个明确意图优先对应一个入口；先复用现有能力，不堆叠同类工具或万能 action 工具。软件依赖按需准备不等于新增模型工具，更不等于插件安装。账号、授权及权限不能通过安装依赖获得。

参考以 2026-11-03 查阅资料为准，不直接复制外部实现：

- [Anthropic：Writing effective tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)：职责边界、清晰描述、精简且可行动的返回结果。
- [Genkit 官方项目](https://github.com/genkit-ai/genkit)：Apache-2.0；本项目仍使用锁定的 Genkit 1.0.0，复用现有工具、interrupt/resume 与 trace 机制。
- [pip secure installs](https://pip.pypa.io/en/stable/topics/secure-installs/) 与 [pip install](https://pip.pypa.io/en/stable/cli/pip_install/)：目标目录安装、wheel 限制、哈希校验；以容器实际 pip 版本支持的参数为准，不依赖最新文档新增选项。
- [npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci/)：锁文件复现与禁用安装脚本；明确禁用脚本不保证所有包可用，失败不能悄悄放开执行策略。

当前实现范围包括通用任务文件工具解耦、工具描述与返回契约、任务文本检索、结构化提问、任务状态（含后台 hook 与依赖准备）、Python/npm 依赖准备与本任务隔离复用。系统级安装仍为后置项。工具设计规矩已同步至 `DESIGN.md`：明确何时用/不用、输入来源、结果下一步；分类仅供盘点，不因补齐类别而加工具。

定向验证结果：Flutter 文件分析退出码 0，显示 4 条既有 info；服务端相关 Dart 分析无问题；`py -3 -m py_compile` 通过；新增文本检索分页、依赖锁定/累加/复用用例通过；任务文件策略、Agent 工具可见性用例通过；后台 hook 文件内 6 项用例通过；`git diff --check` 无问题。未运行整套测试、真实 Docker 包安装或真机验证。服务端部署状态待完成发布后更新。
