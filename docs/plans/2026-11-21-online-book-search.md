# 网上找书内置插件 · 首版开发方案

2026-11-21。本轮开发「网上找书」内置插件。用户核对版本和来源后，选定 PDF／EPUB，并通过现有导入服务入库。书源实测覆盖三个中文作品的官方版本和 Open Library 版次书目。[确认原图](../design/book-library-monochrome-v1/confirmed/online-book-search-2026-11-21.png) · [交互定稿](../design/book-library-monochrome-v1.md) · [书源实测](../diagnostics/2026-11-21-online-book-sources.md)

## 1. 用户最终能做什么

用户点「网上找书」，在大号居中弹窗里点三条推荐之一，也可以直接输入书名、作者、ISBN 或问题。书卡和文字回答沿同一个对话显示。用户核对作者、版本、语言、格式和来源后，点对应版本的「导入」。主聊天里说「帮我找这本书」时，消息下复用同一个版本选择和导入组件。

| 发起位置 | 成功后的落点 |
| --- | --- |
| 书库 → 新建 → 网上找书 | 按所选版本新建或复用书目，文件出现在这本书的资料列表。 |
| 已有「网上找书」入口（添加新书／本书资料／任务资料） | 打开同一插件，沿用调用方传入的书目信息。成功时把书籍和资料标识交回原入口，取消时直接返回。 |
| 主聊天调用插件 | 在当前消息下显示版本和来源，确认后调用同一个导入动作，回显实际结果。 |

新书入口目前直接打开古登堡，已有书的入口另有来源对话框。只在这些「网上找书」动作上接入插件，并显式处理返回值，避免误入扫码或文件选择。书库负责已有的文件存储，调用入口负责接收导入结果。[书库入口](../../lib/pages/book_learning_shell_page.dart) · [添加新书](../../lib/widgets/reading_task_book_creation.dart) · [来源菜单](../../lib/widgets/book_pdf_import_sheet.dart) · [已有书的导入入口](../../lib/widgets/book_source_import.dart)

## 2. 一个窗口怎样找书和追问

| 用户操作 | 执行者与反馈 |
| --- | --- |
| 首次打开 | 显示三条温和灰底的编号推荐。优先用当前关联书籍，无关联时按本地近期阅读取线索，缺少线索时使用三条常见推荐。点推荐即提交，保留未发送草稿。 |
| 提交找书条件 | 校验有效的独立 ISBN 直接调用已鉴权的查找接口。书名、作者及自然语言要求沿用现有 Agent 按需调用同一服务。一个底部输入框和一条消息列表承接这两种提交。 |
| 点 Python 版、查看来源或导入 | 已知版本的选择只更新结果视图。点来源才打开来源页。导入使用用户点中的候选及目标书，不额外发起模型回合。 |
| 补充要求或换一本书 | 从已有候选即可回答时直接使用它们。确实需要新检索时创建新的查找编号，旧响应只能更新原查找。 |
| 窗内点「停止」 | 停止对应检索，弹窗保持打开，已经核实的结果仍可导入。 |
| 关闭弹窗 | 右上角关闭、系统返回和实际离开弹窗时停止当前检索及未结束的回合。仅收起键盘时，检索继续。 |
| 断网与重连 | 弹窗仍打开时按原编号恢复查找状态。弹窗已经关闭时只补送待确认的停止请求。部分来源失败时保留其他来源的结果。所有来源不可达时显示「来源暂不可用」。 |

插件展示两类业务状态：当前查找是否仍在进行，以及所选文件是否已经入库。查找以服务端记录为准，入库以设备书库的写入结果为准。聊天中的「正在回答」沿用现有回合状态。

合并版继续使用 API 39。Genkit 1.0.2 的 `AgentChat.sendStream` 持有官方会话，`AgentChunk.text` 读取流式文本，`AgentResponse.text` 校正同一条最终回复。远程反序列化的 `Part` 不能依赖 `TextPart` 运行时类型。按回合绑定业务检索引用，仅在 Flutter 维护本窗口的显示顺序。上一份业务检索编号沿用 `book_search_context_id` 给现有服务端 Agent；它仍是候选状态的唯一来源。取消沿用 `AgentTurn.abort` 与已有停止接口，A2UI 继续通过已安装的 v0.9 官方组件目录和动作分发。

「我的 → 内置插件」提供网上找书开关，沿用绿色开关样式，无卸载入口。首次启用是建议默认值。关闭插件后阻止新的插件操作，停止继续寻找来源。

## 3. 单引擎与数据契约

在现有 Dart 服务端增加一份找书业务实现。直接搜索用应用的鉴权 API。聊天用一个标准 Genkit 工具调用同一实现。两者共用候选核验、来源策略和查找状态。网页发现和读取复用现有 WebService，包括已配置的 TinyFish 和 DeepSeek 备用接口。它们是网页发现服务，具体电子书渠道另行选定。[联网实现](../../xiaoqi_harness/genkit_server/lib/src/web_service.dart) · [Agent 工具注册](../../xiaoqi_harness/genkit_server/lib/src/agent_runtime.dart)

| 业务契约 | 最小内容与处理 |
| --- | --- |
| 发起查找 | 输入书名／作者／ISBN，按已有信息附语言、版次及格式。服务端从登录设备派生账号，校验插件开关、联网权限及原任务归属。为这一次提交携带请求标识，同次重发返回同一查找编号。不同账号、会话或新查询独立。 |
| 获取进度与停止 | 按查找编号和已见版本号读取状态及候选。在关窗或手动停止时，取消本次可中止的网络请求，停止派发后续请求。客户端丢弃关窗后的迟到响应，服务端确认停止后拒绝追加候选。停止可重试。若发起请求尚未返回编号就关窗，保留该次提交的请求标识，确保迟到的启动也进入停止流程。 |
| 返回候选 | 每个候选有稳定编号、书名、作者、语言、版次、格式、来源名和落地页。译者、出版社、出版年、ISBN 以来源实际提供为准。记录取得方式、许可依据和核验时间。多来源的同版可归并并保留各自出处。译本、代码语言版本、整本与章节要分开。 |
| 确认导入 | 卡片提交查找编号、候选编号及目标上下文。服务端复核归属、开关、有效期和来源，返回经核验的下载信息。设备复用现有下载和书库写入。失效候选先重新核实，已确认的同版导入可安全重试。 |

Agent 的新工具建议命名为 `find_book_material`，用于用户按书名、作者、ISBN 或版本要求查找可导入电子书的场景。输入来自用户请求或已有书目信息，账号与调用归属由运行时绑定。工具返回查找编号、候选版本、出处和取得方式。需要区分版本时在当前对话追问，用户点选后才导入核实过的文件。

所有入口沿用现有认证、接口版本检查、网络禁用策略及请求范围。找书开关沿用设备维度，服务端应能核对当前认证设备的有效设置。登出、撤销或关闭后旧卡片不能继续发起新操作。通用网页工具仍按原有权限服务其他任务。有效 ISBN 直查、选择已有版本和导入均无新增聊天模型调用。单次调用网页供应商仍可能计费。工程验收分开统计模型调用、实际检索及入库写入。

建议在现有认证路由下使用 `POST /v1/book-searches` 发起，`GET /v1/book-searches/{id}` 读状态，`POST /v1/book-searches/{id}/stop` 停止，`POST /v1/book-searches/{id}/candidates/{candidateId}/resolve` 在点击导入后重新核验取得方式。首次 GET 返回快照，后续可带已见 revision。首版仅在当前界面有订阅且查找未结束时短轮询，复用同一订阅。关窗时立即发出停止并解除视图订阅。停止确认由插件请求层处理，网络中断后按原查找标识补送。已停止的查找只允许读取既有结果。查询有超时和有限重试，终态结果短期按账号缓存，过期卡片提供「重新查找」。已经入库的书和长期来源记录继续从本地书库读取。会话和分支只保存查找引用，后续追问按需使用已有候选。

## 4. 首批书源的选择与文件处理

开发先用可控样本跑完整流程。真实渠道逐个记录检索方式、中文覆盖、版本辨识、全文链接、服务条款／每书许可、允许的下载域名及跳转、速率限制和实测结果。优先评估作者或出版社官方发布页、可提供整书的开放获取书库。网页搜索摘要和文件扩展名只提供线索。只有来源支持所选版本的完整文件、取得与本产品处理条件相符时才显示「导入」。其余可展示书目信息并标明试读、购买、借阅、仅章节或暂无全文。

| 样本 | 要回答的问题 |
| --- | --- |
| 《Hello 算法》 | 作者发布的简体版能否区分 Python／Java？逐项核对文件和作品许可，区分书籍内容与程序代码的许可。[作者官网](https://www.hello-algo.com/) · [发布记录与文件](https://github.com/krahets/hello-algo/releases) · [许可](https://github.com/krahets/hello-algo#license) |
| 《动手学深度学习》中文第二版 | 能否搜到官方在线版及整本 PDF？书卡区分纸书与在线版，避免把纸书 ISBN 填给网络文件。[作者官网](https://zh-v2.d2l.ai/) |
| OAPEN 整书／章节记录及只有购买页的中文书 | 同一部作品出现章节、整本或零售书目时，只为核实可用的整本提供导入。记录真实中文命中情况。OAPEN 元数据和逐书全文分别核对使用条件。[OAPEN 书目说明](https://oapen.org/librarians/metadata) |

在目标服务运行网络验证样书发现和来源读取，在 Android 网络验证下载和实际文件能否打开。记录跨时段成功率、超时／限流及重试结果。上述名称都是候选。正式交付可找回全文的插件，需要至少一条真实渠道跑通「查找 → 查看来源 → 导入正确版本 → 核对文件」。

沿用现有临时下载、超时、流式大小上限和 PDF／EPUB 格式校验。自动书源增加每次跳转的 HTTPS、许可域名／CDN 和公网地址检查。日志保留来源域、结果和耗时，剔除临时签名和凭据。文件校验失败时清理本次临时副本，保留其他已找到的版本。

## 5. 插件导入与结果回执

- **入库只发生一次。** 复用书库对文件的 SHA-256、实际格式校验及同一书目下的唯一约束。同版双击、两入口近同时确认、响应丢失后重试均应读回实际结果。先核实文件，再提交书目和资料关系。新建书时要覆盖「书目创建成功、资料插入失败」及并发新建。数据库已有书、原文件与用户编辑过的元数据都须保留。[入库服务](../../lib/services/book_library_service.dart) · [数据库约束](../../lib/services/database_service.dart)
- **来源随文件保存。** 复用资料已有的 `origin_uri`、`canonical_uri`、`captured_at` 等字段，补齐网络导入传参和写入。来源页使用可长期打开的地址。旧记录没有来源时按既有本地资料展示。书名相同而版次不同不得误合并，匹配顺序优先核对 ISBN 与具体版本信息。[资料字段](../../lib/models/book_source.dart) · [书目匹配](../../lib/models/book_recognition.dart)
- **把结果交回发起位置。** 现有导入服务成功后，插件返回目标书籍 ID、资料 ID、来源及是否复用已有文件，供当前入口显示「已导入」。取消、失败或调用方已失效时，避免把结果写到后来打开的书或会话。

## 7. 开发顺序和验收

| 次序 | 交付 | 通过条件 |
| --- | --- | --- |
| 1 · 样书与单引擎 | 建立正反样本，验证候选渠道，贯通已鉴权的发起、读进度、停止与候选核验。界面可并行使用夹具。 | 能区分正确版本、仅章节、无全文、网络异常。停止后保留已核实结果，无迟到回写。 |
| 2 · 文件导入 | 贯通版本选择、文件下载校验、来源留存和现有入库服务回执。 | 同一版本重复点击只入库一次。来源可追溯，文件与所选版本一致，下载或校验失败时可重试。 |
| 3 · 插件交互与宿主接入 | 完成大号居中弹窗、统一消息流、三条开场推荐、A2UI 书卡和内置插件开关。 | 推荐可点，书卡出现在对应回合，追问文字出现在下一条回复。消息中的书卡可导入。关闭插件后，旧卡片不能继续发起插件操作。 |
| 4 · 回归与配对发布 | 分别完成服务端业务检查、Genkit Trace、Flutter 同状态视觉比对和 Android 验收。 | 满足下面的核心场景，再按已有流程成套发布客户端和后端。 |

**验收从一次真实操作开始。** 搜有两个版本的样书，用同一输入框追问「推荐哪个版本」，核对先显示书卡、后显示针对已有候选的文字回复。点一次导入，当前按钮显示「正在导入」，核对正确版本、来源、封面和目录。切换版本和导入沿用同一个查找编号，查找访问多个来源时按一次业务请求统计。

分别在刚提交、部分结果已显示、网络暂时中断时，用关闭按钮和系统返回退出。核对服务端进入停止态、离线重连后补送停止、已关窗口停止接收结果。再次打开后首屏等候主动提交。查找中只收起键盘时，原查找继续。

回归覆盖插件入口、取消和返回、开关关闭后点击旧卡片、换书后旧结果晚到、停止找书、断网或失效链接、下载中断及重复确认。核对账号隔离与旧卡片归属。手机、平板与大字号核对弹窗、键盘和按钮单击响应。复用现有图标，新固定图形先独立预览再接入。[全局界面规则](../../DESIGN.md)

### 扩充书源与找书指令（接口 40）

本次客户端和服务端使用同一发布编号 `2026-11-21-wikisource-book-search`。接口 40 将书名、作者、版次等条件传给工具，并允许客户端导入从中文维基文库核实的 EPUB。已有书籍、找书记录和导入凭据沿用原有存储。旧客户端按已有版本检查提示升级。发布验收使用真实找书回合、候选二次核验和客户端入库，回滚沿用正式部署脚本的上一版恢复点。

中文维基文库作品经原始目录和章节核对后，用官方 MediaWiki API 的指定修订排版生成 EPUB。已有的候选核验接口在同一次鉴权响应里返回最多 4 MiB 的成品及 SHA-256 校验值，找书列表只保存书目与候选状态。客户端复用已有的 EPUB 读取与入库流程。单本需等待逐章读取，服务端核验上限 90 秒，客户端对这类候选给出 100 秒。香港出口对 WS Export 返回 403，作品及章节 API 经生产出口验证可用。
