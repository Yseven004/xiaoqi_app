# 小七 DSH 可视化管理后台开发计划

日期：2026-10-08。状态：产品范围与 UI 方向已确认；管理后台已部署到目标服务器并通过公开页面和容器健康检查；真实 DSH 操作及同视口视觉对比仍待验收。

## 1. 目标与已确认决策

为小七维护者提供独立浏览器后台，通过 HTTPS 域名和管理员登录，管理服务端真正使用的 DSH 插件、配置及运行版本。优先复用官方能力，补齐小七任务系统的配置发布和版本切换。

- UI 以本次对话的图二「版本管理」和图三「插件工作区」为依据；不再等待合并图片生成。用户已确认方向并要求简洁、易懂、易操作。
- 插件操作先保存到待应用配置；点击「应用到小七」发布全局配置，覆盖新会话和已有会话的下一条消息。正在回答的任务保留其启动时配置直到完成。
- 切换 DSH 版本前暂停接收新任务，等待当前任务完成后切换；健康检查通过后恢复。下载和准备候选版本在暂停之前完成。
- DSH 和插件均固定精确版本，不自动安装更新；检查更新与应用更新是两个动作。
- 主导航仅「插件」「版本管理」，账户菜单放登录信息和退出。不照搬设计图里的新会话、工作区、聊天功能。

成功标准：无需 SSH 即可完成安装插件→配置→应用→下一条小七消息生效，以及检查 DSH 更新→查看兼容结果→切换→必要时恢复上一版本；当前回答不中断，原有会话和租户隔离不被破坏。

## 2. UI 与交互规格

### 插件页（默认入口，图三方向）

顶部只显示当前 DSH 版本、运行状态和「管理版本」链接；正文使用官方式图标列表、白底、浅灰侧栏、清晰中文文字和留白。默认显示已安装插件，按官方／社区分组；搜索在插件数量增长后仍可定位项目。

| 元素 | 行为 |
| --- | --- |
| 添加插件 | 单一入口，输入 npm 包名或 GitHub 仓库；社区发现列表放在此弹窗内。显示来源、精确版本和兼容结果后安装到草稿。 |
| 插件行 | 名称、简短说明、当前版本、开关和必要的异常／更新状态；整行可进入详情。未应用的修改有明确标记。 |
| 插件详情 | 配置、版本、来源、更新、卸载；原始错误和日志默认折叠。更新后仍需应用到小七。 |
| 检查更新 | 次要动作；发现新版本不直接安装，也不显示为兼容通过。 |
| 应用到小七 | 仅有待应用变更时出现主要按钮，旁边是「放弃修改」；点击先展示简短变更摘要和影响范围，再确认发布。 |

开关只修改草稿，不能用绿色「已生效」误导用户。发布成功显示「已应用，下一条消息生效」；失败保留草稿和旧线上配置，并提供重试。可从最近一次发布记录恢复旧配置。

### 版本管理页（图二方向）

只展示当前精确版本、是否固定、更新检查结果和可恢复的历史版本。主要动作是「检查更新」；选中候选版本后才出现「切换到此版本」。始终固定当前版本，避免多余的自动升级开关。

切换确认展示：当前版本→候选版本、变更摘要、插件兼容结果、会话格式检查结果、恢复点。进度用静态步骤文字：准备完成→等待当前回答→切换与检查→恢复服务。等待阶段可取消；进入切换阶段不提供强杀按钮。

异常情况下显示一句原因和一个明确动作。回退必须说明会恢复哪些内容；不能把「切换旧程序」标成「会话数据已恢复」。默认只推荐已保存且检查通过的恢复点。

### 全局易用性约束

- 每页至多一个高强调主要操作；不加监控图表、KPI 卡片墙、复杂筛选器或独立日志中心。来源与上次检查时间置于详情／轻量说明，不把技术术语堆在首页。
- 兼容性分为「版本要求匹配」「不兼容」「尚未确认」，运行验证另列结果；普通界面不显示 peerDependencies 等实现名词。
- 首次加载用静态骨架或占位；页面跳转没有转圈。操作中的按钮可显示小型进行中反馈；状态变化不能仅依赖颜色。
- 网络失败保留已有数据并显示检查失败，不能显示「已是最新」。空状态给添加插件入口；登录过期重新认证后可恢复查看操作结果。
- 键盘可操作、焦点可见、弹窗可关闭且返回触发点，表单错误靠近字段。主要按键目标至少 44px；1280px 桌面和窄屏均可完成主要操作。

视觉资产使用原始官方 SVG 或独立矢量文件；记录来源、许可、viewBox、显示尺寸、状态和消费组件。禁止截图切片或把整张设计图做成页面背景。生成稿中的日期、版本历史、插件数量、已验证等文字都是示意，实际页面必须绑定真实结果。

## 3. 现有实现与复用结论

本次只读代码核对发现：

- `xiaoqi_harness/Dockerfile` 固定安装 DSH `0.2.0-rc.2`；Compose 中 app 非 root、根文件系统只读，已有独立持久化数据卷。
- `single_server.py` 使用 Flask，现有任务队列是进程内单 Worker。保留现有 API、持久化、租户校验与任务模型。
- `capabilities/harness_worker.py` 每次创建临时 DSH_HOME，通过 `xiaoqi-acp` profile 启动 ACP；会话快照仅包含 sessions、attachments、storages，不含 profile 和依赖。
- 小七有额外的工具禁用与权限约束。官方 Web 页面中的开关不会自然控制这些 ACP 任务；必须实现发布接入，不能另起一个面板后声称已控制小七。

## 4. 技术方案与接口边界

### 管理服务与运行版本

Compose 新增一个非 root 管理服务，负责官方管理能力适配、候选依赖安装及管理页面；沿用 Flask API 风格，前端使用 React + TypeScript 实现两个轻量管理页，不另加通用后台框架。用 Node 子进程适配官方 DSH 包与 CLI，精确锁定 Node 和基线 DSH 版本。

管理服务写入独立运行包持久化卷，生产 app 只读挂载该卷。每个发布包包含精确 DSH 运行文件、插件依赖锁、ACP 配置、配置版本和完整性记录；用 release_id 标识。下载与安装在新目录进行，现有发布包不可就地改写。管理安装进程不注入模型密钥，也不授予生产数据卷或 Docker socket。

生产 app 的 SQLite 记录唯一有效 release_id 和维护状态；通过受认证的内部接口发布、暂停、恢复，不能仅靠管理服务改一个软链接绕过队列控制。Worker 按 release_id 选择明确可执行路径，避免 PATH 中旧 DSH 与环境变量版本号不一致。运行包准备失败不影响旧版本。

现有镜像内 0.2.0-rc.2 作为首次迁移基线与紧急回退入口。需要更高 Node 版本、系统依赖或新适配器接口的 DSH 更新，显示「需要更新服务环境」，不可声称能在线安装所有未来版本。

### 全局配置与任务连续性

草稿和线上发布分开保存。草稿变化仅影响管理预览；发布生成不可变配置 revision。任务开始执行时原子读取有效 revision 并记录，执行期间不再重新读取；重试和权限恢复沿用该任务 revision，下一条新消息读取最新 revision。

Worker 创建临时 HOME 时装配所选发布包的 ACP 配置与依赖，再恢复原有会话状态。依赖不进入会话快照；不在每次回答前联网安装。配置生效顺序固定为：官方 ACP 基础→已发布插件和配置→小七每请求设置及权限约束。受小七安全策略禁止的能力必须显示明确原因，不能出现开关开启但实际无效的状态。

Web 专用插件、语音输入和纯前端装饰不自动认定为小七 ACP 能力；界面标明适用位置。插件仅声明运行版本匹配时，显示「版本要求匹配」；还须在目标 ACP 配置中启动检查才能进入待发布包。缺失声明或未确认 ACP 支持时先阻止生产发布并给出原因，不默认强行豁免。

### 更新来源与检查

DSH 可安装版本以官方 npm 包元数据为准，GitHub Releases 用于发行说明、预发布标记和交叉核对；GitHub 有发布但 npm 尚不可用时不得显示可安装。分别处理 latest／next 与精确版本，不能把 latest 字符串当成最高版本。

插件目录只用于发现；npm 插件检查其注册表元数据，Git 来源固定到不可变 commit，记录具体来源与校验值。官方内置插件随 DSH 发布，不提供与整体运行时脱节的独立升级按钮。社区插件更新先检查新插件与当前 DSH；DSH 切换则检查目标版本与全部启用插件。

默认每 6 小时检查元数据，支持手动检查；显示真实检查时间、来源和失败／缓存状态。此定时行为由服务实现，不创建聊天自动化。只检查、不自动安装。社区目录失效时仍能查看已安装插件并按包名添加。

### 维护、回退和恢复

准备候选→校验安装和锁文件→插件及 ACP 会话检查→建立恢复点→原子进入维护状态→暂停新任务受理与队列启动→等待在途任务自然结束→提交新 release_id→健康检查→恢复队列。

进入维护与任务受理共用调度锁／事务，消除刚检查完无任务又启动新任务的竞争。已受理未启动的任务保留队列，切换后使用新版本；切换期间新提交返回可识别的 maintenance 错误及 Retry-After，客户端保留输入并给出「服务更新中，请稍后重试」。不静默丢弃，也不自动重复提交消息。

等待 10 分钟仍有任务时取消此次切换并恢复受理，保持旧版本；不强制结束回答。管理页面关闭不取消服务器操作。操作持久化且可查询；服务器重启后先恢复未完成切换状态，检查通过前不自动放开队列。

回退保留程序、插件、配置和会话格式的对应关系。旧版本不能读取新会话格式时，阻止直接降级并解释原因，不静默恢复旧快照造成新消息丢失。完整数据灾难恢复属于独立运维动作；本期回退按钮只允许兼容性检查通过的恢复点。切换后的健康检查失败自动恢复上一有效发布包；若旧包也不可用，保持维护状态并报告恢复操作。

### 管理 API 与权限

| 接口组 | 最小职责 |
| --- | --- |
| /admin/api/auth | 管理员登录、当前身份、退出；使用独立管理员会话，无公共注册和默认密码。 |
| /admin/api/plugins | 当前／草稿配置、安装预检、安装与更新任务、配置、开关、卸载。 |
| /admin/api/releases | 当前发布、检查更新、兼容性预检、应用配置、切换、恢复上一发布。 |
| /admin/api/operations | 查询操作进度与结果、允许阶段的取消；相同请求幂等，防止双击重复安装或发布。 |
| 内部运行控制接口 | 带独立凭据的状态读取、排空任务、提交 release_id 和恢复；仅 Docker 内网可达。 |

对外经现有 Caddy 加入独立管理域名；具体域名作为部署参数，部署时校验 DNS／证书，不猜测或擅自购买域名。认证使用服务端会话、密码哈希、Secure/HttpOnly/SameSite Cookie、登录限速及 CSRF 防护；退出立即撤销会话。普通小七账户不得获得管理权限。API 密钥只在服务端保管，日志脱敏。插件宿主代码有服务器权限，安装权限仅限管理员，管理页明确来源与必要脚本权限。
