## 历史方案及证据

范围是网上找书。现有实现先展示候选，点击导入才 resolve。新流程把完整文件取得与校验提到交付之前，用户点击后仍由原书库服务保存。

1. 模型从用户话里提取已明确的书名、作者、ISBN、语言、出版版次、代码框架和格式。适用时用下一组查询补充作者别名或切换已审核渠道，保留用户的硬条件。
2. 系统执行检索，核对允许渠道、取得授权和书目。尝试取得完整文件，并检查实际格式、完整性和版本。只保留通过的文件，暂存凭据只对本账号、本次检索有效。模型得到结构化结论和下一步线索。
3. 一轮计一次实际执行的找书工具调用。符合用户全部明确条件且已核验的整本命中后结束。否则只要还有预算和不同的有效条件，就必须继续检索；最多五轮。重复查询复用已有结果，并发工具请求不能绕过上限。只有没有可执行的不同条件、权限不足、用户取消或整体超时时才提前结束，报告真实状态；不可在预算未耗尽时仅建议用户选择下一种搜法。
4. 界面可以显示查询和核验的过程状态。核验结束后统一展示可导入卡片及回复；仅书目另标清楚，下载失败的项无导入按钮。失败回复依据执行记录区分未命中、仅书目、渠道异常和文件未通过核验。用户确认后复用已有文件入库。

## Genkit 实现边界

沿用 Genkit Dart 1.0.2 的标准 Agent 工具循环。以 BookSearchService 的同一任务记录维护轮次预算、已查条件、取消状态及已核验文件。每轮有独立查询身份，聚合进同一个找书任务。模型收到经核验的工具输出，客户端展示由宿主管理。Genkit 的 maxTurns 约束模型回合，不等于五次工具调用。五次工具调用外仍要允许最终回复走一次模型，或由宿主根据执行记录给出确定性的结果说明。

## 扩大书源覆盖

已经确认现有通用网页搜索只能给三部登记作品补别名，最终可下载候选依然受同一份目录制约。目标是扩大可发现的发行页和整本渠道。网页搜索命中只代表有线索，整本仍须核对发行方、可提供的完整文件、书名、作者、版本与格式。核验失败继续显示实际原因。每种渠道记录查找、文件探测、获取和核验的具体结果，不记录查询原文、下载链接或凭据。

本轮已去掉官方目录与既有其他来源之间的互斥。官方目录没有匹配版次、文件探测失败或文件核验失败后，继续查适用的其他来源。取得符合要求的整本后，现有服务仍立即结束本次搜索。分渠道诊断已接入服务端日志。28 项本地定向测试通过，6 项需要真实书源的用例保持跳过，相关 Dart 静态分析通过。真实整本取得率沿用最近全量测评的 3/20，尚无改动后的全量结果。

- 中文古籍优先修中文维基文库已定位的目录和页头识别，使用正式目录确定需要核对的章节。参考 MediaWiki 的 [Wikisource 导出说明](https://www.mediawiki.org/wiki/Help:Extension:Wikisource)，导出服务可提供 EPUB 和 PDF，但能导出文件本身不证明目录及正文章节完整。
- 优先复用宿主现有 `WebService` 来发现其他作者、出版方和数字馆藏的发行页。评估候选渠道时先验证该渠道是否能确定授权、格式和版次，再接入整本下载。图书馆书目和发行页可沿用现有仅书目卡片。通用发现的搜索请求需要独立计量。
- 古登堡作为可选补充渠道，优先评估其正式机器可读目录和馆藏下载路径，参考 [自动访问说明](https://dev.gutenberg.org/policy/robot_access.html) 和 [官方目录](https://www.gutenberg.org/ebooks/offline_catalogs.html)。目录不提供原纸书的出版版本信息。Gutendex 的 MIT 实现可以作为目录索引参考，不把其托管实例设为运行依赖。 [Gutendex 项目](https://github.com/garethbjohnson/gutendex)

### 开放搜索和用户确认

沿用现有网上找书弹窗与书卡。适用的整本渠道未命中后，使用一个有时限的公开网页搜索补充发行页线索。仅从现有 WebService 已校验的公开地址中挑与书名相关的 HTTPS 来源页，展示站点和待核标签。搜索摘要不能提供下载资格。不新增检索工具、模型回合或客户端协议。用户指定版次、语言和格式继续应用于正式整本；网页线索只作为来源提示。

当完整文件能安全交付，但版本或来源说明有用户可以取舍的不确定性时，在同一张书卡显示具体原因、来源、版本和格式，提供「接受并导入」和「跳过」。有效确认须来自对应用户对当前候选的操作，绑定候选文件及摘要。确认后由现有导入链路取同一份文件。点跳过保留其他结果，关窗取消未完成工作。文件安全检查失败、缺失正文、需要绕过登录或借阅、无法核实允许交付时，只说明原因。质检装置未就绪就提供网页线索。新增交付确认状态和按钮前按此设计确认并更新两端契约。参考 [OWASP 文件校验](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) 和 [服务端公网访问校验](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。
