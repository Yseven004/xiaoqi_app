## 1. 已确认的用户闭环

1. 技能「添加」只保留「使用编辑器创建」「通过聊天创建」两个选项，移除独立的「从设备上传」。
2. 编辑器创建直接打开统一编辑页；既可从空白开始，也可在页内导入已有内容。
3. 聊天创建由小七内置的技能创建助手负责：描述需求 → AI 追问关键问题 → 整理创建摘要供确认 → 生成技能草稿。A2UI 承载追问、确认与草稿操作，保持统一组件样式，不重复询问已回答的信息。
4. AI 生成后留在聊天，草稿卡展示名称、简短说明和「查看草稿」。用户可以继续聊天修改；点击后携最新草稿进入同一编辑页，不自动跳页、重新导入或发布。
5. 编辑页 → 预览页 → 用户确认发布 → 发布到小七市场，供其他用户查看、搜索和安装。第一版作者确认后直接发布，不增加人工审核队列。

「技能创建助手」是小七内置插件的产品定位，不代表当前代码已经完成插件注册、结构化追问或草稿交接。A2UI 指项目已有的 Agent-to-UI 能力；依据：[Genkit 官方说明](https://genkit.dev/docs/dart/agents/a2ui/)。

## 2. 冻结的界面与操作

| 区域 | 已确认行为 |
| --- | --- |
| 编辑页顶部 | 返回、居中「编辑资料」、草稿归属与状态；右上角「导入内容」使用黑底白字和原有导入图标。仅增强按钮醒目程度，保持已确认布局，不新增导入区块或移动按钮。 |
| 展示资料 | 图标、名称、一句话简介、详细介绍。图标支持内置矢量库与上传，可预览、更换、恢复默认；作者、来源与版本不作为可自由填写的身份信息。 |
| 技能内容 | 独立的可展开行，显示主文件及实际附件情况；正文和包内文件默认收起，需要时展开编辑。详细介绍与技能执行指令分开。 |
| 介绍图片 | 固定有序图片区，支持添加、排序、删除及可选简短说明。图片可选，不把图稿示例张数、字数或图片内容当成产品限制及默认数据。 |
| 编辑页底部 | 「保存草稿」「预览」。预览页按最终只读详情效果展示资料与图片，顶部注明尚未发布；底部「返回编辑」「确认发布」。 |

技能、插件、MCP 的展示资料采用统一模板与视觉语言，是此前已确定的方向；本轮冻结的具体页面和闭环仅针对技能。更换图标、正文展开等内部界面的具体布局尚未单独出稿，不应据本规格宣称全部子界面均已视觉验收。

## 3. 导入、权限与草稿状态

- 「导入内容」复用现有文件／链接导入弹窗及检查、取消与错误反馈；检查通过后回填当前草稿、关闭弹窗并停留在原编辑页。结束动作不再直接安装或另开第二个编辑器。
- 导入涉及覆盖已有修改时先确认；取消、失败或解析不完整时保留原草稿。已有包检查、路径限制、来源信息与脚本执行边界继续有效，不因复用弹窗而绕过。
- 只有作者可编辑并发布自己创建的作品。上传、导入、安装或本地保存本身不能作为作者归属证明；第三方扩展保持原始来源与归属，安装不授予编辑和重新发布权限。
- 编辑页与聊天关联同一份草稿；往返、继续修改与重新打开应保留内容，查看草稿打开最新版本。具体持久化与同步接口在技术方案中确定。
- 保存、预览与发布是不同动作。草稿未发布前仅作者可见；已发布内容的新修改先保留为草稿，作者再次确认发布后才对其他用户生效。发布失败保留草稿及既有公开版本，并允许重试。
