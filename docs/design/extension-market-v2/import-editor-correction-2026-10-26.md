状态：代码已接入；未执行验证，待用户真机验证。本轮是用户已确认流程的纠错，不重新设计页面，不改变后端或导入数据结构。

## 纠正的实现

1. 上传插件/技能包不再使用 Android `FileType.any`。复用已有 FilePicker 的 custom 类型和服务端允许格式；Android 将 `tar.gz/tgz` 映射到可识别的 gzip 类型，将 `.skill` 同时映射到 ZIP 类型，避免未知/复合后缀导致整个筛选回退为所有文件。没有可识别类型时停止选择并提示，不放宽为通配符。
2. 技能的 Markdown 使用 md/markdown 后缀映射；插件不加入文本类型，不额外加入 TXT、二进制或所有文件通配符。映射只服务于系统筛选，选择后的文件名、大小、服务端内容检查仍采用原始允许后缀；TXT、单独 GZ、图片、视频、PDF 不因此获得导入资格。
3. 详细介绍扩展只在固定弹窗内部给正文更多空间：收起“介绍内容”辅助标签及底部说明，正文填满可用编辑区；弹窗宽高、坐标、标题及完成按钮保持不变。收起后恢复辅助内容和原画布尺寸。复用主输入框的 220 ms 收展节奏及已有 SVG，支持减少动态效果。
4. 正文始终使用同一个文本、焦点、滚动控制器；展开不新建页面、不保存数据、不自动弹键盘。返回先收起画布，完成返回资料；键盘仅影响正文可见视口，继续遵守空输入收键盘失焦与按钮单次点击规则。

- [Android 官方文件选择说明](https://developer.android.com/training/data-storage/shared/documents-files)（查阅 2026-10-26）：系统按 MIME 类型筛选，无法精确区分同一类型的每个后缀。Markdown 识别为普通文本时可能同时显示 TXT，压缩包也可能出现相同 MIME 的其他后缀；客户端仍严格拒绝不在原始策略内的文件。`.skill` 若被文件提供方标成未知二进制类型，其可见性仍依赖提供方元数据；本轮不加入二进制或所有文件通配符掩盖该限制。
- 普通/扩展两态使用相同外框测量公式。2026-10-25 记录中“整个介绍弹窗放大”的行为，以及 Android 显示所有文件的决策被本轮纠正覆盖。
