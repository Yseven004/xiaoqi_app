# 创建弹窗：三张定稿实施与验收

日期：2026-10-24。以本节最终交互为准，覆盖同日早期“完成后返回创建页”的方案。

## 冻结范围

1. 导入插件／技能和独立 MCP 是两份编辑状态、两个草稿 ID；默认选中导入页，上传与 GitHub 同时展开。顶部切换按钮位于滚动内容之外。
2. 导入框在空态和文件态均使用虚线；文件态展示文档／压缩包图标、名称、真实原始大小，右上角只有小 × 删除。文件与 GitHub 互斥，删除来源后才能切换。
3. 从插件／技能文件中识别出的 MCP 是该内容的依赖，配置区内嵌、可折叠；无声明时不渲染标题、分隔线或占位，也不为它增加弹窗高度。
4. 常驻 MCP 切换页独立走添加内容、补充资料、确认。成功测试后原位用小型绿色勾及文字替换测试按钮；测试按钮为方圆矩形，地址为空不出现。错误在地址／令牌对应字段显示。
5. 两页都存在配置信息时，下一步及发布均阻止并显示错误；用户清空其中一页后才能继续。文件中内嵌的 MCP 依赖不算第二份配置。

## 数据修复与边界

- 文件移除同步清除编辑器内容、声明、就绪状态，防止只删卡片却提交旧文件。来源变化先使读取结果失效；新来源失败或取消替换不覆盖上一份已检查内容。
- 切换页面分别保留文件、字段、步骤、MCP 测试结果；这些编辑态只在当前创建流程中保留，不自动写入草稿。只有明确点击「保存草稿」才持久化；直接关闭或取消会丢弃本次未保存修改，并保留打开前已有的草稿版本。确认发布仍按既有流程持久化并提交。草稿恢复核对账号、ID、kind 和创建模式。
- `CapabilityDraft.creationMode` 与 `importSource` 仅是本机元数据，网络序列化排除；保存导入来源类型、原始大小和 GitHub URL，避免恢复时丢失卡片。云端同步落回本机时保留这些字段。
- 草稿同步拒绝 ID／kind／账号不一致；同一草稿不能被其他类型覆盖。技能聊天预览查询过滤插件，避免插件草稿混入技能修改链路。
- 已有草稿保留，不做批量删除或重分类。旧草稿未记录原始包大小时显示“原始文件大小未记录”，不把解压大小冒充原始大小。
- 令牌仍只进系统安全存储／本人私有连接；服务器地址变化清空旧令牌及测试结果，防止凭据跟随新服务器。没有改变服务端接口或 API 合约。

## 已发布作品的编辑入口与恢复（2026-10-24 追加）

- 公开列表及公开详情移除「编辑技能／插件」，本人发布的作品也从「个人」进入编辑。
- 个人列表与个人详情仅本人创作的 `origin=local` 作品开放编辑；安装的 GitHub、上传安装及市场第三方作品不提供编辑，并在编辑入口和数据转换处拒绝绕过。
- 编辑以作品当前版本为准，恢复正文、完整附件、名称、简介、详细介绍和图片。已保存的作者草稿仅补充原始上传来源、大小和创建模式，旧草稿正文不能覆盖作品当前版本；显式点击草稿仍继续编辑该草稿。
- 上传卡片与编辑器在打开前使用同一份恢复数据初始化，不在编辑画布展示版本号；版本号由系统在发布时自动更新。历史记录缺少原始包大小时保留「原始文件大小未记录」提示，不根据解压文件伪造原始大小。完整版本缺失时提示同步，不进入空白编辑器。
- 插件／技能导入使用服务端当前允许的扩展名配置系统文件选择器；技能可选 SKILL.md 与支持的压缩包，插件只列出支持的压缩包。显示和上传前验证使用同一份扩展名列表。
- MCP 恢复已保存的独立画布和服务器地址；再次测试时通过本人私有连接 ID 复用凭据，不读取或展示令牌，也不把旧测试结果冒充新的连接成功。
- 只有「保存草稿」和「确认发布」持久化修改；编辑中的版本在明确确认发布前不会改动公开版本。服务端既有账号归属与作品类型校验保持有效，本次不修改 API。
- 本次验收：29 项定向回归通过；静态分析无 error，保留 1 条原有未使用方法警告和样式提示；Debug APK 构建成功（构建日志 `.codex-artifacts/published-edit-build.log`）。菜单、数据恢复和 MCP 私有连接复用已做 widget／mock 验证；未执行同状态截图对比和真机验证，待用户真机验证。server deployment not needed：仅修改 Flutter 展示与编辑数据初始化，没有修改服务端或 API 合约。

## Layout Spec 与素材

视觉目标是用户确认的三张生成图（1024×1536），追加修正为虚线导入框。实际截图 viewport 834×1251（相同比例，DPR 1），使用项目 NotoSansCJKSC 字体；另以 390×844 检查手机无溢出。

| 项目 | 实际约束 | 对照与限制 |
| --- | --- | --- |
| 弹窗宽 | 可用宽 80%，最大 670 dp | 三张生成图的外框宽度略有不同；实现保持一致宽度 |
| 平板顶部 | 可用高度的 23.5% | 手机使用 24 dp 顶距，避免小屏过度压缩 |
| 外框高度 | 普通导入与独立 MCP 均为 1.04×宽；依赖 MCP 1.48×宽，均受可用高度约束 | 834 viewport 下分别约 694／933／694 dp；无 MCP 不预留配置高度 |
| 固定入口 | 高至少 52 dp；间隔 10 dp；圆角 9 dp | 当前页黑边选中，另一页浅底；滚动时坐标不动 |
| 导入卡片 | 宽高比 3.75，最小高 150 dp，圆角 16 dp | 虚线为用户追加确认，与原生成图实线不同 |
| 字段／测试 | 字段圆角 12 dp；测试按钮圆角 8 dp、高 48 dp | 成功为 24 dp 图标加 18 dp 绿色文字，无绿色背景块 |
| 底栏 | 固定分隔线；左取消、右下一步 | 首步按钮 52 dp 高、18 dp 字 |

复用现有 `file-text.svg`、`upload-document.svg`、`upload-border.svg`、GitHub 标志和关闭图标。全局 MCP 连接器资产复用项目 Phosphor `share-network.svg` 的三节点路径并旋转 90°，不再使用插头形。ZIP 和成功图标均为独立 SVG，不使用截图裁片；ZIP 字母用矢量路径，避免 Flutter SVG 文本不支持。资产清单见 `asset-catalog.md`。

## 分层结果

### 最新交互覆盖：上传预校验与读取失败

- 本条覆盖旧版“读取无论成功失败均显示绿色下一步”：只有读取成功才显示绿色下一步；失败显示字段错误，按钮为黑色“重新读取”。独立 MCP 仍沿用已确认的连接测试与下一步逻辑。
- 选中文件后先根据当前服务端限制校验格式、空文件及大小，再替换当前来源；失败仅在上传区下方显示具体红字，保留之前有效文件，不新增“正在检查文件”状态。插件不接受 Markdown；技能允许策略支持的 Markdown 与压缩包。文件选择器仍可浏览全部文件。
- 读取内容承担包结构、类型及内容识别；未识别到扩展或单一不支持候选时显示明确错误。上传后是原文件名，读取通过才采用识别名称。
- 20 项定向测试通过，包含格式、空文件、超限、插件拒绝 Markdown、双扩展名、大小边界与失败后重新读取不出现下一步。替换失败保留原来源通过校验顺序代码核查；系统文件选择器与真机操作未执行，待用户验证。日志：`.codex-artifacts/creation-upload-validation-test.txt`、`creation-upload-analyze.txt`。
