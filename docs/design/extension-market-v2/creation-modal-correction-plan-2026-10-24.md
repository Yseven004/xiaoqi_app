## 2. 五项优先修正

| 优先级 | 当前偏差及影响 | 修改方式 |
| --- | --- | --- |

## 3. 第一步应恢复成什么样

从上到下依次为：创建标题与关闭、说明「先添加内容，资料可以稍后补充」、连续三步进度、并列的导入与连接 MCP 入口、来源区和固定底栏；只有在技能／插件内容声明需要 MCP 时，才插入「已识别 MCP 服务」折叠行及其字段，不为它预留空白。

上传区不能靠缩小全部文字来容纳额外控件。以插件确认图为例，其上传区宽高接近 2:1，录屏里接近 3:1；释放 AI 和编辑横条占用的空间后，优先返还上传与输入区域。同一设备上的精确 dp、外框位置和字号应通过同 viewport 实际渲染确认，不能把生成图像素直接抄成 dp。

### 固定底栏的状态规则

| 状态 | 左侧操作 | 右侧唯一主操作及行为 |
| --- | --- | --- |
| 尚未选择文件／填写来源 | 取消 | 「读取内容」维持相同位置和尺寸，使用不可用态；不显示可点击的下一步 |
| 有文件或有效 GitHub 输入 | 取消 | 「读取内容」，执行已有来源检查和内容解析 |
| 正在读取 | 使用已有安全取消机制 | 同一按钮显示「读取中…」，防止重复请求；不跳页面 |
| 读取失败／无可用内容 | 取消 | 保留输入和选择，局部显示原因；允许重新读取 |
| 多个候选／需要确认支持范围 | 取消 | 在本步展示必要的候选及警告；先选定、校验，再将当前内容标为可进入下一步，不绕过既有检查 |
| 已读取并应用内容 | 取消 | 同一按钮变为「下一步」，用户点击后才进入资料页；可显示紧凑文件名／来源摘要，无需增加成功说明墙 |
| 更换文件／修改 GitHub 来源 | 取消 | 旧读取状态失效，主按钮恢复「读取内容」；替换既有草稿仍保留原有确认保护 |

纯 MCP 插件允许只提供连接配置。这里的「读取内容」负责校验并应用连接声明；区内「测试连接」保持独立，不把测试、保存和发布合并，也不新增“所有插件都必须测试成功”的要求。修改服务器地址或凭据后旧测试结果失效。

### 局部样式建议

这是对现有灰阶令牌的复用建议，不新增全局设计系统；最终以同状态定稿对照为准。

| 元素 | 目标 |
| --- | --- |
| 弹窗／编辑画布 | 白色 `#FFFFFF`；通过细分隔线组织，减少多余卡片和说明 |
| GitHub、MCP、名称与简介字段 | 复用 `marketSoft`：`#F4F4F4`；默认边框弱化，适度圆角，输入内容保持深色；GitHub 添加链条前缀。避免外部已有标签、内部再浮动重复标签 |
| 主操作 | 复用现有深色 `#1D1D1D` 与白字；适度圆角矩形，替换底栏默认 `radius: 99`；读取、下一步和确认发布各状态尺寸稳定 |
| 次操作 | 浅灰填充、深色文字；不使用透明描边胶囊作为本弹窗默认样式 |
| 焦点、错误、触控 | 焦点边界清楚，错误靠近相应输入；不能为还原“无边框”去掉焦点。图形可以小，触控区域仍至少 48 dp；错误不只靠红色表达 |

主要操作应由创建弹窗负责，导入区仅渲染输入、检查结果及必要选择。现有底栏虽设置 `WrapAlignment.end`，其父 `Column` 没有将底栏横向撑满，录屏实际呈现居中小按钮；应明确使用全宽操作区，将左侧次操作与右侧主操作排开，不能只调整 `alignment` 值。

## 4. 三步与展开编辑态的统一修正

| 页面／状态 | 保留的已确认行为 | 本轮修改与验收重点 |
| --- | --- | --- |
| 第二步默认资料 | 图标与名称同排；简介可直接改；详细介绍和图片默认收起 | 对齐灰底字段、名称／简介层级、图标编辑角标和分隔线；底栏改成左上一步、右下一步。文字密度和留白以定稿同状态测量，不增加新字段 |
| 原位展开查看 | 展开只读内容，其他资料仍在；同一弹窗内滚动 | 明确查看和编辑入口。展开标题本身不进入专注编辑；点编辑／上传才切换内部画布。保留草稿及返回后的展开／滚动状态 |
| 详细介绍专注编辑 | 同一外框；仅返回、标题、完成与正文画布；其他资料及步骤隐藏 | 「完成」改成定稿黑色小圆角矩形；正文使用完整白色画布，覆盖通用表单的轮廓／填充样式，加入顶栏细分隔。正文与键盘在内部适配，不能伸缩或移动整个外框来容纳输入 |
| 图片横向专注编辑 | 默认横向；末尾虚线添加框；最后一张的比例；无图 3:4；说明及排序 | 将 `_gallery` 的固定 200／280 高度改为按专注画布剩余高度分配，预留说明／排序和可见滚动条；图片保留原比例。删除恢复为每张右上角灰色圆形关闭控件，避免图片下方再塞红色垃圾桶工具栏 |
| 图片网格与布局菜单 | 与横向模式共用图片、顺序和说明；布局图标无下拉箭头 | 网格保留拖动排序，避免默认额外前移／后移按钮挤占说明栏；为无障碍需要保留等效排序能力。布局按钮位于完成左侧；紧凑菜单左图标、中文字、右侧勾选，复用已确认左右并排 SVG；控件外观不要沿用默认大菜单 |
| 第三步确认 | 只读详情；上一步、保存草稿、确认发布；发布前后跟随图片排版 | 标题下显示「仅自己可见 · 尚未发布」，替换“确认内容后发布”并删除内容区重复状态。底栏左侧上一步、右侧草稿及黑色确认发布。检查所有编辑、添加、删除、排序按钮均不进入只读预览 |
| MCP 原位展开、成功、失败 | 配置字段在首步展开；输入保留，测试不保存不发布，重复测试受限 | 同步浅灰字段和局部错误样式，展开时仅内部滚动使字段可见；令牌明确可选且私有，已有令牌留空保留规则继续有效。失败后按钮文案「重新测试」，成功仅简短「连接成功」；常驻连接入口进入独立 MCP 画布，返回后保留来源状态 |

图片布局、无图 3:4、末图添加框、默认折叠和只读展开等能力在当前代码已有基础，应保留。编辑画布和展示画廊共享图片与排版数据，但不强求二者具有相同展示高度：编辑应充分利用画布，预览可使用定稿里的画廊高度。

固定图形优先复用现有独立 SVG。若右上角删除等控件缺少忠实资产，按已确认轮廓补独立 SVG，先做实际尺寸／64 px 预览和资产登记；不从截图裁切图标，也不以近似 Material 图形替代定稿。

## 6. 验收顺序与完成标准

先批量完成这一轮修改，再集中检查；最多一次首轮检查和一次修正后的确认，避免无边界微调。

1. **第一步闭环**：技能与插件空态、文件／GitHub 读取、必要候选选择、失败／重试、取消、读取成功停留、手动下一步、改来源后重新读取，以及 MCP-only 路径。首屏只有定稿允许的区块和一处主推进操作。
2. **资料与编辑闭环**：折叠→原位查看→真正编辑／上传→完成／返回，名称等资料保留；所有状态同一外框。横向／网格切换、排序、删除、说明、添加框末图比例和删空后 3:4 都要覆盖。
3. **确认与持久化**：隐私状态、草稿保存和恢复、发布前后图片排版一致；失败保留内容，确认页不出现编辑控件，保存草稿不等于发布。
4. **视觉与可访问性**：按目标设备相同逻辑 viewport、主题、字体缩放和状态拍图；先比弹窗内部几何与控件，再比色彩和字体。验证键盘、系统返回、焦点、触控区域以及长标题／长错误。首步、资料、两种专注编辑、确认与 MCP 结果一次覆盖。
5. **分别记录完成情况**：代码修改、静态／自动化检查、同状态视觉对照、目标设备验证分开报告；通过 widget 测试不等于符合确认稿，源代码存在不等于真机通过。

## 7. 独立评审结果与限制

整体判断：技能／插件共用固定弹窗、连续步骤、GitHub 入口和 MCP 折叠位置已有可复用基础；当前外观仍明显受通用表单和胶囊按钮默认样式支配，未完成针对已确认创建流程的还原。主要情绪断点在首步：最强的“下一步”会引出“先读取内容”的错误；首屏应给用户明确可完成的准备动作，末尾再让用户主动推进。

认知负荷：首屏同时提供选择文件、读取、编辑内容、AI 编写、下一步，插件再加 MCP 配置，超过四个并列动作。收敛后只需识别上传或 GitHub；插件用户按需要填 MCP，再执行固定底栏动作。新用户的红旗是“不知道先点哪个”，注意力易分散用户的红旗是“AI 区把当前任务打断”，有经验用户的红旗是“重复推进和小按钮增加操作”。

## 8. 本轮实施补充（2026-10-24）

按用户最终确认，首步固定并列显示“导入技能／插件”和“连接 MCP 服务”两个入口。文件与公开 GitHub 是互斥来源，选定其中一个后禁用另一个，先移除来源才可切换；MCP 是可叠加组件，可以和任一内容来源共存，也可以作为纯 MCP 插件完成。未从技能／插件内容中识别到 MCP 声明时，不渲染下方配置区也不预留其位置；识别到 `.mcp.json` 或等效声明后才插入“已识别 MCP 服务”下拉区。点击常驻的“连接 MCP 服务”进入独立画布，返回后保留来源与读取状态。

文件选择器使用系统的全文件视图，回选后仍由服务端上传策略校验扩展名和容量。读取成功卡片只显示解析出的技能／插件名、来源文件大小和对应类型图标；读取失败保留来源、错误和重试入口。读取完成或失败后底栏都保留绿色“下一步”，失败时点击会回到对应错误输入，修正并成功后可继续。

MCP 测试按钮只在服务器地址非空时出现；成功只显示小型绿色勾和“连接成功”文本，不使用整块绿色背景。失败在地址或令牌字段附近显示错误。首步导入组件保持挂载，前进后退不会清除文件、大小、解析结果或来源选择。详细介绍专注态继续使用无边框正文画布，图片专注态按剩余高度布局并将拖动柄与说明同排，布局菜单勾选固定在右侧。
