日期：2026-10-24（Asia/Shanghai）。更新：2026-10-25。状态：用户已附图确认底部状态带并授权实现；其余两个方向不采用。实现及验证记录见[修复计划](../../plans/2026-10-24-draft-save-refresh-fix.md)。

## 设计目标

让用户立即回答两个问题：**这次修改保存了吗？现在能做什么？**

范围仅为技能／插件三步创建弹窗的保存反馈、同步异常及恢复操作。保留现有弹窗外框、位置、尺寸、三步结构和主操作顺序。沿用手动保存边界，不增加自动保存。

本轮参考为用户提供的 1080×1728 截图。截图实际反馈是本机保存成功、云端同步发生冲突；不能把它笼统叫作本机保存失败，也不能在没有证据时归因为另一设备。

## 为什么当前呈现混乱

| 当前问题 | 调整原则 |
| --- | --- |
| 把本机成功、云端失败、冲突原因和恢复建议拼成一条长红字 | 先说保存结果，补一句原因，按需展开详情 |
| “重试”和“另存”按独立条件堆叠在正文与底栏之间 | 同一状态只使用一个反馈区域；恢复操作跟对应提示成组 |
| 版本冲突仍给普通网络重试 | 网络错误提供重试；内容冲突提供处理入口 |
| 冲突后“确认发布”仍呈绿色可操作 | 状态与按钮联动，禁用时就近解释原因 |
| 反馈缺少固定位置 | 成功、等待、失败使用同一个位置，不因状态变化移动弹窗 |

## 共同状态规则

| 状态 | 主文案 | 补充说明／操作 | 发布 |
| --- | --- | --- | --- |
| 尚未保存 | 有未保存修改 | 保存草稿 | 先按既有发布流程保存与校验 |
| 本机正在写入 | 正在保存… | 保存按钮防重复；以这次点击的快照为准 | 本机写入完成前不可发起 |
| 本机成功、云端进行中 | 已保存在本机 | 正在同步；继续编辑及退出不等待网络 | 等待当前已保存快照同步 |
| 全部成功 | 草稿已保存 | 最近保存时间可在详情查看；短暂成功提示使用现有 AppToast | 内容及权限校验通过后可发布 |
| 真正本机写入失败 | 未保存成功 | 当前内容仍在，请重试。操作：重试保存 | 禁用，不能假称草稿安全落盘 |
| 本机成功、网络同步失败 | 已保存在本机 | 暂未同步，联网后可重试。操作：重试同步 | 禁用并说明需先同步 |
| 内容版本冲突 | 云端版本有变化 | 本机内容已保留。操作：处理同步 | 禁用并说明先处理同步 |
| 云端已删除 | 云端草稿已删除 | 本机内容已保留。操作：另存草稿 | 不自动恢复原 ID 或发布 |

以上是状态映射表，不表示要同时展示全部状态。主页面同一时刻只显示与当前草稿有关的一条反馈。修改内容后，未保存状态必须及时恢复；旧保存成功不能覆盖新修改的状态。

## 操作规则

1. 点击“保存草稿”：先保存点击时的本机快照；成功后留在当前步骤，显示明确保存结果，后台同步独立执行。只在真正本机保存失败时显示红色“未保存成功”。
2. 点击“重试同步”：同步最后已保存的版本；不偷偷持久化当前表单里的新修改。重试期间原位置显示“正在同步”，不增加第二组按钮。
3. 点击“处理同步”：进入有明确标题的局部处理视图，提供“保留为新草稿”和“查看云端版本”；查看不等于替换，替换前确认并保留本机内容的退出路径。
4. 关闭有未保存修改的弹窗：建议提供“保存后退出／不保存退出／继续编辑”。保存后退出只等待本机写入，失败则保留弹窗。此项需确认后更新现有“直接关闭丢弃”的规则。
5. 状态恢复：原位置收起错误与操作，清除过期冲突标记；不得残留“已同步”与“处理冲突”同时出现的状态。

## 保持的设计约束

- 黑白灰与既有成功绿保持一致；冲突用中性或克制的暖色提示，真正本机保存失败才使用明确错误色。
- 复用现有按钮和 SVG 系统，概念图不是正式 UI 素材；确认后再按资产规则整理接入。
- 状态不只靠颜色；恢复入口有明确文字、足够触控区域和可访问名称。重要变化播报一次，不能重复播报。
- 点击保存、关闭或其他按钮应当次执行；遵守空输入收键盘失焦及输入框之间正常转移焦点的全局规则。
- 弹窗不随错误增高或移动；长说明在内部处理视图呈现，不堆在底栏外。页面加载不用转圈过渡。
