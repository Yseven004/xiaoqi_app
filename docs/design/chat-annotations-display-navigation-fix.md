## 冻结目标

- [用户选定的原图](chat-annotations-display-navigation-reference.png)：853×1844 像素，作为组件视觉参考，不是目标设备截图，不从像素尺寸推断设备 dp。禁止将此图作为页面或控件素材。
- 详情横向居中，手机宽度约可用宽度 82%，平板上限 480dp，圆角 18dp；纵向位置沿用选图中下部的留白关系。高度随内容变化，上限可用高度 70%，标题和关闭按钮固定，条目内部滚动。
- 纯注释消息只有计数胶囊，不嵌进淡紫色正文气泡；混合输入保留真实文字。若有附件，顺序为附件、注释胶囊、正文气泡；注释胶囊始终位于正文上方。
- 每条详情依次为蓝色“注释 N”、加粗“所选文本：”、完整引用、加粗“评论：”、完整评论。图片条目使用“所选图片：”和既有点位数据，不改图片标注流程。
- 已发送详情只读；待发送可编辑、移除，删除后仅重新排列草稿编号。保存后的消息快照、编号与来源保持固定。同一 AI 回复的多个注释段共用一个操作栏。

## 数据与运行边界

- `AiConversationMessage` 新增本地 `displayText`、不可修改的 `annotations` 快照及 `capabilityTagOrigin`。原 `text`、`capabilityMetadata` 和 `capabilityScopeOperation` 继续承担原有执行语义；新增字段不拼进能力元数据或后端接口。
- 发送、编辑重发都从真实输入重新生成模型正文，避免注释说明重复拼接。编辑取消恢复之前的注释和输入草稿；发送失败恢复原编号和本次挂载来源。
- 对旧消息执行只读展示投影。只有完整匹配旧序列化格式并通过重新序列化校验时才折叠正文；来源必须在祖先消息中唯一出现才能恢复来源 ID 和摘要。歧义、损坏或无法识别的正文保持原样，不覆盖原始记录。
- 显式选择与任务继承分开记录。只有显式选择显示消息标签；发送后的自动保留、会话恢复、版本切换均标为继承。再次主动选择同一项仍显示标签。旧“创建／修改技能”仅在无原始插入位置且祖先消息证明同一任务已启动时隐藏重复标签。
- Agent 工具决策、权限、能力作用域和服务端 API 契约不变。客户端只为当前注释消息增加回复格式说明，不新增强制工具调用或权限。

## 回复与定位

- 模型按编号逐段回答，每段末尾附普通可见来源文字 `【注释 1】`，客户端原位转换为绑定本条用户消息 ID 的蓝色“注释 1”链接。每段各自绑定，同一注释的多个段落可重复引用。旧版小节标题及私有标记根据原有明确小节归属移到小节正文末尾。禁止添加全文末尾的“相关注释”汇总；缺少明确绑定的正文不由客户端猜测补号。复制时保留段尾可读编号。
- 链接点击再次检查所属用户消息和编号边界。未知、溢出、残缺标记不生成来源链接；代码块和行内代码中的样例标记保持文字。流式输出读到完整段尾来源时即可转换，不集中搬移到回答结尾。
- 定位使用来源消息 ID、内容 SHA-256、选区起点和引用文本。正文有独立布局锚点，排除思考面板和操作栏。先根据行索引、已测高度缓存寻找未渲染的目标，再根据正文真实文字矩形精确滚动。
- 保留惰性列表，不将整段历史常驻内存；估计高度校正后等待布局稳定再确认。定位最多修正 48 轮，用户拖动、切换会话或分支可取消。停止跟随最新回复，防止生成过程把用户拉回底部。
- 原文定位后淡蓝高亮约 2 秒，不创建待发送注释或永久点位，不调起键盘；尊重系统减少动画设置。来源删除、摘要变化、分支不可见或布局未找到时使用既有 `AppToast` 提示，引用快照仍可查看。
- 复制、分享、做笔记使用可读标题，避免导出内部标记。

## 输入与焦点

- 打开详情、点击来源链接时退出当前输入焦点并保留文本；按钮当次点击执行，详情不自动打开键盘。
- 评论编辑仍由明确点击触发。空输入收键盘须失焦；有内容仅收键盘不强制失焦，不清空内容；点击另一输入框正常转移焦点，不得被后续布局重新抢焦点。
- 选区旁的评论输入浮层随键盘 inset 变化，将整个输入控件限制在键盘上缘与安全区之间；不会因来源行靠近屏幕底部而被 IME 覆盖。
- 页面和定位不增加转圈加载态。

## 后续修正：可见回复标题与键盘避让（2026-10-26）

- 早先怀疑 Genkit 最终答复“不输出内部协议”的要求会影响私有标记，因此改为普通可见编号。用户随后明确拒绝“相关注释”汇总，当前实现已删除这一回退。
- 锚点评论框原先只依据原文坐标放置，没有可用滚动位置时无法避开软键盘。现随 `viewInsets` 把输入框顶部夹在安全区与键盘上缘之间；不会触发强制滚动或修改原文位置。
- 混合文字与注释现在按“附件（如有）→ 注释胶囊 → 正文气泡”展示。
- 组件与真机验收沿原分层要求执行；真实模型、同屏截图及设备行为仍由用户验收。

## 段尾逐条对应修正（2026-10-26）

- 用户以 Codex 截图确认为“第一条答复……注释 1；第二条答复……注释 2”，链接紧跟各自段落，不在全文末尾汇总。
- 进一步发现续接远端 Agent 会话时只发送当前用户消息，历史开头的排版系统提示只在新会话初始化时传递。现在在发送当前消息给 Agent 前加入本轮的编号范围和段尾格式要求，覆盖会话续接、编辑重发及继续生成。附件内容、真实 `current_turn_text`、能力元数据及本地原始正文保留；未改服务端或 API。
- Markdown 仅转换完整、合法、明确绑定的段尾编号；旧版明确小节标记按所属正文迁至小节末尾。无编号的旧回答保留原文，不统一补链接；要获得逐段对应需重新生成该回答。

用户验收路径：发送 1 条注释 → 打开详情 → 发送含 2 条注释的消息 → 查看逐段蓝色标题 → 点击标题回到对应原文 → 连续发送“？”检查无继承标签 → 主动再选同一技能检查标签显示。追加检查重开会话、编辑取消／重发、失败恢复、旧消息、删除来源、字体放大及键盘收起。
