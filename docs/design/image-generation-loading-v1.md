# 生图加载视觉 V1

状态：目标图已确认并完成 Flutter 接入；动效、网格及协议边界已按 [V2 修复记录](chat-generation-motion-v2.md) 更新。Flutter 同 viewport 视觉对照与 Android 真机验收待用户完成。

## 范围与状态

- 目标：聊天回复中的生图占位区；保持现有 3:4 比例、最大宽度 480 dp、14 dp 圆角及周围聊天布局。
- 加载中：顶部状态标题继续表达“正在生成图片”；图片内部呈现均匀流动、缓慢呼吸的浅蓝、淡紫和青绿色柔光，并覆盖低对比度的 4 dp 方格像素纹理。
- 加载完成、失败或取消：移除加载占位，现有结果和任务反馈流程不变。
- 移除占位图片下方重复的“正在生成图片...”文案。
- 动效尊重系统减少动态效果设置；无动画时保留静态柔光和网格。

## 视觉与动效验收

- 渐变覆盖整张占位图：蓝 `#DDEBFF`、淡紫 `#EEE5FF`、青绿 `#DDF3EF`；流动变化平缓、混色均匀，不出现强烈的单一光团或图片外溢。
- 方格保持规律、细小且低对比度，圆角裁切与图片边界一致。
- 屏幕只有顶部一处生图状态文案；未使用页面路由转圈过渡。
- Flutter 同 viewport 实际画面、截图对照及 Android 真机体验仍待用户验证。

## MCP 自动接入规则

- 原生生图直接调用内置图片服务，不依赖 MCP，也不触发 MCP 连接器。
- 普通任务只向模型提供已安装连接器的名称和目录描述；只连接模型判定与当前任务直接相关的连接器，最多 8 个。凭据、URL 和令牌不进入筛选请求。
- 用户明确选择的连接器仍按原流程连接。连接阶段和工具执行阶段使用各自状态名称，避免把连接失败显示为“MCP 工具失败”。
- 自动筛选失败时不连接所有候选项，记录不含请求或凭据的错误类型，并继续当前任务。
