# 小栖技能 / 插件 V1 已确认交互规格

## 交互外观基准

技能菜单以用户确认的原始左图为视觉基准，并按后续反馈收窄菜单卡片、移除底部小尖角。技能 / MCP 胶囊匹配阅读任务胶囊当前尺寸与材质；阅读任务胶囊本身保持原样。胶囊总布局高度为 56dp：48dp 触控区加 8dp 透明底部留白，使玻璃背景在同一 Row 中与阅读胶囊等高对齐；按压涟漪半径、颜色与高亮也复用阅读胶囊。主菜单是技能胶囊正上方的白色锚定卡片，中心与胶囊中心对齐（受屏幕边缘限制时贴合安全边距），卡片宽度按视口的 40% 收缩，最小 210dp、最大 240dp；内容整体距左右边缘各 16dp。管理面板保留原有 48%、220–320dp 尺寸。菜单包含四个带 SVG 图标的功能入口、实际保存的技能 / 插件分组及底部管理栏；空分组隐藏。阅读任务菜单上限为 240dp。尺寸按 Flutter 可用视口、安全区和键盘空间适配，不能将截图物理像素直接当 dp。

技能与插件采用用户确认的 Codex 输入栏标签表现：标签位于可编辑文本流中，由侧边栏扳手图标和能力名称组成；能力名称使用浅粉色强调，输入标签保留中粗字重；标签位于半透明渐变、细亮边和柔和阴影的圆角容器中，不显示关闭按钮。已发送气泡中的能力标签使用同一扳手图标、浅粉色能力名称和圆角阴影容器；已保存技能 / 插件菜单条目复用该扳手，尺寸为 18 dp，菜单卡片名称保留原色。“创建技能 / 插件”功能行和底部胶囊继续使用拼图图标。标签可用光标、退格、Delete 和触屏选择整体移除。点击“创建技能 / 插件”直接把创建标签插入输入栏，不弹创建类型窗口，插入后不自动聚焦输入框或弹出键盘。含正文时标签与正文一起发送；只有标签时也允许发送。参考当前 UI 稿见 [skills-plugins-v1-review.svg](skills-plugins-v1-review.svg)。

V1 沿用当前消息模型的单个能力元数据字段：每条消息保留一个能力标签；从菜单再次选择时替换输入栏中的待发送能力标签。标签的位置和身份随对话消息存储，并在编辑消息时恢复。多标签协议暂不加入本次实现。

### 创建图像与对话生图

- 选择“创建图像”后插入 `type: action, id: create-image` 能力标签，保留输入正文并关闭菜单；能力身份随现有消息元数据保存、编辑和恢复。
- 任务请求在现有 `capability` 字段发送 `{type: "action", id: "create-image"}`。服务端将它作为内置动作处理，不读取同名已保存技能；该动作只开放 `generate_image`，每次固定生成一张图，并用中文简短说明。没有文字描述时直接追问，不调用图片 API。
- 普通会话只在明确要求生成/编辑图片、“用图说明 / 生成示意图”，或询问“能否生成图片”这类能力问题时开放生图工具。能力问题先简短回答“可以”，再生成一张示例图；普通解释不触发生图。
- 任务失败时服务端保留错误代码和脱敏诊断，并在失败事件中返回具体原因；客户端收到失败事件后回查任务详情，在弹窗中显示可操作原因、诊断信息和任务编号，不以固定“检查服务端配置”文案覆盖底层错误。
- 后端 `ImageService` 已调用 Ark Seedream API，并默认使用 Seedream 5.0 Lite（模型 ID：`doubao-seedream-5-0-260128`）。火山引擎文档将 `doubao-seedream-5-0-lite-260128` 标为即将下线的别名，因此采用仍列出的模型 ID。部署需由服务器运维人员在 `single-server.env` 配置 `ARK_API_KEY`；密钥只保存在服务器环境文件，不能写入客户端或仓库。图片 API 超时不自动重试。
- 图片继续走任务附件事件、聊天预览和现有会话持久化。2026-10-10 已用配置密钥完成一次 Ark 真实出图与图片下载（HTTP 200）。同日通过阿里云 CLI 将 `api.dart`、`agent_runtime.dart`、`image_service.dart` 更新到目标 ECS 并重建、重启 Genkit 容器；新容器健康，公网 `/health` 返回 HTTP 200，运行容器已读到 Ark 配置，数据卷清单部署前后匹配。源码、旧镜像和数据卷备份保存在服务器 `/opt/xiaoqi-single-server/backups/create-image-remote-update-20261010-154344`。Android 真机生图闭环仍待复测。

### 对话生图链路与展示（本次确认）

- 明确要求配图的自然语言请求（包括“先解释，再加一张图片帮助理解”）必须进入生图链路。此前普通问答关键词判断会把含“原理”等词的复合请求提前排除；漏判后，Genkit Agent 又没有可用的生图工具，因此模型只能把图片要求写成 SVG / 代码文本。修复后，复合请求会向 Agent 提供受控的 `generate_image` 工具；若 Agent 没有调用，服务端仍会调用现有 `ImageService` 保底生成，避免工具选择结果决定图片是否存在。纯图片请求继续由服务端直接调用图片服务。
- 生成中的聊天消息显示 3:4 轮廓和轻微呼吸、缓慢流动的淡色光晕，状态文字只显示“正在生成图片...”。图片完成后在对话中直接显示原图比例的图片，不显示附件文件名、大小和下载卡片；点击图片打开可缩放预览，并可从预览中下载。非图片附件保持现有卡片样式。
- 图片提示词未指定画幅比例 / 尺寸时追加竖版 3:4 要求；用户写明比例、宽高或方向时保留用户要求。现有 Ark `size` 参数表示分辨率档位，继续使用现有 2K 默认值，不把比例误传为分辨率参数。

## 已确认的操作状态

1. **试用后保存**：先在对话展示代表性试用结果，再在输入框上方提供「直接保存」「修改后再看」。保存评审中「在胶囊中显示」默认勾选，可取消；正式版本只由用户操作创建。
2. **修改草稿**：用户在同一个对话输入框描述建议，再选择重新生成并试用；保留上一版草稿。新结果仍由用户决定是否保存，不直接覆盖正式版本。
3. **管理我的能力**：同一轻量面板按技能、插件分组并展示真实保存条目；提供展示开关、修改与二次确认删除。关闭展示只影响菜单显示，不影响 AI 的技能摘要发现。
4. **冲突 / 离线同步**：同一面板后续提供「分别保留为草稿」「查看两个版本的差异」「稍后处理」。断网时保留本地草稿并标记待同步；冲突时不静默覆盖。

当前实现：本地草稿、不可变技能版本、展示开关、删除标记、对话能力元数据、技能目录发现和生成后保存 / 修改入口已接入。技能 / MCP 胶囊已匹配阅读胶囊既有外观（阅读组件保持未修改）；原型菜单结构、自适应空状态和单能力输入标签交互已接入。配对、云同步、冲突解决、Python 沙箱和后台工具循环仍待实现。

## 需要纳入实现的其他状态

- 管理页空列表：可说明还没有保存能力；主菜单的空列表遵循上文紧凑结构，不显示空状态文案。
- 同步成功：行内低干扰状态，不阻塞管理操作。
- 保存失败 / 服务暂不可用：保留用户输入与草稿，给出重试入口。
- 删除：在执行前说明会同步删除标记；取消不改数据。
- 创建/修改任务取消或中断：停止后续工具调用，保留可恢复草稿；Python 沙箱按任务清理规则关闭。
- 展示关闭：菜单不列出该能力，但后台技能目录仍可供 AI 自动发现。

## 评审边界

- 图稿使用的能力名称、对话文字与版本号都是示意数据，不形成默认条目。
- 面板横向贴合当前聊天可用宽度，随键盘和安全区变化；列表过长时只在列表区域滚动。
- 同步冲突时「保留双方」是默认安全路径；任何覆盖或删除操作都由用户显式触发。
- 菜单与底栏仍依据冻结截图；布局在 Flutter 落地时适配当前页面安全区、键盘与小屏宽度。
