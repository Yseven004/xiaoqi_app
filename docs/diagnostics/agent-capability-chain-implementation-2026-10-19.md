## 实现

| 环节 | 已接入的行为 |
|---|---|
| 任务作用域 | 普通追问继承技能、插件及 MCP；显式替换/清空分别处理；移除项从自动发现中排除；按可见快照和聊天分支恢复。 |
| 客户端选择 | 发送后保留现有能力标签；恢复聊天和切换问答分支时恢复对应选择；编辑问答保存选择操作。 |
| 技能发现与加载 | 发现当前账号启用的能力，保留固定版本；显式选择由运行层读取正文；隐式技能通过 Genkit `skills/use_skill` 激活；调用其资源、脚本或联网流程前检查是否已经加载。 |
| 插件 | 技能组件与 MCP 组件分别登记；支持远程 MCP 的插件可部分安装，依赖绑定当前账号已有连接；不执行插件提供的宿主命令，不导入插件声明中的凭据。 |
| 工具执行 | MCP 工具逐页发现并检查循环分页；逐次授权；业务错误先归一化再发布终态；读取返回资源时限制同一连接实际返回的 URI。 |
| 产物 | MCP 图片、音频和内嵌文件完整入库，长文本与结构化结果可作为文件保存；模型使用有界摘要，产物不做字符串截断。 |
| 完成检查 | 声明步骤、必要工具与产物要求；检查真实成功次数、文件数量、私有存储路径、长度和 SHA-256；缺交付时补执行，仍不足则明确未完成。 |
| 恢复与预算 | 计划和成功记录持久化，恢复授权后继续核验；计划可增加但不能降低既有要求；图片调用受交付数量和预算限制。 |

复用了现有 Genkit、CloudStore、沙箱、授权及产物展示通道，没有新增 Agent 框架或运行依赖。

## 发布与真实模型检查

已在发布流程中加入激活前检查：新镜像使用独立临时数据仓库，实际调用 `deepseek-flash` 和已配置的图片供应商。检查隐式生图技能、显式插件技能组件、无关问候、纯文本技能四个场景；前两项各限制一张图片，无关问候不应生成图片或激活技能，纯文本技能须实际加载并读取规则但图片调用为 0。

这些检查在替换运行服务和接触生产持久化卷之前执行。失败使用现有回滚路径；成功后仍需检查公网健康、版本匹配、数据清单及唯一应急恢复点。

先前真实检查中，隐式技能已通过；显式插件场景实际读取资料并生成图片，但完成检查拒绝通过。最初日志记录到模型追加不存在的脚本步骤；补充失败详情后，进一步确认模型自行将交付约束为 PNG，供应商实际返回其他合法图片 MIME，又追加重试要求。已收紧真实脚本可见性，并在计划绑定前校验图片格式与实际工具契约：普通图片匹配 `image/*`，严格格式必须有真实可用的转换步骤，不能用再次生图代替格式转换。修正后四个真实场景均已通过。

发布查询一度因本机 DNS 返回代理地址而超时；使用本机已有 HTTPS 代理恢复查询，未重启或安装网络工具。发布脚本的公网健康检查现遵循显式代理环境，远端服务环境未改变。

第二次构建期间，2 核 / 2 GB ECS 出现持续高磁盘读取，容器查询与公网健康请求均超时；远程诊断及停止测试命令未能执行。停止挂起的发布调用并正常重启 ECS 后，原服务恢复。Docker 构建中的测试改为 `dart test --concurrency=1`，降低并发压力；后续串行构建、真实模型检查及最终发布全部完成。没有取得明确 OOM 日志，不将内存压力推测当成已证实的根因。

正常重启后，原服务恢复健康，仍为 contract `15` 的原版本；没有强制断电。只读 `PRAGMA quick_check` 返回 `ok`，文档 381 条、对象索引 85 条，镜像标签与运行容器一致。确认无残留测试进程后重新发布。同时修复发布等待器未识别 Cloud Assistant `Timeout` 终态的问题，避免已结束的调用被持续等待。

## 构建环境修复

Windows 上的 Pub 缓存使用跨磁盘目录链接，导致 JNI CMake 和 Kotlin 增量缓存失败。构建辅助脚本现在把生成的包路径规范到实际缓存目录，JNI 原生构建暂存目录位于项目内，关闭了该项目的 Kotlin 增量缓存。

没有删除全局依赖缓存。Android 构建目录设置参考 [Android CMake DSL 官方文档](https://developer.android.com/reference/tools/gradle-api/8.10/com/android/build/api/dsl/Cmake)。
