## 1. 核对基线与结论

客户端和服务端的声明、锁定依赖及 `.dart_tool/package_config.json` 均指向 **genkit 1.0.0**。服务端 `genkit_openai`、`genkit_middleware`、`genkit_mcp`、`genkit_shelf` 为 1.0.0；`genkit_a2ui` 为 0.4.0。核查直接阅读这些已安装的发布包源码，不依据其他语言或新版本的能力推断当前版本。

结论：目前没有证据要求更换框架。应让官方 Agent 成为聊天执行与消息快照的唯一主体，删除普通聊天强制分类、准备、二次最终生成等额外编排。现有接口中的业务授权、SQLite 存储适配、书籍关联和界面映射并不是重复造框架，应保留。目标核心版本为 1.0.2，采用官方恢复补丁；目标 A2UI 插件为 0.5.0，按新版服务端 middleware 与 Flutter GenUI 接法迁移，不能用升级代替业务修复。版本差异见第 8 节，完整 A2UI 迁移及验收见第 9 节。

### 1.1 修正此前说得过满的部分

- 使用 `defineCustomAgent` 本身不等于错误：官方支持这个扩展点，1.0.0 的标准 prompt Agent 内部也借助它实现。问题是使用它做了什么，不能靠禁止某个函数名判断架构。
- SDK 的可恢复快照保留已完成的模型/工具轮次，**不会保留被取消那一次模型调用的半段输出作为可续接历史**。界面已显示文字需另行保存，不能宣称“接入快照就能原句续写”。
- 取消、等待确认、重新生成是不同操作：取消后恢复检查点；等待确认恢复原工具中断；重新生成从历史检查点开新分支。
- 官方 worker 心跳用于判断后台执行是否存活；用户要求的 10 秒客户端心跳、60 秒断连暂停是产品规则，两者不能互换。
- Genkit 的会话状态不替代外部操作幂等记录。工具组中途取消或响应丢失时，不能仅凭快照保证外部保存/发送恰好只执行一次。

## 3. 暂停、继续与重新生成的修复方案

### 3.1 暂停

调用官方取消能力，页面先显示“正在暂停”。等待 Agent 结束并取得实际 `aborted`/完成状态和快照；不能在只设置一个本地布尔值后就显示“已暂停”。若完成与暂停竞争，以服务端确定的状态为准。

持续保存已展示的正文、reasoning、来源及步骤。可见增量与执行快照分别承担展示和执行恢复职责，二者都绑定同一业务回答版本。只有思考、没有正文的回答同样允许恢复；移除 `home_page.dart:7237` 对空正文的提前返回。

### 3.2 继续原任务

先读取绑定的确切快照与业务执行记录。已经完成则同步结果；仍在暂停中则等待；失效/丢失则明确报错。对有效 `aborted`/`failed` 快照，以官方空输入 turn 继续最后保存的模型/工具历史，不增加新的用户提问。恢复连点按同一次恢复请求幂等处理。

对等待确认的 `interrupted` 状态，使用原工具请求的 `respond` 或 `restart`；前者提供回答，后者让原工具带已确认的信息再次进入处理函数。它们不能与普通取消续接混用。当前 SDK 会检查工具名称和引用是否确实来自原中断，保留这项检查。

关键边界有源码依据：1.0.0 `generate.dart:582` 明确说明，被取消模型的部分输出已经作为流式 chunk 发出，但不属于恢复历史；`agent.dart:1915` 只保留干净的模型输入历史和完整结果。恢复可以重新进入被中断的模型调用，不代表从供应商内部 KV 状态继续计算。

### 3.3 已输出半句话的续写：官方支持与接入缺口

> **2026-11-17 方案修订：本节最初提出的“工具历史 + DeepSeek prefix”集成已被实测反例推翻，不再作为当前实现计划。** 详见本文件“2026-11-17 DeepSeek 取消恢复复核与实现映射”：当前取消恢复使用 Genkit 已提交快照重跑标准 Agent/tool loop，不注入 provider prefix。以下原始协议研究仅作为历史背景，不代表小栖已支持或应该在 Agent 恢复中使用 prefix。

用户既定目标仍是：保留原有内容、继续同一回答，不从头发送原问题。不能悄悄降级为覆盖半段答案或生成一个新的回答。

截至本次查证，DeepSeek 明确提供 [Chat Prefix Completion](https://api-docs.deepseek.com/guides/chat_prefix_completion/)：把已收到的半段回答作为最后一条 assistant 消息，设置该消息的 `prefix: true`，调用 `https://api.deepseek.com/beta`。这是带前缀的新请求，不是恢复原 HTTP 请求或供应商内部 KV 状态；不能承诺恢复原随机轨迹、零重算或原请求计费继续。

| 中断位置/历史组合 | 官方支持边界 | 本方案处理 |
| --- | --- | --- |
| 已输出半段正文 | Prefix Completion 明确支持补全 assistant 前缀，返回新增部分 | 保留原正文并追加新增内容，仍属于同一业务回答；完成后官方会话中应得到完整回答，而非只保存后半段 |
| 只有思考、正文为空 | [Chat API](https://api-docs.deepseek.com/api/create-chat-completion/) 明确允许在 prefix 模式末条 assistant 中传入 `reasoning_content`；这提供思考前缀输入能力，但文档没有承诺每个“空正文＋工具”组合均可无缝接续 | 不能按空正文禁用恢复；保留模型实际返回的 reasoning，按该协议接入。具体模型、空正文及再次暂停的组合仍须定向验证，不能称已验证 |
| 小栖 function 工具已完成，随后正文中断 | thinking 模式支持 function tools；携带 tools 的后续请求要求完整回传历史 reasoning。现有小栖 `web_search/web_fetch` 调用独立 Search & Fetch 接口，不是下一行的内置服务端工具 | 从官方干净检查点保留配齐的工具请求/结果和引用，再附加当前模型调用的前缀。工具历史＋prefix 联合场景是有协议依据的接入方案，尚非实测保证；不得重复执行已完成副作用 |
| 工具参数只输出了一半，或工具执行结果未知 | 不完整流式参数不是可执行工具调用；SDK 会丢弃未完成轮次 | 不把半段 JSON 当成正文 prefix，也不编造工具结果。从官方检查点恢复；已发生/未知外部操作交由现有 ToolExecution 核实和幂等处理 |
| 回答使用 DeepSeek 内置 `deepseek_web_search/deepseek_read_url` | 官方 [Web Tools — Continue Generation](https://api-docs.deepseek.com/guides/web_tools/#continue-generation) 明确说不能续写，返回 400；建议重发原请求。Responses API 也不支持该续写方式 | 不能宣传全场景可续写，也不将小栖工具替换成内置工具来“解决”续写。当前方案保留小栖 function 工具；若未来引入该受限组合，先明确产品行为，不静默重发原问题 |

历史 reasoning 回传依据：[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)。普通无工具多轮对话忽略旧 reasoning 的规则，不能拿来否定专门的 prefix reasoning 参数；也不能据此删除带 tools 请求所必需的 reasoning。

**Genkit 接入方式和唯一状态归属：**

1. 已对照发布包：`genkit_openai` 1.0.0 与 1.0.2 的 `converters.dart` 内容一致，均未映射消息级 `prefix`。直接升级不会自动补齐这一字段，Genkit 1.0.2 也仍排除被取消调用的部分输出。
2. 优先复用现有官方 DeepSeek 插件与其公开 `httpClient`/`baseUrl` 扩展入口，在供应商请求适配处补足无法由类型表达的字段；SDK 自己也以请求体适配处理 DeepSeek `thinking` 字段。不能导入 SDK 的私有 `src` 类、改 Pub 缓存、复制整套 SSE 解析或工具循环。只有公开入口不足且写出证据后，才考虑官方 `defineModel` 扩展；不得先自建模型客户端。
3. 续写上下文绑定账号、任务、模型调用和回答版本；不能把共享客户端的可变“当前前缀”用于多个并发任务。通过官方模型/generate middleware 或模型扩展点传递请求级信息。只有恢复后的目标模型调用使用 prefix；后续工具轮次回到常规官方循环，不重复拼入前缀。无 tools 的专门 reasoning-prefix 请求也须保留末条 reasoning，不能沿用普通多轮请求“忽略历史 reasoning”的默认转换把它丢掉。
4. 模型响应规范化必须使流式界面只追加新增部分，官方最终 ModelResponse 包含该次模型调用的完整正文/reasoning。原始工具请求及引用保持不变；Genkit 再按正常流程保存消息和快照。部分内容日志只承担未完成输出的恢复材料，不成为第二份可独立推进的模型历史。
5. 重复暂停从同一模型调用的最新累计前缀续接；按事件序号去重，不能靠字符串相似度删正文。前缀和快照须绑定同一调用边界，旧材料不能附加到已经完成或已经进入下一轮的调用。失败保留可见内容并报告真实错误，不静默从头重跑。

适配的输入是官方检查点关联的未完成模型输出和恢复标识，输出是标准 Genkit chunks/ModelResponse；官方 Agent 仍拥有唯一执行状态。上游插件直接支持该能力后删除字段适配。**当前代码已接入有界 DeepSeek Prefix Completion 字段适配；正文、纯思考和工具联合续写尚未做真实供应商运行验证**，不能将官方网页产品的演示当作小栖 API 已验证证据。

### 3.4 重新生成与修改提问

从原提问前的官方快照打开新分支，发送原提问（修改时发送修改后内容），形成新的执行尝试和回答版本。保留旧回答及其所有后续快照，界面切换时选中明确的分支。

修正现有“同一业务提问只能绑定一个 task”的假设：业务提问 ID 可关联多个回答尝试；每次尝试有独立身份，同一次网络重试沿用相同身份。不能简单关闭冲突校验，否则同一请求重试仍会启动多份任务。对应故障：客户端复用 question.id、创建新 task；服务端 `api.dart:1628` 拒绝该绑定。

历史较早数据缺少 Genkit 快照时，按既有可见分支建立受控初始化记录，并保留历史、书籍关联；不补造原来的工具/思考信息。重新生成不能顺带重复先前已完成的保存或发送；外部副作用继续受业务授权和幂等记录约束。

### 3.5 后台和断网

把 Flutter 对任务的订阅与页面生命周期分开，复用现有状态管理能力，切会话不取消执行。需要服务端脱离连接运行时优先使用官方后台执行、快照查询和 abort；官方 `detach/poll` 不能自动等同于可重放的逐 token 日志。

后台执行方式在任务受理时选定并绑定唯一执行身份。1.0.0 的 `AgentChat.detach(...)` 会通过 transport 提交输入，不能在页面离开时把原问题再传给它并声称只是“把现有任务转后台”。已经运行的任务只改变订阅和显示方式，不新开第二份执行。模型产生的正文和步骤通过现有事件存储提供显示补发；模型历史和执行恢复仍归官方 Agent 快照管理。

为保留流式画面和断网补发，现有事件存储可作为展示日志保留，不能承载另一套 Agent 恢复消息。框架 worker 心跳用于执行进程存活；客户端每 10 秒续期、60 秒无续期触发取消是独立业务租约。客户端不得仅因自己超时就宣称服务端已暂停；回来需同步官方执行状态。续期不自动恢复已暂停任务。

## 4. 思考、工具重复与提示词

### 4.1 思考和步骤

直接保留 `genkit_openai` 已转换出的 `ReasoningPart`；SDK 已提供 `reasoning_content` 转换与必要的工具历史 reasoning 回传，不再写另一套模型响应解析器。展示层只做明确敏感值处理，不按“目录、后端、token”等普通词屏蔽整段。

官方 `ToolRequest.ref`/工具响应关联作为步骤身份依据。现有 presentation middleware 虽收到 `ToolRequestPart`，却只向投影层发工具名称并创建进程内 Object；这个身份无法自然贯穿持久化与重连。改为沿用官方引用，并加任务/调用上下文约束以避免跨轮冲突。没有引用的业务步骤单独保留稳定业务 ID，不冒充模型工具调用。

开始、结束、通用返回事件归入同一个步骤，旧状态不覆盖新状态；不同搜索用实际主题或网页标题区分。截图只能证明同文案重复出现，无法证明是哪一种重复原因。执行层重复仍通过 `ToolExecution` 判断，不能靠隐藏 UI 行解决。

### 4.2 提示词与缓存

主提示词职责限于身份、表达、按需能力和事实边界。取消“准备完成”门槛和固定“一句话结论”式结构；框架协议、幂等、快照和状态转换不再靠提示词要求模型维持。

使用现有 Dotprompt 能力管理固定文字；技能、资料与规则根据实际需要载入。固定前缀与工具定义顺序尽量稳定，不在开头拼接任务 ID、精确时间或变化的结果清单。同一任务沿用已绑定版本，按供应商要求正确保留工具历史和 reasoning。

KV/上下文缓存仍由模型供应商负责，不建立小栖自己的 KV 缓存。模板变更和历史压缩可能降低旧前缀复用，不影响缓存机制本身；后续若做缓存效果验收，检查供应商真实 usage，不以提示词长度猜命中率。当前 Genkit OpenAI 转换器映射的是 `promptTokensDetails.cachedTokens`，不能默认 DeepSeek 的独立 cache hit/miss 字段一定已显示到小栖统计。

- 当前 A2UI 0.4.0 声明 `genkit: ^1.0.0`；目标 0.5.0 依赖 `a2ui_core: ^0.5.0`。官方 0.5.0 README 明确要求该插件只在服务端安装；GenUI 0.10.x 使用 `a2ui_core: ^0.1.0`，两者不能放进同一个 Flutter 包解析。小栖已有分离的服务端包，按官方方式分别解析即可，不需要升级整套渲染引擎或使用 dependency_overrides 强压冲突。包版本范围是源码证据，实际编译仍待实施。

### 8.2 什么时候升级依赖，什么时候调整架构

**依赖补丁升级**：官方已修复项目正在使用路径上的缺陷，或存在安全/兼容性修复时，优先升级而不是本地打补丁。先查看 changelog、实际 diff 和锁定依赖，客户端/服务端同一发布内完成；只验证涉及的恢复、工具和契约路径。Agent/session API 仍通过 experimental 入口提供，不能仅凭补丁版本号断言绝无行为变化。

**架构调整**：只有已经证明现有官方架构的能力边界不足时才启动，例如多实例任务需要共享持久存储而当前 SQLite 单节点无法满足，进程重启后的任务接管有已确认可靠性目标，或者新 UI 协议确实要求端到端迁移。先给出问题、负载或故障证据，检查官方现成存储/部署/插件方案，再提出最小调整和数据迁移。不能为了“更先进”、一次界面问题或固定格式回答就换执行框架。

**当前判断**：已找到应用强制多阶段、两层历史拥有者、空正文恢复门槛和重新生成绑定冲突等具体问题。修复它们应回归官方路径；Genkit 1.0.2 与用户已确认的 A2UI 0.5.0 迁移同批规划，无需重构整个架构。A2UI 迁移采用官方服务端/渲染端分工，不另写 UI 协议或 Agent 调度器。框架升级不能自动修复小栖的业务 ID、事件展示或提示词策略。

## 9. A2UI 0.5.0 官方迁移方案（已纳入本次范围）

### 9.1 依据、版本与职责

依据为 [genkit_a2ui 0.5.0 发布包](https://pub.dev/api/archives/genkit_a2ui-0.5.0.tar.gz) 内的 README、CHANGELOG、pubspec 和 `lib` 源码，配合已安装 `genui 0.10.4` 源码；许可证分别为 Apache-2.0 和 BSD-3-Clause。引用或移植官方示例保留来源和适用许可证。当前本地 developing-genkit-dart skill 的 A2UI 部分仍介绍 0.4.x 的客户端 helpers，不能将它当作 0.5.0 的迁移指令；采用目标发布包说明，并在实际升级后刷新版本相关的能力映射。

官方目标链路：

`同一个 Genkit Agent → a2ui() middleware 编译 Express → 标准 DataPart → remoteAgent → GenUI SurfaceController → Flutter 宿主展示（普通卡片沿用消息位置；提问面板按 9.7 节锚定输入区上方）`

`GenUI onSubmit → 官方示例的 action 消息桥接 → 同一 Genkit 会话的下一轮；真正的工具中断仍使用 respond/restart`

| 位置 | 目标依赖/职责 | 具体边界 |
| --- | --- | --- |
| 服务端独立 Dart 包 | Genkit 1.0.2、genkit_a2ui 0.5.0；插件声明 a2ui_agent ^0.1.0 / a2ui_core ^0.5.0，具体解析结果进入锁文件 | 由官方插件编译、校验和修复 Express，输出 A2UI v0.9 消息；不手写编译器或另启一个 UI Agent |
| Flutter 包 | Genkit 1.0.2、现有 genui 0.10.4、a2ui_core 0.1.1；移除 genkit_a2ui | 该 GenUI 版本满足官方至少 0.10.3 的要求，按标准 JSON 消息渲染，不解析 Express 原文 |

### 9.3 Catalog 与既有组件

- 服务端注册的 lookup id 与真正的 `catalogId` 分清；模型输出的 catalogId 必须等于 Flutter 注册的 catalogId。新版官方说明未知 catalog 会显示空白，因此匹配是必要检查，不能只看消息到达成功。
- 新 catalog 使用符合规范的唯一 URI，两端同步。现有 `com.xiaoqi.chat.clarification.v1` 的历史记录保留，采用受限历史标识映射或 renderer 的旧标识注册读取；仅映射到已核实的原组件集合，不接受任意未注册组件。这个映射服务于历史数据保留，不用于兼容旧客户端请求。
- 优先使用官方 basic 组件的相同 schema 和 GenUI builders；小栖确有专有组件时才通过官方 CatalogItem 扩展，列出业务用途、属性、事件和 builder。不能把所有书籍卡片、确认弹窗和插件面板强行改成 A2UI。当前原生卡片和 MCP Apps 面板继续走原有能力，现有界面范围及输入焦点规则保持有效。
- 表单值使用官方数据绑定；提交事件 context 明确引用对应数据路径。不要假设 TextField/CheckBox 的值会自动出现在提交消息中。

### 9.4 卡片生命周期、按钮与任务状态

1. **有序更新**：一个 A2UI part 可能仅更新旧 surface；所有消息按顺序交给官方 controller，不为每个 chunk 新建 renderer。遵循插件的 delete/create 替换和 updateComponents/updateDataModel 更新；只维护 surface 的聊天位置，不手工复制组件树。流式和最终消息不能无区别地重复投递；遵循原有事件序号及一次回放边界，保留 SDK 合法的修复/替换消息。
2. **切换与恢复**：切会话后继续存储后台标准 parts；回来按选定分支重建/同步 renderer。切分支时清理旧分支的 surface 状态，不能把相同 surfaceId 的两条分支混合。应用重启时从保存的 parts 顺序重建，不能靠页面中的 Completer 存活恢复表单。
3. **按钮监听**：在第一轮开始前订阅 onSubmit。只处理含 action 的用户提交；renderer 错误不是用户动作，不发送给模型触发新 turn。处理中的按钮给出明确禁用/进行中反馈，避免并发 turn 和连点重复动作；任务终态同步后再开放。
4. **状态语义**：普通 A2UI 提交以标准 action 用户消息进入同一分支的新 turn，不再次发送原问题。不再仅凭“卡片包含 Button/TextField”推断 Agent 正在等待确认。真正等待权限或输入的工具中断，仍绑定原 tool ref 并走官方 respond/restart；现有批准逻辑不能被普通 UI action 绕过。
5. **任务归属**：卡片动作绑定原会话、分支及合法的 surface；网络重试沿用同一次操作身份。服务端验证当前可操作状态，删除或被替换卡片的迟到动作不得推进错误任务。业务任务可关联多个官方 turn，但只有一个官方会话执行主体。
6. **失败/取消**：暂停同步取消官方 turn，包括正在进行的 A2UI 修复调用。保留正文、已有效渲染卡片及已收集的业务信息；错误卡片有明确反馈，不能出现永久无响应的等待。恢复和重新生成沿用第 3 节的快照与分支规则，不能创建隐形第二任务。

### 9.5 Express、半段续写和额外模型调用边界

正文与卡片混排时，官方 middleware 将 `<a2ui>` Express 编译为标准 parts，普通聊天仍直接输出文本。不能把只剩文本的 UI 展示结果当作供应商完整的模型前缀；混排续写需要在官方模型 middleware 的适当边界保留该次模型调用的真实未完成输出，并让恢复输出继续经过同一 A2UI middleware。Genkit 继续保存完成后的标准消息与 metadata，客户端不接收需要自行编译的 Express。

实施时必须先证明公开扩展点可以正确处理“Express 块中途暂停、块前后正文、完成前缀与新增部分的组合”，防止恢复后缺少块开头或重复创建卡片。此为第 3.3 节同一供应商适配的扩展场景，不另造续写引擎。若公开入口存在未解决限制，先记录具体证据，不把 UI 文字当作完整前缀凑合运行，也不静默将继续改成重新生成。

沿用官方 `a2ui(validate: 'strict', repair: true)` 能力：只有 Express 块编译失败时才触发官方有限修复；没有失败的普通回答不增加该调用。0.5.0 官方实现限制为每个不同坏块一次、每模型调用最多 3 次及总计 30 秒；取消会传递，修复消耗计入 usage。需要明确记录这是异常路径可能增加延迟的来源，不另加小栖“修复 Agent”。严格校验在修复仍失败时报告错误，保留已有正文并结束实际失败状态，不静默丢卡片后冒充完整成功。排查时可通过官方 repair 开关关闭修复观察原错误。

提示词只决定何时用界面和回答风格，catalog/Express 规范由官方 middleware 提供；避免重复手写其协议提示词。普通问答不强迫卡片化，不恢复固定准备/最终回答两阶段。catalog 及工具排序保持稳定；不新增小栖 KV 缓存。

### 9.6 历史、发布和必要验证

历史消息保留原始 DataPart、必要 metadata、书籍关联及来源。官方已有对旧 `envelopes` 历史的读取能力，优先复用；新客户端发送 `messages`。遇到缺失或无法识别的旧卡片，保留原记录及明确错误，不猜测重建数据。模型重放与 UI 回放使用相同选定分支，不能一边回放旧卡片、一边让模型按另一分支继续。

服务端插件和客户端桥接作为同一契约发布，按第 5 节版本检查阻止旧客户端接新协议；不增加长期双协议运行。迁移遵守原数据备份、健康检查和单恢复点流程，失败按同一发布恢复，不能只回滚一端并忽略契约不匹配。

只增加本次迁移必要的定向检查，不扩展全量测试：

- 分别解析两端依赖、编译和检查受影响代码；确认 Flutter 不再导入已删除 helpers，也未强行覆盖冲突依赖。
- 一条有效卡片及表单提交、跨轮同 surface 更新，证明 catalog 匹配、数据绑定与 action 回传；错误事件不能触发模型请求。
- 切分支/重连/历史回放不重复卡片、不混入其他分支；使用一份旧 envelopes 历史验证保留能力。
- 正文及 Express 中途暂停/继续、重新生成后回切旧分支；卡片提交连点不重复执行外部动作。
- 一个坏 Express 块走官方有限修复/取消路径；保留真正失败状态、已有正文及权限边界。

真机由用户检查卡片外观、表单输入与收键盘、按钮首击、滚动、暂停继续及分支回切。本轮未执行这些检查，方案和源码对照不能替代真机有效性证据。

### 9.7 提问面板完整交互（用户已确认，纳入冻结方案）

本节补充 Flutter 展示、输入和业务数据适配；不更换第 9.1–9.6 节的官方 A2UI 接入及 Genkit 执行机制。完整视觉依据与状态记录见 [提问面板设计](../design/agent-question-panel-v1.md)。静态概念图不足以证明键盘、任务恢复或真实工具交互已运行。

#### 视觉、位置与键盘

- 采用第一张及细化图的黑白简约现代风格，纵向选项列表，面板锚定聊天输入区上方，底部保留可多行填写的自定义回答。沿用项目字体、灰阶、轻边框、浮层阴影；不重设计其他聊天组件。
- 未编辑时无整页遮罩；点击面板输入框才弹键盘。**只有键盘与提问卡片上下移动，顶栏、消息画布、能力工具条及原聊天输入框保持位置**；不能由页面整体 resize 造成重复避让、消息滚动或其他组件被顶起。
- 键盘展开时其余页面显示半透明遮罩，拦截穿透操作；卡片随实际键盘遮挡与安全区避让，不能写死高度。窄屏、大字体、长题目时约束面板高度并提供内容滚动，保证导航、输入和提交可达；平板按聊天区域限宽。
- 主动收起键盘时，无论文字是否为空均立即失焦，移除光标和焦点边框，保留答案；遮罩消失、卡片回落，其他组件不位移。布局更新、键盘动画及任务事件不能重新抢焦点。
- 点击遮罩空白处只收键盘并失焦，不提交、不取消、不关闭卡片；点击“取消任务”在当次点击收键盘并终止任务。键盘回车仅换行，最终提交只通过卡片按钮完成。

#### 多题与答案

- 顶部题号及前后导航支持自由切换，未回答不阻拦；保留各题的选项、自定义文字、当前题号。切题不提交、不调用模型，不重新生成问题。
- 单选选中后有下一题则自动进入下一题；最后一题选完仍保留卡片，点“提交并继续”才提交。多选留在当前题，点“下一题”切换。
- 键盘原本展开时，点击选项及前后切题不收键盘，编辑目标随当前题正确转移，不能把文本写入上一题；键盘原本隐藏时切题不自动弹出。此处是面板内明确确认的焦点行为例外。
- 预设选项与自定义文字分别保留并一起交给 AI 理解；由 AI 判断是补充还是修改，前端不互相清空、不强行替换。存在会影响外部操作的歧义仍须澄清，不将输入解释冒充额外授权。
- 最终提交统一检查所有必答题，漏答定位到对应题目并保留其他答案。提交期间避免重复操作；成功后才恢复原工具中断或发送对应标准 A2UI action，不能重复发送原始问题。失败保留草稿并允许重试，沿用同次提交身份避免重复执行。

#### 取消、系统返回与暂停恢复

| 用户操作/状态 | 确定行为 |
| --- | --- |
| 取消任务 | 当次收键盘、失焦、终止任务并关闭卡片；终止后的任务不提供“继续”，不可暗中转成暂停 |
| 键盘可见时按系统返回 | 先收键盘、失焦，留在当前页面并保留卡片 |
| 键盘已收起时按系统返回离开 | 暂停当前任务，保留卡片和全部答案，返回上一页；不另问是否取消 |
| 再次进入会话 | 恢复显示原卡片、题号及已填答案，任务保持暂停，不自动弹键盘、提交或运行 |
| 点击“继续任务” | 从原任务快照/原工具中断恢复，回到可回答状态，未最终提交的草稿不自动作为答案发给模型 |

取消与暂停都通过官方取消控制落实到实际执行，业务层记录不同的终止/暂停语义；官方快照存在不代表产品必须开放已取消任务恢复。迟到的表单事件或工具回调不能重新启动已终止任务，已完成外部操作不因关卡片自动撤销。暂停不能仅是本地状态标签；其服务端确认及失败反馈复用第 3 节机制。

本节“系统返回时暂停”针对正在展示的提问面板；普通聊天切会话/返回书库继续执行的既有规则保留。草稿按账号、会话、分支和实际提问身份保存，不能依赖页面 Completer 或临时控件存活；复用官方表单模型与现有业务存储适配，不另造模型历史、协议解析器或任务调度器。

#### 成功后的问答摘要

- 提交成功后关闭浮层，在对话里保留一条默认折叠的可展开问答摘要，采用 Codex 类似的交互。展开按顺序显示实际问题、预设选项答案和自定义文字；收起恢复摘要视图。
- 摘要仅供阅读，展开/收起不重复提交、不恢复任务；归属原分支。未成功提交时不写“已提交”记录，重试不重复追加摘要。不把思考原文、内部工具日志或附件原件混入这份问答摘要。

### 实施决策

DeepSeek官方 [Chat Prefix Completion](https://api-docs.deepseek.com/guides/chat_prefix_completion/) 是独立的新请求，不是供应商 KV/精确 token 恢复。Genkit 1.0.2 公开的 `AgentChat(snapshotId: ...)` 恢复官方最近提交状态；该状态不承诺包含被取消调用尚未提交的 stream chunk。之前第 3.3 节的“工具历史 + prefix”适配假设已被真实请求反例推翻：见 `docs/diagnostics/2026-11-16-genkit-trace-diagnosis.md` 对照 Trace，以及本地 DevTools 同一 session 的无 prefix 工具历史跟进成功 Trace `b537193da6d56959427816177faed77a`、`6fa8e055cd3a3f371d76f860d6288eca`。后两条是正常的已完成工具会话及同 session 跟进，不宣称已经验证中止恢复。

因此本轮实现不再把 partial text/reasoning 伪装成模型请求的 provider prefix；同一 task 仍由官方 snapshot 恢复并重新运行标准 Agent/tool loop。UI 保留已见的 partial text，并用既有 continuation 合并处理恢复文本。重新计算可能增加模型调用/费用，不能称为恢复供应商内部推理状态。模型 request 输入保留 Genkit 已提交的工具定义、请求、结果；未知副作用继续经既有 journal 核验。

普通文本链路额外移除必经的 `_classifyTurn` 模型门槛：由现有消息/附件/明确的 capability 选择等请求数据建立窄 scope，Agent 模型本身按任务选择工具；账号权限、用户选择、每个 effect tool 的检查和图片限制保持服务端约束。仅当附件/图片或特定产物识别需要现有专用业务解释时保留分类。遇到 network/model 失败时，普通文本不再在工具 loop 前停在“任务识别”；失败应来自标准 Agent 的真实模型/tool span。

### 有依据的适配例外

1. DeepSeek 1.0.2 插件转换器不序列化 assistant prefix 字段；`TaskModelClient` 只为绑定该续写请求的任务，使用 DeepSeek 官方 `/beta/chat/completions` 和 `prefix: true`，不复制 SSE 解析或 Agent 工具循环。
2. 60 秒客户端租约、来源补发、步骤投影和提问草稿是明确的产品行为，使用现有任务/事件/会话数据，不建立第二套模型消息或 snapshot 引擎。
3. 键盘避让、遮罩、触控和 SVG 单选/多选图形是 Flutter 宿主视觉需求，A2UI 不负责这些原生布局细节；Surface 结构与交互消息仍走官方接口。

### A2UI 客户端包最终核定

- 锁定依赖：Flutter `a2ui_flutter 0.3.0`、`a2ui_core 0.7.0`；服务端 `genkit_a2ui 0.5.0`。Flutter 3.47.5 满足 `a2ui_flutter` 的最低版本要求。
