# PDF 附件失败：根因与解决方案

本报告前半部分记录的是修复前代码与首次错误提示。补充排查确认这不是唯一根因：视频一的 177 秒任务还把普通概览放进了多轮资料分析，视频三则是接口版本不匹配，未进入 OCR。下方“2026-10-19 通用链路实现”是当前状态，取代旧版整本 OCRmyPDF 接入描述。

## 代码证据

1. `lib/services/home_chat_attachment_reader.dart:65–81`：逐页调用 `loadText()`，任何一页返回空文字就抛出“是扫描图片”的异常，整份解析中止，已经提取的内容也不会返回。
2. `lib/pages/home_page.dart:1823–1833`：先读取文字，随后才调用 `readScannedPageImages()`。前一步异常导致扫描页转图逻辑不可达。
3. `lib/pages/home_page.dart:1866–1878`：捕获该异常，显示截图文案并直接返回。该发送流程尚未进入模型调用。27.7 MB、网络、模型或 book-to-skill 的执行不是这条报错的触发条件。
4. 空文字不等于扫描图片：图片封面、空白页、字体/文字提取异常也可能返回空文字。后续检查到的健身书第 1 页为扫描页；`book.pdf` 第 1 页是图片封面，第 4 页为空白。

## 为什么 DeepSeek 上传成功，而小栖失败

DeepSeek 官方产品提供文件上传与文字提取功能；小栖调用模型前有自己独立的解析逻辑，不会自动继承官方产品的文件处理流程。官方产品究竟对此文件使用了 OCR、忽略了封面，还是采用了不同提取器，现有证据无法确定。

官方当前 Files API 文档列出的上传格式是 JPEG、PNG、GIF、WebP；Vision 文档说明 deepseek-flash 支持图片。因此不能声称 DeepSeek 完全不能识图，也不能把官方产品接受 PDF 等同于当前 API 可直接接收原 PDF。

## 为什么不能只删掉异常

- `lib/pages/home_page.dart:2428–2433` 会跳过没有文字的资料。纯扫描 PDF 若只转图不补文字，book-to-skill 的分段读取链路仍没有正文。
- `read_task_material` 仍需可读取文字；因此对扫描页补充 OCR，而不是只跳过空页或仅向模型传图片。
- OCRmyPDF 是文字层与文字提取方案，不会理解动作示意图或保留结构化表格。需要图表视觉理解时应另做按需页图检索，不能把数百张原图一次放入请求。

上游实现依据：[OCRmyPDF 官方处理示例](https://github.com/ocrmypdf/OCRmyPDF/blob/main/docs/cookbook.md)。本次直接调用 OCRmyPDF，不要求用户预先转换文件。

## 2026-10-19 通用链路实现

代码证据确认了五个独立问题：普通概览会重复读取大量片段并触发无关工具；混合 PDF 因空文字页进入整本 OCR；客户端轮询一次超时会丢掉资源引用；A2UI 卡片存于页面全局状态而未绑定消息；旧会话接口 8 对当前服务接口 9 的请求在版本门禁处被拒绝。视频三的版本错误不能归为 OCR 超时。

客户端和服务端共用当前发布号 `2026-10-19-public-process-2`、接口版本 `14`。附件选择后启动共享准备器；消息“正在阅读”、上传/解析状态和重试状态绑定附件及当前会话。新会话清除旧 A2UI 展示，迟到回调不能覆盖当前请求。非 PDF 使用原有解析器在工作 isolate 中提取，并提交带来源位置的片段；PDF 先按页提取原生文字，只在概览、查询或全文请求涉及的无文字页上使用 Poppler 单页渲染和 Tesseract。取消、超时、失败和重启保留已完成片段，任务 24 小时过期。

普通附件概览使用目录/代表片段及一次禁用工具的模型流，不进入 48 轮准备流程，不调用 Python 或联网。问题查询扩展相关页；只有明确要求全文时才读全本，并清楚报告覆盖范围。服务端分别记录上传、排队、提取、OCR 和模型首字耗时；真实耗时仍需在线上模型和目标文件上测量。

回归夹具生成器覆盖原生文字、扫描、混合、空白、加密、损坏、超页数 PDF、PNG 与 Unicode 文本；另外两份原文件仅作为补充回归样本。Windows 本机 Docker 桥接用例需显式指向项目 Python 运行时；完整服务端测试在设置后通过。后续补充的 DOCX/EPUB 中文解析、HEIC 临时转换文件清理和附件状态隔离回归详见下方验收记录。

当前代码完成不代表线上性能指标或真机界面验收已完成。应在部署后分别测上传、排队、提取、OCR、模型首字耗时，并检查扫描页中文质量。目标 Android 真机仍待用户验证。
