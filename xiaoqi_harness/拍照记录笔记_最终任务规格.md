## 前置约束（所有任务必须遵守）

### 引用 project-insights.md
- §1.1 笔记保存后**不自动**调用 AI 分析，需用户手动点击"✨ 让小七看看"
- §1.2 笔记类型仅 `'text'`、`'photo'`、`'ai_generated'`，AI 生成笔记须设 `parent_note_id`
- §1.3 V1.0 不做书籍自动识别，书名+页码由用户手动输入
- §1.4 小七表情优先级：1烦躁 > 2困倦 > 3微笑 > 4思考 > 5常驻眨眼，触发后2分钟恢复
- §2 OCR识别失败：图片正常保存，content留空，提示手动补充
- §2 AI分析超时：显示"小七暂时走神了，稍后再试"，不自动重试
- §2 笔记列表空状态：显示"开始记吧。"3秒后消失
- §3 每日AI生成笔记次数限制5次（客户端计数）
- 决策：V1.0只用StatefulWidget，纯本地存储无云同步

### 引用 coding-standards.md
- 目录结构：config/ models/ services/ pages/ widgets/ utils/
- 命名：文件snake_case，类PascalCase，变量/方法camelCase，私有_开头
- 颜色/边距/字体必须从 config/ 引用，禁止硬编码
- 字符串用单引号
- async 函数必须 try-catch + 向用户显示友好提示
- 日志：`debugPrint('[XiaoQi] 模块名: 内容')`
- **V1.0 只用 StatefulWidget + setState，禁止 provider/riverpod/bloc**
- 数据库用 sqflite，所有操作在 DatabaseService 单例中
- 删除用软删除 is_deleted=1
- UI速查：主背景 #FAFAFA，卡片 #FFFFFF，圆角 12px，左右边距 20px，卡片间距 12px
- **禁止 print，禁止自动添加依赖，禁止 UI 中直接调用 API**

## 任务2：照片笔记数据模型与存储

### 用户故事
作为开发者，我需要扩展 Note 模型支持 photo 类型，以便后续所有页面都能正确读写拍照笔记数据。

### 数据模型

在 `lib/models/note.dart` 中扩展 Note class，新增字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 主键，自增 |
| type | String | `'photo'` |
| title | String | 笔记标题，可为空 |
| content | String | OCR提取/用户手输文字，可为空 |
| photo_path | String | 本地图片相对路径（**必填**） |
| book_name | String | 手动输入书名，可为空 |
| book_page | String | 手动输入页码，可为空 |
| created_at | String | ISO8601 |
| updated_at | String | ISO8601 |
| is_deleted | int | 软删除标记，0/1 |

### DatabaseService 扩展

在 `lib/services/database_service.dart` 单例中新增：

```dart
Future<int> insertPhotoNote(Note note)   // 插入photo笔记，photo_path为空时抛ArgumentError
Future<List<Note>> queryPhotoNotes()     // 查询photo列表，过滤is_deleted=1
Future<int> getTodayAiCount()            // 查询当天AI生成笔记次数（按created_at当天日期过滤type='ai_generated'）
```

复用已有的 `softDelete`、`update` 方法。

### 数据库迁移

- `onUpgrade` 增量 ALTER TABLE ADD COLUMN，版本号+1
- 新字段默认空字符串，不 drop 表
- 为 `type + is_deleted + created_at` 建复合索引

### 验收标准
- [ ] Note model 支持 type='photo' 及所有新增字段
- [ ] insertPhotoNote 正确写入，photo_path 为空时拒绝并提示
- [ ] queryPhotoNotes 返回完整数据，过滤已软删除记录
- [ ] 软删除后默认查询不返回
- [ ] 旧版本数据库升级后数据不丢失
- [ ] getTodayAiCount 按当天日期正确计数

### 边界条件
- photo_path 为空 → 不允许保存，返回校验错误
- 数据库写入失败 → try-catch，提示"保存失败，请重试"
- 旧库升级 → ALTER TABLE ADD COLUMN，默认空字符串
- 500+笔记查询 → 复合索引保证 <200ms

### 技术约束
- sqflite 单例（coding-standards）
- 软删除 is_deleted=1（coding-standards）
- 日志 `debugPrint('[XiaoQi] DB: ...')`（coding-standards）
- async 必须 try-catch（coding-standards）

### 不做什么
- 不做云同步
- 不做书籍自动识别（§1.3）

### 过渡动效（拍照→编辑页）

总时长 ≤1.5秒，分4步渐进披露：

| 时间 | 动效 | 参数 |
|------|------|------|
| 0-200ms | 快门闪白 + 小七微笑 | opacity: 0→0.3→0, 200ms, linear |
| 200-500ms | 照片从底部浮起着陆 | translateY: 屏幕高度→0, 400ms, Cubic(0.2, 0.9, 0.3, 1.0) → scale bounce: 1.0→1.02→1.0, 150ms |
| 500-900ms | 输入区从上到下逐步展开 | height: 0→实际值, 300ms, easeOutCubic |
| 900ms+ | 保存按钮淡入 | opacity: 0→1, 200ms, easeOut |

### 图片持久化

保存时从临时目录复制到 `{appDocDir}/photos/{timestamp}_{random}.jpg`（不用note_id，因为insert前不知道id）

### 保存流程

1. 校验图片路径非空
2. 保存按钮立即进入 loading + disabled（防重复点击）
3. 复制图片到持久化目录
4. 构建 Note 对象（type='photo'）
5. 调用 DatabaseService.insertPhotoNote
6. 成功 → 整个编辑页内容向上收缩+淡出（300ms）+ 小七微笑 → 返回列表
7. 失败 → try-catch 提示，保留已填内容（setState不清空）

### 保存成功反馈

- 保存按钮 → loading态（旋转指示器），按钮disabled，1.2s内完成
- 保存成功 → 内容向上收缩+淡出（300ms），小七切换"微笑"表情
- 返回列表页 → 新笔记卡片从顶部"滑入"

### 中途退出

- WillPopScope + showDialog 确认弹窗
- 弹窗文案："放弃编辑？内容将不会保存"（强调损失，不是"确定退出？"）
- 弹窗动效：从中心 scale(0.8→1.0) + opacity(0→1), 200ms
- 背景：半透明遮罩 + 模糊度 2px（编辑内容仍可见，利用禀赋效应降低误操作放弃率）

### 验收标准

- [ ] 点击预览区图片可全屏查看
