#工程约束（小七项目）

> 本文件仅用于 AI 代码生成时的强制规则。  
> 每次生成代码前必须执行。

## 一、代码结构（必须遵守）

1. **目录结构**
   - `lib/config/` 存放 `colors.dart`、`text_styles.dart`
   - `lib/models/` 数据模型
   - `lib/services/` 单例服务（数据库、API）
   - `lib/pages/` 页面
   - `lib/widgets/` 可复用组件
   - `lib/utils/` 工具函数

2. **命名规范**
   - 文件：`snake_case`
   - 类：`PascalCase`
   - 变量/方法：`camelCase`
   - 私有成员：`_` 开头

## 二、必须做到的工程底线

1. **异步处理**
   - 所有 `async` 函数必须使用 `try-catch`，并向用户显示友好错误提示（如 `ScaffoldMessenger`）。
   - 禁止直接抛出未捕获的异常。

2. **日志**
   - 只使用 `debugPrint('[XiaoQi] 模块名: 内容')`。
   - 禁止使用 `print`。

3. **颜色与常量**
   - 所有颜色、字体、尺寸、边距等**必须从 `lib/config/` 下的常量引用**。
   - 禁止在代码中硬编码 `Color(0xFF...)` 或 `EdgeInsets.all(12)` 等数值（除非该值在任务规格中明确给出，且未在 `colors.dart` 中定义）。

4. **状态管理（V1.0）**
   - 只允许使用 `StatefulWidget` + `setState`。
   - 禁止引入 `provider`、`riverpod`、`bloc` 等包。

5. **数据库**
   - 所有 SQL 操作必须在 `DatabaseService` 单例中。
   - 删除记录必须使用软删除（`is_deleted = 1`）。

## 三、禁止事项（红线）

- ❌ 禁止在 UI 代码（`pages/`、`widgets/`）中直接调用 API 或数据库。必须通过 `services/` 调用。
- ❌ 禁止自动添加未在任务规格中明确要求的 `pubspec.yaml` 依赖。
- ❌ 禁止在代码中写入死数据（如 `mockData`）除非任务规格要求。
- ❌ 禁止生成超过 300 行的单个文件。超过时需拆分为多个文件。

## 四、关于 UI 数值的处理方式

当你收到任务规格（包含具体圆角、边距、颜色等）时：
- **如果颜色值已在 `lib/config/colors.dart` 中定义**：直接引用。
- **如果颜色值是新的（如 `#D4A574`）**：先在 `colors.dart` 中添加常量（如 `static const Color accent = Color(0xFFD4A574);`），然后在 UI 代码中引用。
- **圆角、边距等数值**：直接按规格中的数值写入（不需要提前定义常量）。

## 五、输出要求

- 每次输出代码前，先列出将要生成的文件清单（路径 + 简要说明）。
- 每个文件只输出一次，不要重复输出相同文件。
- 代码块必须标注文件路径，例如：
  ````dart
  // lib/pages/home_page.dart

## 六、与用户沟通

- 如果任务规格中有模糊或缺失的信息（例如未指定颜色值），先向用户确认，不要自行猜测。
- 如果需要添加新依赖，先列出依赖名和版本号，等待用户确认后再执行 `flutter pub add`。
