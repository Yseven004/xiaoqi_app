# 照片悬浮预览与"丢给小七"交互设计

**版本**：V1.0  
**创建日期**：2026-06-16  
**状态**：交互设计完成，UI/UX由UI设计技能生成

---

## 1. 设计背景

当前流程：拍照/选择相片后直接跳转到"拍照笔记"编辑页面。

**问题**：缺少过渡感，用户直接被打断到编辑流程，没有"照片刚拍好，接下来要做什么"的决策空间。

**目标**：
1. 拍完照后，照片以悬浮形式出现在主界面，让用户先预览、决定是否编辑
2. 提供两个核心功能入口："一键生成笔记"和"笔记分析和指导"
3. 点击"笔记分析和指导"时，触发"照片丢给小七"动画——照片飞向小七，小七吃掉照片并思考，完成后跳转结果页

**设计理念**：通过"照片丢给小七"的隐喻，让用户潜意识里觉得小七在"帮我消化知识"，不是冰冷的AI工具，而是一个会吃东西会思考的伙伴。

> **注意**：本文档只定义交互逻辑和动画时序。所有UI视觉规格（色彩、圆角、阴影、字体、间距等）由UI设计技能在开发时根据项目风格生成，不在本文档中固定。

## 2. 交互流程

```

  - 照片下方两个功能按钮：

  - 右上角关闭按钮
  - 小七执行眼睛引导动画（看照片→看左按钮→看右按钮→回正）
    ↓

    ↓
动画序列：
  ① 照片沿弧线飞向小七位置

  ⑤ AI失败 → 小七 E6 烦躁 → 显示错误文案
```

## 3. 悬浮照片预览层

### 3.1 功能要求

| 元素 | 功能 |
|------|------|
| 背景遮罩 | 半透明 + 模糊，主界面内容不可交互 |
| 照片预览 | 居中显示，自适应高度，不拉伸变形 |
| 关闭按钮 | 右上角，点击关闭悬浮层 |
| 两个功能按钮 | 照片下方并排，"一键生成笔记"和"笔记分析和指导" |

### 3.2 交互规则

| 交互 | 行为 |
|------|------|
| 点击照片 | 调用系统图片编辑器（Android: Intent ACTION_EDIT，iOS: PHPhotoUI） |
| 编辑完成返回 | 悬浮层更新为编辑后的照片 |
| 编辑取消返回 | 保持原照片不变 |
| 点击 × | 关闭悬浮层 |
| 点击遮罩空白区域 | 不关闭（避免误触） |
| 按系统返回键 | 关闭悬浮层，不退出App |

### 3.3 小七眼睛引导动画

悬浮层出现后，小七执行眼睛引导动画，引导用户视线到功能按钮：

```
[0.0s]  悬浮层出现，小七 E1 微笑，眼睛朝前
[0.3s]  开始引导动画
[0.3-0.8s]  眼睛向下看照片
[0.8-1.3s]  眼睛向左看"一键生成笔记"按钮
[1.3-1.8s]  眼睛向右看"笔记分析和指导"按钮
[1.8-2.3s]  眼睛回正，恢复 E1 默认
```

每段 500ms，曲线 easeInOut。动画只播放一次，不循环。

**中断规则**：用户在此期间点击任何按钮，引导动画立即停止，进入下一步。

## 4. "照片丢给小七"动画序列

### 4.1 关键帧时序

```
[0.0s] 用户点击「笔记分析和指导」
       照片开始沿弧线飞向小七
       小七保持 E1

[0.6s] 照片到达小七位置
       小七切换 E7 惊讶（张嘴）

[0.6-0.8s] 照片被"吃掉"（缩小+淡出）
           小七嘴巴闭合

[0.8s] 照片完全消失
       悬浮层开始 fade out（0.3s）
       小七切换 E3 思考
       主界面显示等待文案

[0.8s - AI完成] 小七持续 E3 思考状态
               思考期间轻微晃动（呼吸节奏）

[AI完成时] 小七切换 E2 微笑
          弹出气泡文案
          0.5s 后自动跳转 AI 分析结果页

[AI失败时] 小七切换 E6 烦躁
          显示错误文案
          不自动跳转，用户可重试
```

### 4.2 照片飞行轨迹

- **轨迹类型**：二次贝塞尔曲线（弧线，不是直线）
- **起点**：照片中心坐标
- **终点**：小七脸部中心坐标
- **控制点**：水平中点，垂直方向向上偏移（制造"抛出"的弧线感）
- **缩放**：飞行过程中从 1.0 缩小到约 0.3
- **淡出**：飞行最后 20% 进度内 opacity 从 1.0 → 0.0
- **时长**：600ms，曲线 easeOutCubic

### 4.3 小七表情切换时序

| 时间点 | 表情 | 触发条件 |
|--------|------|----------|
| 0.0s | E1 微笑 | 默认状态 |
| 0.6s | E7 惊讶 | 照片到达小七位置 |
| 0.8s | E3 思考 | 照片消失，开始分析 |
| AI完成 | E2 欣慰 | 分析成功 |
| AI失败 | E6 烦躁 | 分析失败 |

## 5. 状态机

```dart
enum PhotoOverlayState {
  showing,      // 悬浮层显示中，等待用户操作
  guiding,      // 小七眼睛引导动画播放中
  throwing,     // 照片飞向小七（0-0.8s）
  processing,   // 小七思考中，等待AI返回
  success,      // AI成功，小七微笑，准备跳转
  error,        // AI失败，小七烦躁
}
```

### 状态转换

```
showing → guiding：悬浮层出现 0.3s 后自动进入
guiding → showing：引导动画播放完毕（用户未操作）
guiding → throwing：用户点击「笔记分析和指导」
showing → throwing：用户点击「笔记分析和指导」（跳过引导）
throwing → processing：照片消失（0.8s 后）
processing → success：AI 返回成功
processing → error：AI 返回失败或超时（>15s）
success → 跳转结果页：0.5s 后自动跳转
error → showing：悬浮层恢复，用户可重试
```

## 6. AI 处理同步规则

| 场景 | 处理 |
|------|------|
| AI 在 2s 内完成 | 小七 E3 思考 → E2 微笑 → 跳转 |
| AI 超过 2s 未完成 | 小七继续 E3 思考，文案改为"还在想..." |
| AI 超过 15s 未完成 | 视为超时，小七 E6 烦躁 + 错误文案 |
| AI 失败 | 小七 E6 烦躁 + 错误文案，不自动重试 |

## 7. 边界情况

| 情况 | 处理 |
|------|------|
| 拍照后直接关闭 App | 悬浮层消失，照片不保存 |
| 系统编辑器返回失败 | Toast "编辑失败"，保持悬浮层 |
| 点击"一键生成笔记"（V1.0） | Toast "功能开发中，敬请期待~" |
| 小七不可见（设置中关闭） | 照片飞向屏幕右上角（默认位置），动画简化为直线 |
| 照片尺寸过大 | 悬浮层中压缩预览，实际处理原图 |
| 用户快速连续点击按钮 | 只响应第一次，后续点击忽略 |
| 飞行动画中用户按返回键 | 取消动画，恢复悬浮层 |

## 8. 预期用户感受

| 阶段 | 用户感受 |
|------|----------|
| 悬浮层出现 | 照片浮起来了——悬浮感制造新鲜感 |

| 小七微笑+跳转 | 满足——它帮我想好了，去看看 |

**核心情感价值**：整个过程 3-4 秒，但动画填充让等待变成"小七在帮忙"的仪式感。
