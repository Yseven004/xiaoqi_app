## 前置约束（所有任务必须遵守）

### 引用 project-insights.md

* §1.1 笔记保存后**不自动**调用 AI 分析，需用户手动点击"✨ 让小七看看"
* §1.2 笔记类型仅 `'text'`、`'photo'`、`'ai\_generated'`，AI 生成笔记须设 `parent\_note\_id`
* §1.3 V1.0 不做书籍自动识别，书名+页码由用户手动输入
* §1.4 小七表情优先级：1烦躁 > 2困倦 > 3微笑 > 4思考 > 5常驻眨眼，触发后2分钟恢复
* §2 AI分析超时：显示"小七暂时走神了，稍后再试"，不自动重试
* §2 笔记列表空状态：显示"开始记吧。"3秒后消失
* §3 每日AI生成笔记次数限制5次（客户端计数）
* 决策：V1.0只用StatefulWidget，纯本地存储无云同步

### 引用 engineering-minimums.md

* 目录结构：config/ models/ services/ pages/ widgets/ utils/
* 命名：文件snake\_case，类PascalCase，变量/方法camelCase，私有\_开头
* 颜色/边距/字体必须从 config/ 引用，禁止硬编码
* 字符串用单引号
* async 函数必须 try-catch + 向用户显示友好提示
* 日志：`debugPrint('\[XiaoQi] 模块名: 内容')`
* V1.0 只用 StatefulWidget + setState，禁止 provider/riverpod/bloc
* 数据库用 sqflite 单例，删除用软删除 is\_deleted=1
* 禁止 print，禁止自动添加依赖，禁止 UI 中直接调用 API
* UI数值（圆角、边距、字体等）由设计师自由定义，不受硬性约束

## 任务1：文字笔记编辑与保存页

### 用户故事

作为用户，我想要快速写一段文字笔记来记录灵感或知识点，以便日后回顾和让小七帮我分析。

### 新增文件

* `lib/pages/text\_note\_edit\_page.dart` — 编辑页 StatefulWidget

### 页面布局

```
页面背景：AppColors.background

┌─────────────────────────────────────┐
│  ← 新建笔记                         │  AppBar, elevation=0, 背景透明
├─────────────────────────────────────┤
│  ┌─────────────────────────────────┐│
│  │  标题：给笔记起个名字（选填）   ││  单行TextField, 18sp, w600
│  │  ─────────────────────────────  ││  分割线, 1px, AppColors.disabled
│  │                                 ││
│  │  写点什么...                    ││  多行TextField, 16sp, 行高1.6
│  │                                 ││  minLines=6, 无maxLength
│  │                                 ││  自动增高, ConstrainedBox最大屏幕60%
│  │                                 ││
│  │  📖 书名（选填）      页码      ││  Row: Expanded + SizedBox(width:80)
│  │  14sp, AppColors.hint           ││  页码: 数字键盘
│  └─────────────────────────────────┘│  卡片: AppColors.card, 圆角16px
│                                     │  内边距: 20px, 左右边距: 20px
├─────────────────────────────────────┤
│  \[        保存        ]            │  高48px, 圆角24px
│                                     │  AppColors.accent, 文字: 16sp, AppColors.onAccent
│                                     │  底部固定, 左右边距20px, 底部24px
└─────────────────────────────────────┘
```

**与拍照编辑页的关键差异：**

|维度|拍照编辑页|文字编辑页|设计理由|
|-|-|-|-|
|顶部|图片预览区240px|标题输入框|拍照=图片为主，文字=文字为主|
|卡片圆角|12px|16px|文字笔记更"软"，更大圆角增加亲和感|
|内容区|固定描述框(maxLength 500)|6行起自动增高,无maxLength|文字笔记可能很长，给足生长空间|

### 进入过渡

从 FAB 点击"写文字"到编辑页出现：

1. 页面从右滑入（CupertinoPageRoute），300ms
2. 进入后100ms，内容输入区自动获焦，键盘升起
3. **标题不自动获焦**——直接进入内容区，跳过"先想标题"的犹豫

### 保存流程

1. 构建 Note 对象（type='text'，photo\_path=null）
2. 保存按钮立即进入 loading + disabled（防重复点击，`\_isSaving` 状态变量）
3. 调用 `DatabaseService.insertNote(note)`
4. 成功 → 按钮文字变为"✓ 已保存"，停留400ms → 页面整体向上收缩+淡出（300ms, easeIn）→ 返回列表
5. 失败 → try-catch 提示"保存失败，请重试"，保留已填内容（setState不清空）

**保存成功过渡心理依据**："✓ 已保存"的短暂停留——完成确认，让用户看到结果再离开；向上收缩——"归档"隐喻。

### 中途退出确认

* **触发条件**：用户点击返回键/返回按钮，且已输入内容不为空
* 未输入任何内容→直接返回，不弹确认
* 使用 `PopScope`（Flutter 3.22+，替代已废弃的 WillPopScope）+ `showDialog`
* 弹窗文案："放弃编辑？内容将不会保存"（强调损失，不是"确定退出？"）
* 弹窗动效：scale(0.85→1.0) + opacity(0→1), 200ms, easeOutCubic
* 背景：半透明遮罩 opacity 0.4
* 默认焦点在"继续编辑"——默认效应保护用户成果

```
┌─────────────────────────────────┐
│                                 │
│  放弃编辑？                     │  标题, 18sp, w600
│  内容将不会保存                  │  副标题, 14sp, AppColors.hint
│                                 │
│  \[继续编辑]    \[放弃]           │  左: AppColors.accent边框
│                                 │  右: AppColors.accent填充
└─────────────────────────────────┘
```

### 键盘处理

* `resizeToAvoidBottomInset: true` + `ScrollController` 确保光标可见

### 验收标准

* \[ ] 标题/内容/书名/页码均可选填
* \[ ] 内容区多行输入，自动增高，最大屏幕60%
* \[ ] 页码仅允许数字输入
* \[ ] 保存后数据正确写入数据库，type='text'，photo\_path=null
* \[ ] 保存成功→"✓ 已保存"(400ms)→收缩淡出→返回列表，新笔记在顶部
* \[ ] 保存失败→友好提示，不清空已填内容
* \[ ] 保存按钮防重复点击（loading + disabled）
* \[ ] 中途退出（有内容）弹窗确认："放弃编辑？内容将不会保存"
* \[ ] 中途退出（无内容）直接返回
* \[ ] 全部留空直接保存允许（空笔记）
* \[ ] 保存后不自动触发AI（§1.1）
* \[ ] 内容区自动获焦（标题不自动获焦）
* \[ ] 键盘弹出时不遮挡输入区
* \[ ] 弹窗默认焦点在"继续编辑"

### 边界条件

* 用户未填任何文字直接保存 → 允许
* 保存失败（数据库异常）→ try-catch，提示"保存失败，请重试"
* 连续快速点击保存 → 只触发一次，按钮立即disabled
* 内容极长（10000+字）→ 正常保存，列表截断展示
* 键盘遮挡输入区 → resizeToAvoidBottomInset + ScrollController

### 技术约束

* 只用 StatefulWidget + setState（engineering-minimums §4）
* PopScope 替代 WillPopScope（Flutter 3.22+）
* 颜色从 AppColors 引用（engineering-minimums §3）
* 保存后不自动触发AI（§1.1）
* 日志 `debugPrint('\[XiaoQi] TextEdit: ...')`
* async 必须 try-catch（engineering-minimums §3）

### 不做什么

* 不做富文本/Markdown编辑
* 不做自动保存草稿
* 不做字数统计
* 不做标签系统

## 任务2：笔记创建入口（ExpandableFAB）

### 用户故事

作为用户，我想要一个清晰的入口来选择"写文字"或"拍照"创建笔记，以便用最短路径开始记录。

### 新增文件

* `lib/widgets/expandable\_fab.dart` — 可展开FAB组件

### ExpandableFAB 设计

```
收起态：
              \[＋]  ← 主按钮 56×56, AppColors.accent, 圆形
                     图标 Icons.add, 24px, AppColors.onAccent
                     阴影 offset(0,2), blurRadius=8, black12

展开态：
              \[✏️ 写文字] ← 子按钮2, 高48, 宽120, 圆角24
              \[📷 拍照]   ← 子按钮1, 高48, 宽120, 圆角24
              \[✕]          ← 主按钮变为关闭, 图标旋转45°

              子按钮间距：8px
              子按钮与主按钮间距：12px
              子按钮背景：AppColors.card (#FFFFFF)
              子按钮文字：AppColors.textPrimary, 14sp, w500
              子按钮图标：AppColors.accent, 20px
              遮罩：黑色, opacity 0.3
```

**子按钮排列顺序**：写文字在上、拍照在下。

* 文字笔记是更高频操作——位置显著性（Position Salience）：视线从上往下扫描，最先看到最重要的
* 锚定效应：先看到"写文字"，锚定"记录=写字"的心智模型

### 动效规格

|动效|时长|曲线|属性变化|心理依据|
|-|-|-|-|-|
|主按钮旋转|200ms|easeInOut|rotation: 0→π/4 (＋→✕)|旋转是方向翻转的通用隐喻，45°是最小可识别旋转角|
|遮罩淡入|200ms|easeOut|opacity: 0→0.3|不全黑——保持环境可见，降低"被困住"的不适感|
|拍照子按钮弹出|200ms|easeOutCubic|scale: 0→1, translateY: 16→0, opacity: 0→1|从小到大+从近到远=从主按钮"生长"出来|
|写文字子按钮弹出|200ms+50ms stagger|easeOutCubic|同上，延迟50ms|stagger产生"依次出现"的节奏感|
|收起动画|150ms|easeInCubic|反向：scale/translateY/opacity归零 + 旋转归零|快速收起，不拖泥带水|

### Flutter 实现要点

```dart
class ExpandableFab extends StatefulWidget {
  final VoidCallback onPhotoTap;
  final VoidCallback onTextTap;
  const ExpandableFab({required this.onPhotoTap, required this.onTextTap});
  @override
  State<ExpandableFab> createState() => \_ExpandableFabState();
}

class \_ExpandableFabState extends State<ExpandableFab>
    with MultiTickerProviderStateMixin {
  bool \_expanded = false;
  bool \_isAnimating = false;
  // 4个AnimationController: rotate / photo / text / overlay
  // dispose中必须dispose所有Controller
  // \_toggle()中 \_isAnimating 防抖
}
```

### 与拍照功能集成

* 替换首页 Scaffold 的 `floatingActionButton` 为 `ExpandableFAB`
* `onPhotoTap` 回调 → 调用已有 `CameraService.takePhoto()`
* `onTextTap` 回调 → `Navigator.push` 跳转 `TextNoteEditPage`
* 返回首页后 FAB 恢复收起态

### 验收标准

* \[ ] 点击主FAB展开子按钮，再点收起
* \[ ] 主按钮旋转动画（＋→✕ 45°）
* \[ ] 展开动画stagger（拍照先，写文字晚50ms弹出）
* \[ ] 收起动画流畅（150ms）
* \[ ] 点击"✏️ 写文字"跳转文字编辑页
* \[ ] 点击"📷 拍照"调起相机（不破坏已有拍照功能）
* \[ ] 点击遮罩收起子按钮
* \[ ] 返回首页后FAB恢复收起态
* \[ ] 快速连续点击主按钮 → 防抖，动画进行中忽略重复点击
* \[ ] 替换原单一相机FAB，无残留

### 边界条件

* 快速连续点击主按钮 → 防抖（\_isAnimating 标记）
* 页面切换时 → 确保FAB状态重置为收起（dispose或RouteObserver）
* 展开动画中切换页面 → FAB状态重置，无异常
* 展开动画中点击子按钮 → 忽略，等动画完成
* 拍照权限拒绝 → 已有PermissionService处理，不受影响
* FAB遮罩不拦截列表滚动 → 遮罩仅在展开态显示，收起后移除

### 技术约束

* StatefulWidget + MultiTickerProviderStateMixin
* dispose 中必须 dispose 所有 AnimationController
* 颜色从 AppColors 引用
* 日志 `debugPrint('\[XiaoQi] FAB: ...')`

### 不做什么

* 不做长按区分（点击展开即可）
* 不做拖拽FAB位置
* 不做更多子按钮（V1.0只有拍照和文字两种）
