# 网上找书测评 · 2026-11-22

## 2026-11-23 按需下载的测评口径

当前本地契约 43：搜索先返回 `downloadable` 文件入口，用户点击后才 resolve 获取完整文件。`downloadable` 只计“找到入口”，不计整本取得或入库成功。评测继续执行真实 resolve、鉴权 `/file` 全量下载、长度与 SHA-256 校验，以及原有 PDF/EPUB 内容条件，满足这些条件才计文件用例通过。90% 门槛同时检查独立作品及全部文件请求的实际文件通过率，对照用例仍须全部通过。

报告分开记录 `search_and_reply_ms`（完成搜索与模型回复，不等于界面首次显示时间）、`prepare_ms`（点击后服务端准备）、`file_transfer_ms`（完整取文件）及总耗时。`downloadEntries` 单列入口命中数；这些后端评测不证明 Flutter 入库与系统下载目录可见，`client_import_verified` 保持 false，须由客户端验收补充。旧的81.8%是历史整本取得率，不能直接作为新策略的验收结果。

本地使用隔离数据目录启动服务后，在项目根目录运行全量和额外样本。两个报告独立计分。

```powershell
$suite = 'tools/evaluations/online_book_search'
& (uv python find) "$suite/evaluate_local.py" --base-url <本地API地址> --data-dir <服务数据目录> --output <固定集报告>
node "$suite/review.mjs" score <固定集报告>
& (uv python find) "$suite/evaluate_local.py" --base-url <本地API地址> --data-dir <服务数据目录> --cases-file "$suite/holdout-cases.json" --output <额外样本报告>
node "$suite/review.mjs" score <额外样本报告> --cases-file "$suite/holdout-cases.json"
```

固定集沿用原有 30 个用户请求和门槛。文件用例核对书名、作者、所需语言、版次、格式和实际交付的文件。只有用户点名作者官网、官方来源或出版社时才核对对应约束。用例的 `source` 字段保留一份参考版本，实际书源可见于报告的 `download.source`。允许新的来源，无需逐本登记 URL。测评同时要求文件直连已通过运行时的下载和校验，并提供可追溯的来源和许可信息。

中文经典 EPUB 核对书内题名、署名和正文，根据作品逐一核验篇名或连续章回，每个要求的篇章都要有正文。某些 EPUB 文件内连续编排多回，以正文中的标题为准。涉及版本署名分歧时按文件实际署名计分。如《封神演义》的一百回用例，维基文库版署陈仲琳，古登堡版署陆西星，卡片与书内的署名须相符。指定作者的请求继续按指定作者核对。技术类用例另校验版本卡元数据与文件交付，PDF 的自动内容检查目前限于文件边界。 [教育部辞典](https://dict.revised.moe.edu.tw/dictView.jsp?ID=36883&la=0&powerMode=0) · [维基文库版](https://zh.wikisource.org/wiki/封神演義) · [古登堡版](https://www.gutenberg.org/ebooks/23910)

额外样本含四部新作品、一条关联书问法和两条控制用例。评测记录每个用例的 UTC 时间、文件准备及传输阶段和公开失败响应，便于在隔离环境里对照书源日志。耗时汇总提供次数、平均值、P50、P90 和最大值。

## 真实下载需求样本

[realistic-cases.json](realistic-cases.json) 独立记录 13 个找整本文件的请求，覆盖口语问法、中国古典小说、当代中文作品、指定译本和版次、开放教材，以及只有试读或开放单章的出版物。每条用例的 `source` 记录核实书目或整本的证据。诸如《人民的西湖》的出版社开放版有独立许可条款，文件可获取性随许可允许的使用范围变化。

复测使用 [realistic-cases-v2.json](realistic-cases-v2.json)，把运行和评分的 `--cases-file` 都指向该文件。旧文件保留用于复核历史报告。整体 `requestedFiles` 保留全部 13 个文件请求。`availabilityUnconfirmed` 单列四条此前尚未确认有可交付全文的请求。后续实际取得匹配且通过核验的全文，照常计成功。仅书目、来源线索、超时和替代版入口均计入分母，文件命中计为零。独立的虚构书和错误版次控制用例仍要求拒绝错误交付。低于 90% 时评分器输出完整 JSON 后以状态码 2 退出。

新样本的 PDF 使用 `pdfinfo` 或环境已安装的 `pypdf` 核对可读页数。配置了文本样例时分别抽样检查头尾内容。EPUB 检查正文与阅读顺序，指定译本按用例核对贡献者和译文。抽样覆盖多个位置，逐页一致性需另有证据。

以下保留接口40历史基线。

生产镜像 `acbb1e0`，接口 40。真实 DeepSeek 和真实来源，使用隔离测试账号。30 条固定用例按 [cases.json](cases.json) 执行，额外复测 4 条。文件通过真实候选 resolve 和完整下载再校验 PDF 文件边界或 EPUB 压缩包、阅读顺序及指定章节数。该轮没有平板入库验收。

## 实际的 Agent 路径

[agent_runtime.dart](../../../xiaoqi_harness/genkit_server/lib/src/agent_runtime.dart) 的 `bookSearchPrompt` 包含找书、问答、作者与版本核验、区分来源状态等规则。启用时追加唯一工具 `find_book_material` 的调用条件，随后附关联书和经过当前账号校验的上一轮结果。找书弹窗使用现有 `xiaoqi_assistant` 的 Genkit Dart 1.0.2 回合与快照，使用独立的提示和工具范围。输入的模型由客户端偏好决定，本次评测选择 DeepSeek Flash。没有额外启动一个找书子 Agent。

| 流程 | 行为和状态归属 |
| --- | --- |
| 自然语言 | Flutter AgentChat → 模型解析条件 → `find_book_material` → BookSearchService 验证来源并发布查询引用 → 模型读取工具结果回复 |
| 书目与文件 | 官方发行渠道核验文件；中文维基文库按作品与章节修订生成 EPUB；Open Library、Internet Archive 及 DeepSeek 发现的图书馆目录用于书目核验 |
| 展示与导入 | Flutter 按已鉴权的查询编号读取候选，A2UI 书卡用业务字段，用户确认后调用 resolve 并由书库负责写入 |
| ISBN 与停止 | 独立合法 ISBN 直查同一服务。关闭弹窗取消 Agent 回合并停止业务检索 |

工具字段为 `title`、`author`、`isbn`、`topic`、`language`、`format`、`edition`。工具要求至少有书名、作者、主题或用户给出的 ISBN 之一。格式枚举为 PDF、EPUB。模型不提供下载地址或调用导入。第二次模型请求是标准 Genkit 工具循环读入工具响应后生成自然语言。它对 AI 解释有用，确定性书卡和原文件获取无需这一步。自然语言需要理解时第一步才调用模型。基线 26 条走两次模型，2 条普通问答或追问走一次，ISBN 直查走零次，主题用例走三次。单次主题异常需要结合工具调用确认重复检索及最终文案。

## 如何达到 90%

1. 修复中文维基文库目录与许可识别。按结构化目录读取可核验的章节、支持不同页头和合法公版标记，保留章节修订、完整性和许可检查。长书单独测时限和全章完整性。逐来源记录无匹配、拒绝、超时、限流及失败阶段。
2. 扩展整本发布渠道。接入可审计的官方书库或发行渠道，先验证两部外部官网样本，再在独立作者和主题上测覆盖。网页摘要只能发现来源，真正提供下载之前继续核对授权、版本和实际整本。
3. 把出版版次、语言、文件格式和代码框架分开筛选；补精确 ISBN 的中文题名、作者别名和主题索引。书卡根据实际核验结果交付，模型只能说明已经执行的检索。
4. 用当前冻结集做回归，用单独未参与开发的样本做验收。建议 100 条正向独立作品请求、跨时段重复测；目标正确整本 >90/100，书目与错版控制全通过。二十部基线要超过 90%，至少需 19 部通过，当前 6 部拿到目标文件，仍差 13 部。实际客户端入库另验。

用 `run-production-baseline.ps1 -ExpectedCommit <完整提交> -OutputPath <报告路径>` 运行。用 `node review.mjs score <报告> [定向复测报告]` 记分，未达门槛退出码为 2。用 `node review.mjs flow-dataset` 导出 28 条独立 Genkit Flow 输入，跨回合和直查由完整评测处理。评估以确定性校验为准，不增加裁判模型请求。
